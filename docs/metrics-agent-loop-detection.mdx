**标签**：社区维护 · LLM-as-a-judge · 单轮 · 无参考 · 智能体 · 多模态

智能体循环检测（Agent Loop Detection）指标是一个**完全确定性**（无需 LLM）的智能体指标，检测 LLM 智能体是否陷入无限循环或循环执行模式。它跨三个独立的子信号分析智能体的完整执行追踪，返回 **0.0**（检测到严重循环）到 **1.0**（执行干净）之间的分数。

<Info>
智能体循环检测会分析你**智能体的完整执行追踪**，这需要[设置追踪](/docs/evaluation-llm-tracing)。由于完全确定性，它在生产环境中运行无需任何 API key 或 LLM 调用。
</Info>

## Required Arguments

`AgentLoopDetectionMetric` 是**仅追踪**指标。它读取通过 `update_current_trace` 设置的智能体追踪，**不**需要 `tools_called` 或 `expected_tools`。它只需要标准的追踪字段：

- `input`
- `actual_output`

## Usage

To begin, [set up tracing](/docs/evaluation-llm-tracing) and supply the `AgentLoopDetectionMetric()` to your `evals_iterator`.

```python
from deepeval.tracing import observe, update_current_trace
from deepeval.dataset import Golden, EvaluationDataset
from deepeval.metrics.community import AgentLoopDetectionMetric


@observe()
def search_web(query: str) -> str:
    # Your tool implementation
    return f"Results for: {query}"


@observe()
def my_agent(input: str) -> str:
    result = search_web(input)
    update_current_trace(input=input, output=result)
    return result


# Create dataset
dataset = EvaluationDataset(goldens=[Golden(input="What is the weather in Paris?")])

# Initialize metric — no model or API key needed
loop_metric = AgentLoopDetectionMetric(threshold=0.5)

# Evaluate
for golden in dataset.evals_iterator(metrics=[loop_metric]):
    my_agent(golden.input)
```

创建 `AgentLoopDetectionMetric` 时有**九个**可选参数：

- [可选] `threshold`：浮点数，表示最低通过阈值。也可设为 `None`，以[仅分数模式](/docs/metrics-introduction#metric-thresholds)运行指标。默认为 `0.5`。
- [可选] `repetition_threshold`：整数，表示出现多少次相同的工具调用（同名同参）后才标记重复。默认为 `3`。
- [可选] `similarity_threshold`：浮点数，表示连续 LLM 输出之间被标记为停滞的最小相似分数。指标取 bigram Jaccard 相似度与 `SequenceMatcher` 比率的最大值。默认为 `0.85`。
- [可选] `check_tool_repetition`：布尔值——为 `True` 时启用工具重复子信号。默认为 `True`。
- [可选] `check_reasoning_stagnation`：布尔值——为 `True` 时启用推理停滞子信号。默认为 `True`。
- [可选] `check_call_graph_cycles`：布尔值——为 `True` 时启用调用图环检测子信号。默认为 `True`。
- [可选] `strict_mode`：布尔值，设为 `True` 时把指标分数强制为二元：完美为 1，否则为 0。它还会覆盖当前阈值并将其设为 1。默认为 `False`。
- [可选] `verbose_mode`：布尔值，设为 `True` 时把计算该指标的中间步骤打印到控制台（见 [How Is It Calculated](#how-is-it-calculated) 一节）。默认为 `False`。
- [可选] `flaky`：布尔值，设为 `True` 时，[把指标标记为 flaky](/docs/metrics-introduction#flaky-metrics)。默认为 `False`。

<Info>
`AgentLoopDetectionMetric` **不**接受 `model` 参数。三个子信号都以确定性方式计算（哈希、n-gram 集合运算、DFS）——不涉及任何 LLM。设计理由见[为什么没有 `model` 参数？](#why-no-model-parameter)。
</Info>

关于 `evals_iterator` 工作方式的更多内容，[点击这里](/docs/evaluation-end-to-end-llm-evals#e2e-evals-for-tracing)。

### 在组件内

你还可以在嵌套组件内运行 `AgentLoopDetectionMetric`，进行[组件级](/docs/evaluation-component-level-llm-evals)评估：

```python
from deepeval.tracing import observe, update_current_span
from deepeval.test_case import LLMTestCase
from deepeval.metrics.community import AgentLoopDetectionMetric

loop_metric = AgentLoopDetectionMetric(threshold=0.5)

@observe(metrics=[loop_metric])
def inner_agent_component(input: str) -> str:
    output = "..."  # Your agent logic here
    test_case = LLMTestCase(input=input, actual_output=output)
    update_current_span(test_case=test_case)
    return output

@observe()
def outer_agent(input: str) -> str:
    return inner_agent_component(input)
```

### 独立运行

你还可以把 `AgentLoopDetectionMetric` 作为独立的一次性执行，运行在单个测试用例上：

```python
from deepeval.test_case import LLMTestCase
from deepeval.metrics.community import AgentLoopDetectionMetric

# test_case._trace_dict must be populated from @observe tracing
metric = AgentLoopDetectionMetric(threshold=0.5)
metric.measure(test_case)

print(metric.score)         # e.g. 0.25
print(metric.reason)        # e.g. "Tool 'search_web' called 6 times with identical arguments."
print(metric.score_breakdown)
# {
#     "tool_repetition": 0.0,
#     "reasoning_stagnation": 1.0,
#     "call_graph_cycles": 1.0,
# }
```

<Warning>
独立运行适合调试或构建自定义流水线，但你会**失去** `evaluate()` 或 `deepeval test run` 提供的测试报告、Confident AI 平台集成以及各项优化（速度、缓存、计算）。
</Warning>

## How Is It Calculated?

`AgentLoopDetectionMetric` 的分数是三个独立子信号的**加权组合**：

$$
\text{Loop Score} = \frac{0.40 \cdot S_{\text{rep}} + 0.35 \cdot S_{\text{stag}} + 0.25 \cdot S_{\text{cycle}}}{W_{\text{enabled}}}
$$

其中每个子分数为 **1.0**（无问题）、**0.5**（轻微问题）或 **0.0**（严重问题），$W_{\text{enabled}}$ 是所有启用检查的权重之和。禁用某个子信号会把它的权重从分母中移除，因此它永远不会惩罚总分。

| 子信号 | 权重 | 检测内容 |
|---|---|---|
| 工具调用重复 | 40% | 相同参数的同一工具被调用 ≥ `repetition_threshold` 次 |
| 推理停滞 | 35% | 相邻 LLM 输出的相似度 ≥ `similarity_threshold` |
| 调用图环 | 25% | 同一 span 在同一条根到叶祖先路径上出现两次（真递归） |

### Tool Call Repetition

该子信号把每次工具调用哈希为 `(tool_name, sorted_args)`，并统计每个唯一调用在追踪中出现的次数。只有**完全相同**的名称与参数才计为重复——参数不同的调用（例如改进后的搜索查询）被视为不同调用，永不被惩罚。

| Condition | Score |
|---|---|
| 最大重复次数 < `repetition_threshold` | **1.0** —— 在可接受范围内 |
| 最大重复次数 ≥ `repetition_threshold` | **0.5** —— 轻微重复循环 |
| 最大重复次数 ≥ `repetition_threshold × 2` | **0.0** —— 严重重复循环 |

### Reasoning Stagnation

该子信号使用两种互补的相似度度量比较**相邻的 LLM span 输出**，并取两者的**最大值**：

1. **Bigram Jaccard 相似度** —— 去除常见停用词与智能体套话后的 bigram 词袋重叠。捕捉字面重复。少于 20 个有效词的输出会被跳过（小规模下 Jaccard 不可靠）。
2. **`SequenceMatcher` 比率**（Python `difflib`）—— 序列感知比较，捕捉语序调换但语义相同的文本（例如 `"I will now search"` ≈ `"Let me search now"`）。

取最大值确保无论智能体是逐字重复还是仅仅调换措辞，都能标记停滞。

| Condition | Score |
|---|---|
| 最大相似度 < `similarity_threshold` | **1.0** —— 无停滞 |
| 最大相似度 ≥ `similarity_threshold` | **0.5** —— 重叠度高，可能正在停滞 |
| 最大相似度 > 0.95 | **0.0** —— 输出本质上相同 |

### Call Graph Cycles

该子信号遍历智能体追踪的父→子 span 树并执行深度优先搜索（DFS）。当某个 span 的 `type:name` 标签在**同一条根到叶祖先路径**上第二次出现时，即检测到**环**——意味着智能体真的调用了自身祖先的函数（真递归）。

<Note>
兄弟位置上出现同一工具的顺序重复在这里被刻意**不**标记——那是上文工具调用重复子信号的职责。
</Note>

| Condition | Score |
|---|---|
| 调用树中无回边 | **1.0** —— 执行图干净 |
| 发现至少一条回边 | **0.0** —— 检测到环；理由中包含完整的环路径 |

## Score Interpretation

| Score range | Interpretation |
|---|---|
| `1.0` | 执行干净 —— 未检测到循环模式 |
| `0.5–1.0` | 轻微问题 —— 存在一些重复或重叠；智能体大概率能自行恢复 |
| `0.0–0.5` | 严重循环 —— 智能体很可能卡住了；建议人工复查 |
| `0.0` | 关键循环 —— 完全相同的重复调用或真正的调用图环 |

```
Agent Loop Detection
Score:  1.0
Reason: No loop patterns detected.
```


## Score Breakdown

`score_breakdown` 属性在评估后独立暴露每个子信号的分数：

```python
metric = AgentLoopDetectionMetric(threshold=0.5)

# After measure() runs:
print(metric.score_breakdown)
# {
#     "tool_repetition": 0.0,
#     "reasoning_stagnation": 1.0,
#     "call_graph_cycles": 1.0,
# }

print(metric.score)   # 0.4 (weighted: 0.0×0.40 + 1.0×0.35 + 1.0×0.25 = 0.60, but tool weight 0.40 dominates)
print(metric.reason)  # "Tool 'search_web' called 6 times with identical arguments."
```

值为 `1.0` 表示该子信号未检测到问题。更低的值表示退化程度与循环模式的严重性成正比。

## Configuring Sub-signals

三个子信号都可以独立开关。禁用某个子信号时，其权重会从分母中排除，因此分数不会因此被惩罚：

```python
# Only check for tool repetition — ignore stagnation and graph cycles
metric = AgentLoopDetectionMetric(
    check_tool_repetition=True,
    check_reasoning_stagnation=False,
    check_call_graph_cycles=False,
    repetition_threshold=2,  # flag after 2 identical calls (stricter)
)

# Only check for true recursive cycles in the call graph
metric = AgentLoopDetectionMetric(
    check_tool_repetition=False,
    check_reasoning_stagnation=False,
    check_call_graph_cycles=True,
)
```

## Limitations & Design Decisions

### Why no `model` parameter?

This metric is **fully deterministic by design**. Every sub-signal is computed with hashing, set operations, and sequence comparison algorithms — no LLM is needed. This means:

- **Zero cost** — runs in production without API keys or network calls.
- **Deterministic** — identical traces always produce identical scores (critical for CI/CD gates).
- **Zero latency** — no LLM round-trip; the metric completes in milliseconds.

未来的 `model` 参数可以为推理停滞子信号启用 LLM-as-judge 模式，捕捉措辞差异巨大但语义相同的输出。这已作为潜在的后续增强被记录。

### Cycle detection uses `type:name:input_hash` labels

调用图环检测器用 `type:name:input_hash` 标签标识 span（其中 `input_hash` 是 span 输入的 64 字符截断序列化）。这是一种**启发式**——追踪字典不暴露 span UUID（它们在内部被剥离），因此无法获得精确的 span 身份。

**权衡：**

- 包含输入哈希可以减少误报：当两个真正不同的 span 共享同一 `type:name` 时（例如外层 `"planner"` 智能体委托给输入不同的内层 `"planner"`）。
- 真正的递归循环会把相同或相似的输入传回自身，因此输入哈希匹配，环能被正确检测。
- 在极少数边缘情况下，两个无关的同名 span 恰好收到相同的截断输入时，理论上可能出现误报。实际中这种情况极其罕见。

### Stagnation detection: dual-signal approach

推理停滞刻意使用**两个**互补信号并取最大值：

| Signal | Catches | Misses |
|---|---|---|
| Bigram Jaccard | 字面重复、共享短语模式 | 语序调换 |
| `SequenceMatcher` 比率 | 语序调换但相似的文本、插入/删除 | 词汇不同但语义相同的文本 |

（例如 `"Search for Paris weather"` 与 `"Look up the forecast in Paris"`）
