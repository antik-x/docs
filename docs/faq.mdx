## General

### Do I need an OpenAI API key to use `deepeval`?

不需要，但 OpenAI 是默认的。`deepeval` 的大多数指标都是 LLM-as-a-Judge 指标，在未指定模型时默认使用 OpenAI。你可以将裁判模型换成**任何提供商**——Anthropic、Gemini、Ollama、Azure OpenAI 或任何自定义 LLM。使用 CLI 快捷方式：

```bash
deepeval set-ollama --model=deepseek-r1:1.5b
deepeval set-gemini --model=gemini-2.0-flash-001
```

或者直接把自定义模型传给任何指标：

```python
metric = AnswerRelevancyMetric(model=your_custom_llm)
```

完整细节见[自定义 LLM 指南](/guides/guides-using-custom-llms)。

### Is `deepeval` the same as Confident AI?

不是。可以把它理解为 Next.js 和 Vercel 的关系——相关但独立。`deepeval` 是一个在本地运行的开源 LLM 评估框架。Confident AI 是一个具备可观测性、评估与监控能力的 AI 质量平台。`deepeval` 与 [DeepTeam](https://trydeepteam.com) 是独立的开源框架，可与 Confident AI 原生集成，但该平台**不仅限于此**——它还有自己的 TypeScript SDK、OpenTelemetry 支持、第三方集成和 API。

Confident AI 可免费开始使用：

### What data does `deepeval` collect?

默认情况下，`deepeval` 仅追踪基础的、非身份识别的遥测数据（评估次数以及使用了哪些指标）。不收集任何个人可识别信息。你可以完全退出：

```bash
export DEEPEVAL_TELEMETRY_OPT_OUT=1

```

如果你使用 Confident AI，所有数据都安全地存储在私有 AWS 云中，只有你的组织可以访问。完整的[数据隐私](/docs/data-privacy)页面见此。

### What's the difference between `deepeval test run` and `evaluate()`?

两者都运行评估并产生相同的结果。区别在于接口：

- **`deepeval test run`** 是构建在 Pytest 之上的 CLI 命令。专为 CI/CD 流水线设计，提供 `assert_test()` 语义和通过/失败的退出码。
- **`evaluate()`** 是一个 Python 函数。更适合笔记本、脚本和需要在代码中处理结果的编程式工作流。

两者支持完全相同的配置（异步、缓存、错误处理、显示），并以相同方式与 Confident AI 集成。

## Metrics

### How many metrics should I use?

我们建议总共**不超过 5 个指标**：

- **2–3 个通用指标**匹配你的系统类型（例如 RAG 用 `FaithfulnessMetric` 与 `ContextualRelevancyMetric`，智能体用 `TaskCompletionMetric`）
- **1–2 个自定义指标**匹配你的具体用例（例如语气、格式正确性、通过 `GEval` 的领域准确度）

目标是逼自己排定对 LLM 应用真正重要的优先级。以后随时可以增加更多。

### What's the difference between G-Eval and DAG metrics?

两者都是自定义 LLM-as-a-Judge 指标，但工作方式不同：

- **G-Eval** 使用自然语言标准评估，最适合正确性、语气或有用性等**主观**评估。设置最简单。
- **DAG（深无环图）**使用决策树结构，最适合需要确定性分支逻辑的**客观或混合**标准（例如「先检查格式，再检查语气」）。

从 G-Eval 开始。需要更多控制时用 DAG。

### Can I use non-LLM metrics like BLEU, ROUGE, or BLEURT?

可以。你可以通过继承 `BaseMetric` 创建[自定义指标](/docs/metrics-custom)，并使用 `deepeval` 内置的 `scorer` 模块计算传统 NLP 分数。不过根据我们的经验，对于需要推理才能评估的 LLM 输出，LLM-as-a-Judge 指标显著优于这些传统打分器。

### My metric scores seem random or flaky. What should I do?

可以尝试以下几种方法：

1. **开启指标的 `verbose_mode`** 以查看中间推理步骤：
   ```python
   metric = AnswerRelevancyMetric(verbose_mode=True)
   ```
2. **使用 `strict_mode=True`** 强制二元（0 或 1）分数（如果不需要粒度）。
3. 改用 **DAG 指标**代替 G-Eval，获得更确定性的打分。
4. **自定义评估模板**——如果默认提示词与你的标准定义不符。每个指标都支持 `evaluation_template` 参数。
5. **使用更强的裁判模型。**较弱的模型会产生更嘈杂的分数。

### How do I run metrics in production without ground truth labels?

选择**无参考指标**——这些指标不需要 `expected_output`、`context` 或 `expected_tools`。例如：

- `AnswerRelevancyMetric`（只需 `input` + `actual_output`）
- `FaithfulnessMetric`（需要 `actual_output` + `retrieval_context`，你的 RAG 流水线已经在产生这些了）
- `BiasMetric`、`ToxicityMetric`（只需 `actual_output`）

请查看每个指标的文档页面，了解它具体需要哪些 `LLMTestCase` 参数。

## Test Cases & Datasets

### What's the difference between a Golden and a Test Case?

**金标（Golden）**是一个模板——包含 `input` 和可选的 `expected_output` 或 `context`，但通常**没有** `actual_output`。可以把它理解为「你想要测试什么」。

**测试用例**（`LLMTestCase`）是一个完全填充的评估单元——包含来自 LLM 应用的 `actual_output` 以及 `retrieval_context` 或 `tools_called` 等运行时数据。

评估时，你遍历金标、调用 LLM 应用生成 `actual_output`，然后构建测试用例。

### What's the difference between `context` and `retrieval_context`?

- **`context`** 是**基准真值**——对于给定输入_应该_相关的理想信息。它是静态的，通常来自你的评估数据集。
- **`retrieval_context`** 是你的 RAG 流水线在运行时**实际检索到的内容**。

`ContextualRecallMetric` 等指标将 `retrieval_context` 与 `context` 对比，衡量检索器的表现。`FaithfulnessMetric` 等指标单独使用 `retrieval_context` 检查输出是否以实际检索到的内容为依据。

### Should my `input` contain the system prompt?

不应该。`input` 应仅表示**用户的消息**，而不是你的完整提示模板。如果想追踪使用了哪个提示模板，请将其作为超参数记录：

```python
evaluate(
    test_cases=[...],
    metrics=[...],
    hyperparameters={"prompt_template": "v2.1", "model": "gpt-4.1"}
)
```

### I don't have an evaluation dataset yet. Where do I start?

两种选择：

1. **写下你已经在使用的提示词**，手动检查你的 LLM 输出。哪怕只有 10–20 个输入也是很好的开始。
2. **使用 `deepeval` 的 `Synthesizer`** 从你现有的文档生成金标：
   ```python
   from deepeval.synthesizer import Synthesizer
   goldens = Synthesizer().generate_goldens_from_docs(
       document_paths=['knowledge_base.pdf']
   )
   ```

`Synthesizer` 支持从文档、上下文、空白或已有金标生成。见[金标合成器文档](/docs/golden-synthesizer)。

## Tracing & Observability

### How do I continuously evaluate my LLM app in production?

Set up [LLM tracing](/docs/evaluation-llm-tracing) with `deepeval`'s `@observe` decorator (or one-line integrations) and connect to [Confident AI](https://www.confident-ai.com/docs/llm-tracing/introduction). Once instrumented, every trace, span, and thread flowing through your app can be **automatically evaluated against your chosen metrics in real-time** — no manual test runs needed.

这意味着你可以在生产中即时发现回归、幻觉与质量退化，而不是事后才发现。Confident AI 支持在三个层级进行评估：

- **追踪** —— 对单个请求的端到端评估
- **Span** —— 对单个步骤（LLM 调用、检索结果、工具执行）的组件级评估
- **线程** —— 跨多轮交互的对话级评估

你还可以使用生产追踪来**整理你的下一个评估数据集**，形成让真实使用持续改进离线评估的反馈循环。

### I already use LangSmith / Langfuse / another tool for tracing. Do I still need `@observe`?

你可以将 `deepeval` 的 `@observe` 装饰器与现有追踪工具**搭配**使用——它们独立运行。

话虽如此，你应该认真考虑使用 [Confident AI 进行追踪](https://www.confident-ai.com/docs/llm-tracing/introduction)。与独立的追踪工具不同，Confident AI 在**同一平台上提供可观测性与自动化评估**——每条追踪、span 和线程都可以对照 50+ 个指标实时自动评估。就像是 AI 应用的 Datadog，但内置了监控 AI 质量随时间变化的 LLM 评估。

此外，Confident AI 中收集的追踪还可以用来**整理你的下一版评估数据集**——让生产数据直接反馈并持续改进你的评估。

入门很简单。Confident AI 为你已在使用的框架提供**一行集成**——OpenAI、LangChain、LangGraph、Pydantic AI、Vercel AI SDK 等，并为任何语言（Python、TypeScript、Go、Ruby、C#）提供完整的 **OpenTelemetry（OTEL）支持**。你不需要重写任何东西：

| Approach                  | Best For                                                                       |
| ------------------------- | ------------------------------------------------------------------------------ |
| **`@observe` 装饰器** | 完全控制 span、属性和追踪结构 |
| **一行集成** | 自动埋点 OpenAI、LangChain、LangGraph、Pydantic AI、Vercel AI SDK 等 |
| **OpenTelemetry（OTEL）** | 语言无关、基于标准的埋点 |

如果你只需要 `deepeval` 做离线评估（不需要生产追踪），则完全不需要 `@observe`——直接使用 `evaluate()` 配合 `LLMTestCase` 即可。

### When should I use end-to-end vs. component-level evaluation?

- **端到端**把你的 LLM 应用当黑盒。适合较简单的架构（基础 RAG、摘要、写作助手）或组件级噪声造成干扰时。
- **组件级**通过 `@observe` 在不同的内部组件上放置不同的指标。适合复杂的智能体工作流、多步流水线，或需要定位_哪个_组件失败时。

你总是可以先从端到端开始，后续根据需要添加组件级追踪。

### Does `@observe` affect my application's performance in production?

不会。`deepeval` 的追踪是**非侵入的**。`@observe` 装饰器只在评估期间被显式调用时（在 `evaluate()` 或 `assert_test()` 内）才收集数据并运行指标。在正常生产执行中，它对应用的行为或延迟没有影响。

要抑制评估之外的追踪控制台日志，设置：

```bash
CONFIDENT_TRACE_VERBOSE=0
CONFIDENT_TRACE_FLUSH=0
```

## Evaluation Workflow

### My evaluation is getting "stuck" or running very slowly. What's happening?

这几乎总是由你的 LLM 裁判的**速率限制或 API 配额不足**引起的。默认情况下，`deepeval` 会以指数退避方式重试瞬时错误一次（共尝试 2 次）。要修复：

1. **降低并发：**
   ```python
   from deepeval.evaluate import AsyncConfig
   evaluate(async_config=AsyncConfig(max_concurrent=5), ...)
   ```
2. **添加节流：**
   ```python
   evaluate(async_config=AsyncConfig(throttle_value=2), ...)
   ```
3. 通过[环境变量](/docs/environment-variables#retry--backoff-tuning)（如 `DEEPEVAL_RETRY_MAX_ATTEMPTS` 和 `DEEPEVAL_RETRY_CAP_SECONDS`）调整重试行为。

### Can I run evaluations in CI/CD?

可以——这是 `deepeval` 的核心设计目标之一。使用 `deepeval test run` 配合 Pytest：

```python title="test_llm_app.py"
from deepeval.metrics import AnswerRelevancyMetric
from deepeval.test_case import LLMTestCase
from deepeval import assert_test

def test_my_app():
    test_case = LLMTestCase(input="...", actual_output="...")
    assert_test(test_case, [AnswerRelevancyMetric()])
```

```bash
deepeval test run test_llm_app.py
```

该命令在失败时返回非零退出码，因此可直接集成到任何 CI/CD `.yaml` 工作流中。搭配 [Confident AI](https://confident-ai.com) 可自动生成跨运行的回归测试报告。

### How do I evaluate multi-turn conversations?

使用 `ConversationalTestCase` 配合对话式指标：

        Turn(role="assistant", content="Sure! What's your order number?"),

### How do I go from offline evals to production monitoring?

典型的工作流是：

1. **从离线评估开始**——使用 `evaluate()` 或 `deepeval test run` 配合整理好的数据集，在开发期验证你的 LLM 应用。
2. **添加追踪**——用 `@observe` 或 [一行集成](https://www.confident-ai.com/docs/llm-tracing/introduction)（支持 OpenAI、LangChain、Pydantic AI 等）为应用埋点。
3. **启用在线评估**——连接到 [Confident AI](https://confident-ai.com)，让每条生产追踪自动对照你的指标评估。
4. **形成闭环**——用生产追踪整理和改进评估数据集，然后在部署前重新运行离线评估验证变更。

这形成了一个持续循环：离线评估在部署前发现问题，生产监控在部署后发现问题，生产数据改进你的下一轮离线评估。

### My custom LLM judge keeps producing invalid JSON. What should I do?

这在较弱的模型中很常见。几种策略：

1. **启用 JSON 约束**——约束输出的详情见[自定义 LLM 指南](/guides/guides-using-custom-llms#json-confinement-for-custom-llms)。
2. **使用 `ignore_errors=True`** 跳过因 JSON 错误而失败的测试用例：
   ```python
   from deepeval.evaluate import ErrorConfig
   evaluate(error_config=ErrorConfig(ignore_errors=True), ...)
   ```
3. **启用缓存**，避免重跑已成功的测试用例：
   ```bash
   deepeval test run test_example.py -i -c
   ```
4. **自定义评估模板**，加入更清晰的格式指令和模型示例。每个指标都支持通过 `evaluation_template` 参数实现。

## LLM Judge Configuration

### Can I use different LLM judges for different metrics?

可以。每个指标都接受一个 `model` 参数，你可以混合搭配：

```python
from deepeval.metrics import AnswerRelevancyMetric, FaithfulnessMetric

relevancy = AnswerRelevancyMetric(model="gpt-4.1")
faithfulness = FaithfulnessMetric(model=my_custom_claude_model)

evaluate(test_cases=[...], metrics=[relevancy, faithfulness])
```

当你想为关键指标使用更强（但更贵）的模型、为简单检查使用更便宜的模型时，这很有用。

### Can I customize the prompts that metrics use internally?

可以。`deepeval` 中的每个指标都支持 `evaluation_template` 参数。你可以继承指标的默认模板类并覆写特定的提示方法：

```python
from deepeval.metrics.answer_relevancy import AnswerRelevancyTemplate
from deepeval.metrics import AnswerRelevancyMetric

class MyTemplate(AnswerRelevancyTemplate):
    @staticmethod
    def generate_statements(actual_output: str):
        return f"""..."""

metric = AnswerRelevancyMetric(evaluation_template=MyTemplate)
```

在使用需要更明确指令或不同上下文学习示例的自定义 LLM 时，这尤其有价值。见每个指标文档页面的**自定义你的模板**板块。

## Ecosystem

### What is Confident AI and how does it relate to `deepeval`?

[Confident AI](https://confident-ai.com) is an AI quality platform with observability, evals, and monitoring. `deepeval` and [DeepTeam](https://trydeepteam.com) are standalone open-source frameworks that **integrate natively with Confident AI** via APIs, so that evaluation results, red teaming assessments, and traces can flow into the platform if you want them to.

但 Confident AI **不仅限于这些开源包**。它还有自己的 TypeScript SDK、OpenTelemetry 支持、第三方集成和独立 API。你可以完全脱离 `deepeval` 或 `deepteam` 使用 Confident AI，也可以脱离 Confident AI 使用 `deepeval` 或 `deepteam`。

Confident AI 提供：

- **LLM 评估**——可分享的测试报告与跨运行回归测试
- **LLM 红队测试**——漏洞扫描与风险评估
- **LLM 可观测性**——追踪、在线评估、延迟与成本追踪
- **数据集管理**——为非技术团队成员提供标注工具
- **生产监控**——追踪、span 和线程的实时质量指标

### What is DeepTeam?

[DeepTeam](https://www.trydeepteam.com/docs/getting-started) is an open-source framework for **red teaming LLM systems**. While `deepeval` focuses on evaluation (correctness, relevancy, faithfulness, etc.), DeepTeam is dedicated to **security and safety testing**. Like `deepeval`, it also serves as an SDK for Confident AI — red teaming results are automatically uploaded to the platform.

DeepTeam 让你可以：

- 检测 **40+ 种漏洞**，包括偏见、PII 泄露、提示注入、虚假信息、过度代理等
- 模拟 **10+ 种对抗攻击方法**，包括越狱、提示注入、ROT13 和自动化规避
- 对齐 **OWASP LLM Top 10**、**NIST AI RMF** 和 **MITRE ATLAS** 等安全框架
- 通过 Python 或 CI/CD 中的 **YAML 配置**运行红队测试

```python
from deepteam import red_team
from deepteam.vulnerabilities import Bias, PIILeakage
from deepteam.attacks.single_turn import PromptInjection

red_team(
    model_callback="openai/gpt-3.5-turbo",
    vulnerabilities=[Bias(types=["race"]), PIILeakage(types=["api_and_database_access"])],
    attacks=[PromptInjection()]
)
```

**同时使用 `deepeval` 和 DeepTeam** 非常常见——`deepeval` 用于质量评估，DeepTeam 用于安全测试。

### How do these three products fit together?

可以这样理解：

- **[Confident AI](https://confident-ai.com)** is the AI quality platform — observability, evals, monitoring, red teaming, and collaboration all live here.
- **[`deepeval`](https://github.com/confident-ai/deepeval)** is a standalone open-source LLM evaluation framework that integrates natively with Confident AI.
- **[DeepTeam](https://trydeepteam.com)** is a standalone open-source LLM red teaming framework that also integrates natively with Confident AI.

每个都可以独立使用——你可以完全在本地使用 `deepeval` 或 DeepTeam 而不碰 Confident AI。但连接后，一切都会汇入同一个平台。你也可以通过 TypeScript SDK、OpenTelemetry 或直接 API 集成单独使用 Confident AI，而不需要任何开源包。

Confident AI 提供企业计划，包括专属支持、SSO、自定义部署选项以及合规认证（SOC 2 Type II、HIPAA、GDPR）。如果你想在组织中推广 LLM 评估和监控，[**预约演示**](http://confident-ai.com/book-a-demo)，团队会为你详细讲解。
