**标签**：LLM-as-a-judge · 多轮 · 无参考 · 聊天机器人 · 多模态

MCP 任务完成（MCP task completion）指标是一个对话式指标，使用 LLM-as-a-judge 评估**基于 MCP 的 LLM 智能体完成任务**的效果如何。任务完成是会自我解释的 LLM-Eval，会输出指标分数的理由。

## Required Arguments

要使用 `MCPTaskCompletionMetric`，你需要在创建 [`ConversationalTestCase`](https://www.deepeval.com/docs/evaluation-multiturn-test-cases) 时提供以下参数：

- `turns`
- `mcp_servers`

只要智能体工作流中出现 MCP 交互，就需要在轮次内提供 `mcp_tools_called`、`mcp_resources_called` 与 `mcp_prompts_called`。创建 MCP 测试用例的更多内容见[这里](https://www.deepeval.com/docs/evaluation-mcp)。

其计算方式的更多信息见[这里](#how-is-it-calculated)。

## Usage

`MCPTaskCompletionMetric()` 可用于基于 MCP 的智能体的[端到端](/docs/evaluation-end-to-end-llm-evals)多轮评估：

<Tabs>

<Tab title="Python">

```python
from deepeval.test_case import Turn, ConversationalTestCase, MCPServer
from deepeval.metrics import MCPTaskCompletionMetric
from deepeval import evaluate

convo_test_case = ConversationalTestCase(
    turns=[Turn(role="...", content="..."), Turn(role="...", content="...")],
    mcp_servers=[MCPServer(...)]
)
metric = MCPTaskCompletionMetric(threshold=0.5)

# To run metric as a standalone
# metric.measure(convo_test_case)
# print(metric.score, metric.reason)

evaluate(test_cases=[convo_test_case], metrics=[metric])
```

</Tab>

<Tab title="TypeScript">

```typescript
import { Turn, ConversationalTestCase, MCPServer } from "deepeval/test-case";
import { MCPTaskCompletionMetric } from "deepeval/metrics";
import { evaluate } from "deepeval";

const convoTestCase = new ConversationalTestCase({
  turns: [new Turn({ role: "user", content: "..." }), new Turn({ role: "assistant", content: "..." })],
  mcpServers: [new MCPServer({ serverName: "..." })],
});
const metric = new MCPTaskCompletionMetric({ threshold: 0.5 });

// To run metric as a standalone
// await metric.measure(convoTestCase);
// console.log(metric.score, metric.reason);

await evaluate([convoTestCase], [metric]);
```

- [Optional] `threshold`: a number representing the minimum passing threshold. Can also be set to `None`（TypeScript 中为 `null`） to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [可选] `model`：字符串，指定使用 OpenAI 的哪款 GPT 模型，**或**类型为 `DeepEvalBaseLLM` 的[任意自定义 LLM 模型](/docs/metrics-introduction#using-a-custom-llm)。默认为 `gpt-5.4`。
- [Optional] `include_reason`: a boolean which when set to `True`（TypeScript 中为 `true`）, will include a reason for its evaluation score. Defaulted to `True`（TypeScript 中为 `true`）.
- [Optional] `strict_mode`: a boolean which when set to `True`（TypeScript 中为 `true`）, enforces a binary metric score: 1 for perfection, 0 otherwise. It also overrides the current threshold and sets it to 1. Defaulted to `False`（TypeScript 中为 `false`）.
[可选] `async_mode`：布尔值，设为 `True` 时，启用[`measure()` 方法内的并发执行](/docs/metrics-introduction#measuring-a-metric-in-async)。默认为 `True`。
  
- [Optional] `verbose_mode`: a boolean which when set to `True`（TypeScript 中为 `true`）, prints the intermediate steps used to calculate said metric to the console, as outlined in the [How Is It Calculated](#how-is-it-calculated) section. Defaulted to `False`（TypeScript 中为 `false`）.
- [Optional] `flaky`: a boolean which when set to `True`（TypeScript 中为 `true`）, [marks the metric as flaky](/docs/metrics-introduction#flaky-metrics). Defaulted to `False`（TypeScript 中为 `false`）.

## How Is It Calculated

`MCPTaskCompletionMetric` 的分数按以下公式计算：

$$
\text{MCP Task Completeness} = \frac{\text{Number of Tasks Satisfied in Each Interaction}}{\text{Total Number of Interactions}}
$$

`MCPTaskCompletionMetric` 把轮次转成独立的单元交互，并逐个交互用 LLM 评估智能体是否完成了用户在该交互中交给它的任务。

## FAQs

<AccordionGroup>
<Accordion title="MCP Use vs MCP Task Completion — usage quality or goal completion?">
`MCPTaskCompletionMetric` 评的是*结果*（智能体是否完成了任务）；`MultiTurnMCPUseMetric` 评的是*过程*（原语与参数的选择）。智能体可能完美使用工具却仍然失败——两者互补。
</Accordion>
<Accordion title="How does it turn a multi-turn conversation into a completion score?">
它把 `turns` 拆成单元交互，由 LLM 逐一评判。分数 = 已满足任务数 / 总交互数。
</Accordion>
<Accordion title="Does the score explain why the task was marked incomplete?">
Yes — it's a self-explaining LLM-Eval that outputs `metric.reason` . Keep `include_reason` set to `True`（TypeScript 中为 `true`） (default) to see which interaction failed.
</Accordion>
<Accordion title="What do I need to provide so it can judge task completion over MCP?">
A [ConversationalTestCase](https://www.deepeval.com/docs/evaluation-multiturn-test-cases) with `turns` and `mcp_servers` , plus `mcp_tools_called` , `mcp_resources_called` , and `mcp_prompts_called` inside the relevant turns.
</Accordion>
</AccordionGroup>
