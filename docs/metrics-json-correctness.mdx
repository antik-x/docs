title: Json Correctness

**标签**：单轮 · 无参考

JSON 正确性（json correctness）指标衡量你的 LLM 应用能否生成符合正确 **JSON schema** 的 `actual_output`。

<Note>

与 `ExactMatchMetric` 一样，`JsonCorrectnessMetric` 不是 LLM 评估；创建 `JsonCorrectnessMetric` 时你需要提供期望的 JSON schema。

</Note>

## Required Arguments

要使用 `JsonCorrectnessMetric`，你需要在创建 [`LLMTestCase`](/docs/evaluation-test-cases#llm-test-case) 时提供以下参数：

- `input`
- `actual_output`

请阅读下文 [How Is It Calculated](#how-is-it-calculated) 一节，了解测试用例参数如何用于指标计算。

## Usage

首先创建一个 `pydantic` `BaseModel` 来定义你的 schema：

<Tabs>

<Tab title="Python">

```python
from pydantic import BaseModel

class ExampleSchema(BaseModel):
    name: str
```

</Tab>

<Tab title="TypeScript">

```typescript
import { z } from "zod";

const ExampleSchema = z.object({
  name: z.string(),
});
```

</Tab>

</Tabs>

<Tip>
如果你的 `actual_output` 是 JSON 对象列表，把现有 schema 包进 `RootModel` 即可创建列表 schema。例如：

<Tabs>

<Tab title="Python">

```python
from pydantic import RootModel
from typing import List

...

class ExampleSchemaList(RootModel[List[ExampleSchema]]):
    pass
```

</Tab>

<Tab title="TypeScript">

```typescript
// ...

const ExampleSchemaList = z.array(ExampleSchema);
```

</Tab>

</Tabs>

</Tip>

然后在创建 `JsonCorrectnessMetric` 时把它作为 `expected_schema` 提供，即可用于[端到端](/docs/evaluation-end-to-end-llm-evals)评估：

<Tabs>

<Tab title="Python">

```python
from deepeval.metrics import JsonCorrectnessMetric
from deepeval.test_case import LLMTestCase
from deepeval import evaluate


metric = JsonCorrectnessMetric(
    expected_schema=ExampleSchema,
    model="gpt-4",
    include_reason=True
)
test_case = LLMTestCase(
    input="Output me a random Json with the 'name' key",
    # Replace this with the actual output from your LLM application
    actual_output="{'name': null}"
)

# To run metric as a standalone
# metric.measure(test_case)
# print(metric.score, metric.reason)

evaluate(test_cases=[test_case], metrics=[metric])
```

</Tab>

<Tab title="TypeScript">

```typescript
import { JsonCorrectnessMetric } from "deepeval/metrics";
import { LLMTestCase } from "deepeval/test-case";
import { evaluate } from "deepeval";

const metric = new JsonCorrectnessMetric({
  expectedSchema: ExampleSchema,
  model: "gpt-4",
  includeReason: true,
});
const testCase = new LLMTestCase({
  input: "Output me a random Json with the 'name' key",
  // Replace this with the actual output from your LLM application
  actualOutput: "{'name': null}",
});

// To run metric as a standalone
// await metric.measure(testCase);
// console.log(metric.score, metric.reason);

await evaluate([testCase], [metric]);
```

</Tab>

</Tabs>

<Tab title="Python">

创建 `PromptAlignmentMetric` 时有**一个**必填参数和**七个**可选参数：

</Tab>

<Tab title="TypeScript">

创建 `PromptAlignmentMetric` 时有**一个**必填参数和**六个**可选参数：

</Tab>

</Tabs>

- `expected_schema`：`pydantic` `BaseModel`，指定你期望 LLM 输出的 JSON 的 schema。
- [Optional] `threshold`: a number representing the minimum passing threshold. Can also be set to `None`（TypeScript 中为 `null`） to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [可选] `model`：字符串，指定使用 OpenAI 的哪款 GPT 模型来生成理由，**或**类型为 `DeepEvalBaseLLM` 的[任意自定义 LLM 模型](/docs/metrics-introduction#using-a-custom-llm)。默认为 `gpt-5.4`。
- [可选] `include_reason`：布尔值，设为 `True`（TypeScript 中为 `true`）时，会为评估分数附带理由。默认为 `True`（TypeScript 中为 `true`）。
- [可选] `strict_mode`：布尔值，设为 `True`（TypeScript 中为 `true`）时，把指标分数强制为二元：完美为 1，否则为 0。它还会覆盖当前阈值并将其设为 1。默认为 `False`（TypeScript 中为 `false`）。
- [可选] `async_mode`：布尔值，设为 `True` 时，启用[`measure()` 方法内的并发执行](/docs/metrics-introduction#measuring-a-metric-in-async)。默认为 `True`。
  
- [可选] `verbose_mode`：布尔值，设为 `True`（TypeScript 中为 `true`）时，把计算该指标所用的中间步骤打印到控制台，具体见 [How Is It Calculated](#how-is-it-calculated) 一节。默认为 `False`（TypeScript 中为 `false`）。
- [可选] `flaky`：布尔值，设为 `True`（TypeScript 中为 `true`）时，[把指标标记为 flaky](/docs/metrics-introduction#flaky-metrics)。默认为 `False`（TypeScript 中为 `false`）。

<Info>
Unlike other metrics, the `model` is used for generating reason instead of evaluation. It will only be used if the `actual_output` has the wrong schema, **AND** if `include_reason` is set to `True`（TypeScript 中为 `true`）.
</Info>

### 在组件内

你还可以在嵌套组件内运行 `JsonCorrectnessMetric`，进行[组件级](/docs/evaluation-component-level-llm-evals)评估。

<Tabs>

<Tab title="Python">

```python
from deepeval.dataset import EvaluationDataset, Golden
from deepeval.tracing import observe, update_current_span
...

@observe(metrics=[metric])
def inner_component():
    # Set test case at runtime
    test_case = LLMTestCase(input="...", actual_output="...")
    update_current_span(test_case=test_case)
    return

@observe
def llm_app(input: str):
    # Component can be anything from an LLM call, retrieval, agent, tool use, etc.
    inner_component()
    return

dataset = EvaluationDataset(goldens=[Golden(input="Hi!")])
for golden in dataset.evals_iterator():
    llm_app(golden.input)
```

</Tab>

<Tab title="TypeScript">

```typescript
import { EvaluationDataset, Golden } from "deepeval/dataset";
import { observe, updateCurrentSpan } from "deepeval/tracing";
// ...

const innerComponent = observe({
  metrics: [metric],
  fn: async () => {
    // Set test case at runtime
    const testCase = new LLMTestCase({ input: "...", actualOutput: "..." });
    updateCurrentSpan({ testCase });
  },
});

const llmApp = observe({
  fn: async (input: string) => {
    // Component can be anything from an LLM call, retrieval, agent, tool use, etc.
    await innerComponent();
  },
});

const dataset = new EvaluationDataset({
  goldens: [new Golden({ input: "Hi!" })],
});
for await (const golden of dataset.evalsIterator()) {
  await llmApp((golden as Golden).input);
}
```

</Tab>

</Tabs>

## How Is It Calculated?

`PromptAlignmentMetric` 的分数按以下公式计算：

$$
\text{Json Correctness} = \begin{cases}
1 & \text{If the actual output fits the expected schema}, \\
0 & \text{Otherwise}
\end{cases}
$$

`JsonCorrectnessMetric` 不使用 LLM 评估，而是用提供的 `expected_schema` 判断 `actual_output` 能否加载进该 schema。

## FAQs

<AccordionGroup>
<Accordion title="指标既然是确定性的，为什么还要传模型？">
Scoring is deterministic — it only checks whether `actual_output` loads into your `expected_schema` . The `model` only *generates the reason* on invalid schemas when `include_reason` is `True`（TypeScript 中为 `true`） ; set `include_reason=False`（TypeScript 中为 `includeReason: false`） to skip it.
</Accordion>
<Accordion title="打分要花钱或调用 LLM 吗？">
Schema validation is free and deterministic. A model is only invoked — incurring token cost — when an output fails the schema and `include_reason` is `True`（TypeScript 中为 `true`） .
</Accordion>
<Accordion title="如何校验 JSON 对象列表形式的输出？">
把你的 `pydantic` `BaseModel` 包进 `RootModel`——例如 `class ExampleSchemaList(RootModel[List[ExampleSchema]])`——并将其作为 `expected_schema` 传入。
</Accordion>
<Accordion title="什么时候该用 JSON 正确性而不是 LLM 裁判指标？">
当你关心的是*结构*而不是含义时——校验工具调用、函数参数或 API 响应能否解析出预期的字段与类型。要评判 JSON 的*内容*，请搭配基于 LLM 的指标。
</Accordion>
</AccordionGroup>
