title: Tool Correctness
---

**标签**：LLM-as-a-judge · 单轮 · 无参考 · 智能体 · 多模态

工具正确性（tool correctness）指标是一个智能体 LLM 指标，评估你的 LLM 智能体的函数/工具调用能力。它的计算方式是：比较预期使用的每个工具是否确实被调用，以及 LLM 智能体选择的工具是否最优。

<Note>
`ToolCorrectnessMetric` 允许你定义正确性的**严格程度**。默认只要求工具名匹配即算正确，但你也可以要求输入参数与输出都匹配。
</Note>

## Required Arguments

要使用 `ToolCorrectnessMetric`，你需要在创建 [`LLMTestCase`](/docs/evaluation-test-cases#llm-test-case) 时提供以下参数：

- `input`
- `actual_output`
- `tools_called`
- `expected_tools`

请阅读下文 [How Is It Calculated](#how-is-it-calculated) 一节，了解测试用例参数如何用于指标计算。

创建 `ToolCorrectnessMetric` 时有**九个**可选参数：

- [可选] `available_tools`：`ToolCall` 列表，提供你的 LLM 智能体可用的全部工具的上下文。该列表用于评估智能体的工具选择能力。
- [Optional] `threshold`: a number representing the minimum passing threshold. Can also be set to `None`（TypeScript 中为 `null`） to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [可选] `evaluation_params`：`ToolCallParams` 列表，指示正确性标准的严格程度，可选值为 `ToolCallParams.INPUT_PARAMETERS` 与 `ToolCallParams.OUTPUT`。例如，提供包含 `ToolCallParams.INPUT_PARAMETERS` 但不含 `ToolCallParams.OUTPUT` 的列表时，只要工具名与输入参数匹配即判正确，即使输出不同。默认为空列表。
- [可选] `include_reason`：布尔值，设为 `True`（TypeScript 中为 `true`）时，会为评估分数附带理由。默认为 `True`（TypeScript 中为 `true`）。
- [可选] `strict_mode`：布尔值，设为 `True`（TypeScript 中为 `true`）时，把指标分数强制为二元：完美为 1，否则为 0。它还会覆盖当前阈值并将其设为 1。默认为 `False`（TypeScript 中为 `false`）。
- [可选] `verbose_mode`：布尔值，设为 `True`（TypeScript 中为 `true`）时，把计算该指标所用的中间步骤打印到控制台，具体见 [How Is It Calculated](#how-is-it-calculated) 一节。默认为 `False`（TypeScript 中为 `false`）。
- [Optional] `should_consider_ordering`: a boolean which when set to `True`（TypeScript 中为 `true`）, will consider the ordering in which the tools were called in. For example, if `expected_tools=[ToolCall(name="WebSearch"), ToolCall(name="ToolQuery"), ToolCall(name="WebSearch")]` and `tools_called=[ToolCall(name="WebSearch"), ToolCall(name="WebSearch"),  ToolCall(name="ToolQuery")]`, the metric will consider the tool calling to be correct. Applies to the tool name matching that is always performed, and defaulted to `False`（TypeScript 中为 `false`）.
- [Optional] `should_exact_match`: a boolean which when set to `True`（TypeScript 中为 `true`）, will required the `tools_called` and `expected_tools` to be exactly the same. Applies to the tool name and type matching that is always performed, and additionally checks `ToolCallParams.INPUT_PARAMETERS` and `ToolCallParams.OUTPUT` when they are included in `evaluation_params`. Defaulted to `False`（TypeScript 中为 `false`）.
- [可选] `flaky`：布尔值，设为 `True`（TypeScript 中为 `true`）时，[把指标标记为 flaky](/docs/metrics-introduction#flaky-metrics)。默认为 `False`（TypeScript 中为 `false`）。

<Info>
Since `should_exact_match` is a stricter criteria than `should_consider_ordering`, setting `should_consider_ordering` will have no effect when `should_exact_match` is set to `True`（TypeScript 中为 `true`）.
</Info>

### 在组件内

你还可以在嵌套组件内运行 `ToolCorrectnessMetric`，进行[组件级](/docs/evaluation-component-level-llm-evals)评估。

<Tabs>

<Tab title="Python">

```python
from deepeval.dataset import EvaluationDataset, Golden
from deepeval.tracing import observe, update_current_span
...

@observe(metrics=[metric])
def inner_component():
    # Set test case at runtime
    test_case = LLMTestCase(input="...", actual_output="...")
    update_current_span(test_case=test_case)
    return

@observe
def llm_app(input: str):
    # Component can be anything from an LLM call, retrieval, agent, tool use, etc.
    inner_component()
    return

dataset = EvaluationDataset(goldens=[Golden(input="Hi!")])
for golden in dataset.evals_iterator():
    llm_app(golden.input)
```

</Tab>

<Tab title="TypeScript">

```typescript
import { EvaluationDataset, Golden } from "deepeval/dataset";
import { observe, updateCurrentSpan } from "deepeval/tracing";
// ...

const innerComponent = observe({
  metrics: [metric],
  fn: async () => {
    // Set test case at runtime
    const testCase = new LLMTestCase({ input: "...", actualOutput: "..." });
    updateCurrentSpan({ testCase });
  },
});

const llmApp = observe({
  fn: async (input: string) => {
    // Component can be anything from an LLM call, retrieval, agent, tool use, etc.
    await innerComponent();
  },
});

const dataset = new EvaluationDataset({ goldens: [new Golden({ input: "Hi!" })] });
for await (const golden of dataset.evalsIterator()) {
  await llmApp((golden as Golden).input);
}
```

## How Is It Calculated?

<Note>
与其他所有 `deepeval` 指标不同，`ToolCorrectnessMetric` 同时使用确定性与非确定性评估得出最终分数。它使用 `tools_called`、`expected_tools` 与 `available_tools` 求出最终分数。
</Note>

**工具正确性指标**的分数按以下步骤计算：

1. 用 `expected_tools` 按以下公式求出 `tools_called` 的确定性分数：

$$
\text{Tool Correctness} = \frac{\text{Number of Correctly Used Tools (or Correct Input Parameters/Outputs)}}{\text{Total Number of Tools Called}}
$$

- 该指标通过把你的 LLM 智能体 `tools_called` 的工具与 `expected_tools` 列表对比，评估智能体工具使用的准确性。分数为 1 表示你的 LLM 智能体使用的每个工具都依据 `expected_tools`、`should_consider_ordering` 与 `should_exact_match` 被正确调用；分数为 0 表示没有任何 `tools_called` 被正确调用。

<Info>
如果未指定 `should_exact_match` 且 `evaluation_params` 中包含 `ToolCallParams.INPUT_PARAMETERS`，正确性可能是一个百分比分数，基于正确输入参数的比例（在名称与输出也正确的前提下，如适用）。
</Info>

2. 如果提供了 `available_tools`，`ToolCorrectnessMetric` 还会用 LLM 以 `available_tools` 为参考，判断 `tools_called` 是否是该任务的最优选择。最终分数取**两个分数中的较小者**。若未提供 `available_tools`，则不会进行基于 LLM 的评估。

## FAQs

<AccordionGroup>
<Accordion title="Does Tool Correctness use an LLM?">
多数情况下不用。核心分数是确定性的——`tools_called` 与 `expected_tools` 的匹配计数。只有传入 `available_tools` 要求评判最优性时才会用到 LLM，最终分数取**两者中的较小值**。
</Accordion>
<Accordion title="How do I make matching stricter than just tool names?">
Add `ToolCallParams.INPUT_PARAMETERS` or `ToolCallParams.OUTPUT` to `evaluation_params` to also match inputs/outputs. Use `should_consider_ordering=True`（TypeScript 中为 `shouldConsiderOrdering: true`） for call order, or `should_exact_match=True`（TypeScript 中为 `shouldExactMatch: true`） for identical lists (overrides ordering).
</Accordion>
<Accordion title="Tool Correctness vs Argument Correctness — what's the difference?">
工具正确性检查是否调用了**正确的工具**，依据 `expected_tools` 确定性判断。[参数正确性](/docs/metrics-argument-correctness)检查传给这些工具的**参数**，由 LLM 无参考评估。
</Accordion>
<Accordion title="Can I evaluate whether the agent picked the best tool, not just a valid one?">
可以——传入 `available_tools`，由 LLM 判断 `tools_called` 是否最优。不传的话，指标只依据 `expected_tools` 确定性地检查调用。
</Accordion>
<Accordion title="Can I use Tool Correctness with LangChain, OpenAI, or another framework?">
可以。`deepeval` 会自动追踪用 [LangChain](/integrations/frameworks/langchain)、[OpenAI](/integrations/frameworks/openai)、LlamaIndex、CrewAI 等构建的智能体——全部[框架集成](/integrations)见相应页面。
</Accordion>
</AccordionGroup>
