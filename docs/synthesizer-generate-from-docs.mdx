如果你的应用是检索增强生成（RAG）系统，从文档生成 Golden 会特别有用，尤其是当你已经拥有**构成知识库的文档**时。

只需提供这些文档，`deepeval` 的 Synthesizer 会自动处理生成合成测试 Golden 所需的相关上下文。

`generate_goldens_from_docs()` 与 `generate_goldens_from_contexts()` 方法的唯一区别是 `generate_goldens_from_docs()` 多了一个[上下文构建步骤。](#how-does-context-construction-work)
</Tip>

## 前置条件

开始之前，从文档生成时必须安装额外的依赖：

- `chromadb`：上下文构建流水线中分块存储与检索所必需。
- `langchain-core`、`langchain-community`、`langchain-text-splitters`：文档解析与分块所必需。

```bash
pip install chromadb langchain-core langchain-community langchain-text-splitters
```

## Generate Your Goldens

<Note>
如果你没有 `OPENAI_API_KEY` 但希望合成 golden，除了自定义 LLM 之外，你还需要使用[自定义嵌入模型](/guides/guides-using-custom-embedding-models)。
</Note>

要从文档生成合成的单轮或多轮 golden，只需提供一组文档路径：

<Tabs>
<Tab title="单轮">

```python
from deepeval.synthesizer import Synthesizer

synthesizer = Synthesizer()
goldens = synthesizer.generate_goldens_from_docs(
    document_paths=['example.txt', 'example.docx', 'example.pdf'],
)
```

使用 `generate_goldens_from_docs` 方法时有**一个**必填参数和**三个**可选参数：

- `document_paths`：字符串列表，表示要从中提取上下文的文档路径。支持的文档类型包括：`.txt`、`.docx`、`.pdf`、`.md`、`.markdown` 和 `.mdx`。
- [可选] `include_expected_output`：布尔值，设为 `True` 时会额外为每个合成 `Golden` 生成一个 `expected_output`。默认为 `True`。
- [可选] `max_goldens_per_context`：每个上下文可生成的最大 golden 数。默认为 2。
- [可选] `context_construction_config`：`ContextConstructionConfig` 类型的实例，允许你[自定义从文档构建的上下文的质量和属性](#customize-context-construction)。默认为默认的 `ContextConstructionConfig` 值。

</Tab>
<Tab title="多轮">

```python
from deepeval.synthesizer import Synthesizer

synthesizer = Synthesizer()
conversational_goldens = synthesizer.generate_conversational_goldens_from_docs(
    document_paths=['example.txt', 'example.docx', 'example.pdf'],
)
```

使用 `generate_conversational_goldens_from_docs` 方法时有**一个**必填参数和**三个**可选参数：

- `document_paths`：字符串列表，表示要从中提取上下文的文档路径。支持的文档类型包括：`.txt`、`.docx`、`.pdf`、`.md`、`.markdown` 和 `.mdx`。
- [可选] `include_expected_outcome`：布尔值，设为 `True` 时会额外为每个合成 `ConversationalGolden` 生成一个 `expected_outcome`。默认为 `True`。
- [可选] `max_goldens_per_context`：每个上下文可生成的最大 golden 数。默认为 2。
- [可选] `context_construction_config`：`ContextConstructionConfig` 类型的实例，允许你[自定义从文档构建的上下文的质量和属性](#customize-context-construction)。默认为默认的 `ContextConstructionConfig` 值。

</Tab>
</Tabs>

**单轮生成**产出单轮 `Golden`，而**多轮生成**产出多轮 `ConversationalGolden`。更多关于 golden 的内容请[点击这里。](/docs/evaluation-datasets#what-are-goldens)

<Info>
最终生成的 golden 最大数量是 `max_goldens_per_context` 乘以 `context_construction_config` 中指定的 `max_contexts_per_document`，而**不是**简单地等于 `max_goldens_per_context`。
</Info>

## Customize Context Construction

你可以通过在生成时向 `generate_goldens_from_docs()` 方法提供 `ContextConstructionConfig` 实例，自定义从文档构建的上下文质量。

下面是单轮生成的示例（多轮同样适用）：

```python
from deepeval.synthesizer.config import ContextConstructionConfig

...
synthesizer.generate_goldens_from_docs(
  document_paths=['example.txt', 'example.docx', 'example.pdf', 'example.md', 'example.mdx'],
  context_construction_config=ContextConstructionConfig()
)
```

创建 `ContextConstructionConfig` 时有**七个**可选参数：

- [可选] `critic_model`：字符串，指定用于判定上下文 `quality_score` 的 OpenAI GPT 模型，**或者** `DeepEvalBaseLLM` 类型的[任意自定义 LLM 模型](/docs/metrics-introduction#using-a-custom-llm)。默认为 **`Synthesizer` 中使用的模型**；作为独立实例初始化时为 `gpt-5.4`。
- [可选] `encoding`：用于解码纯文本文件（`.txt`、`.md`、`.markdown`、`.mdx`）的编码。默认为自动检测编码。
- [可选] `max_contexts_per_document`：每个文档可生成的最大上下文数。默认为 3。
- [可选] `min_contexts_per_document`：每个文档可生成的最少上下文数。默认为 1。
- [可选] `max_context_length`：指定每个上下文生成的文本块数量上限（上下文长度）。默认为 3。
- [可选] `min_context_length`：指定每个上下文生成的文本块数量下限（上下文长度）。默认为 1。
- [可选] `chunk_size`：指定[文档解析](#synthesizer-generate-from-docs#document-parsing)期间考虑的文本块大小（以 token 计）。默认为 1024。
- [可选] `chunk_overlap`：整数，决定[文档解析](#synthesizer-generate-from-docs#document-parsing)期间相邻文本块之间的重叠大小。默认为 0。
- [可选] `context_quality_threshold`：浮点数，表示[上下文选择](synthesizer-generate-from-docs#context-selection)的最低质量阈值。上下文质量低于阈值时将被拒绝。默认为 `0.5`。
- [可选] `context_similarity_threshold`：浮点数，表示[上下文分组](synthesizer-generate-from-docs#context-grouping)所需的最低相似度分数。相似度低于该阈值的上下文将被拒绝。默认为 `0.5`。
- [可选] `max_retries`：整数，指定上下文选择**或**分组未达到要求质量**或**相似度阈值时的重试次数。默认为 `3`。
- [可选] `embedder`：字符串，指定文档解析与上下文分组期间使用的 OpenAI 嵌入模型，**或者** `DeepEvalBaseEmbeddingModel` 类型的[任意自定义嵌入模型](/guides/guides-using-custom-embedding-models)。默认为 'text-embedding-3-small'。

<Warning>
**与其他在实例化 `Synthesizer` 时定义生成流水线配置的定制不同**，上下文构建的定制发生在生成级别，因为上下文构建是 `generate_goldens_from_docs()` 方法独有的。

要了解如何定制生成流水线的其他所有方面（例如输出格式、演化复杂度），请[点击这里。](/docs/golden-synthesizer#customize-your-generations)
</Warning>

## How Does Context Construction Work?

`generate_goldens_from_docs()` 方法在 [golden 生成流水线](/docs/golden-synthesizer#how-does-it-work)之前多一个上下文构建流水线。因为要生成扎根于上下文的 golden，我们必须先从提供的文档中提取并构建上下文组。

上下文构建流水线由三个主要步骤组成：

- **文档解析**：把文档切分成更小、更易管理的块。
- **上下文选择**：从已解析、已嵌入的文档中随机选择块。
- **上下文分组**：把语义相似的块分组（使用余弦相似度），创建对后续生成足够有意义的上下文组。

[点击这里](#customize-context-construction)了解如何自定义上下文构建流水线使用的每一个参数。

<Info>
总结一下：文档首先被切分成块并嵌入，形成节点集合。随后随机选择节点，为每个被选中的节点检索相似节点并分组形成上下文。这些上下文随后按前几节所述用于生成合成 golden。
</Info>

### Document Parsing

在初始的**文档解析**步骤中，每个提供的文档都使用**基于 token 的文本切分器**（`TokenTextSplitter`）解析。这意味着 `chunk_size` 和 `chunk_overlap` 参数并不保证精确的字符长度，而是在 token 层面生效。

这些文本块随后由 `embedder` 嵌入并存入向量数据库，供后续选择与分组。

<Warning>
如果 `chunk_size` 大到无法生成 n=`max_contexts_per_document` 个不重复上下文，合成器会抛出错误。
</Warning>

### Context Selection

在**上下文选择**步骤中，从包含先前已索引节点的向量数据库中随机选择节点。每次选中一个节点都要接受过滤。因为分块后的上下文可能产生琐碎或不良的内容，例如一连串空白或来自文档结构的无关注字符，所以过滤对确保后续生成的 golden 有意义、相关且连贯非常重要。

每个块由 LLM（`critic_model`）依据以下标准进行质量打分（0-1）：

- **清晰度**：信息有多清晰、易懂。
- **深度**：提供的细节和洞察水平。
- **结构**：内容的组织与逻辑程度。
- **相关性**：内容与主题的贴合程度。

如果 `max_retries` 次重试后质量分数仍低于 `context_quality_threshold`，将使用质量分数最高的上下文。尽管这意味着你可能会看到未通过过滤的上下文被使用，但可以保证一定有上下文可用于分组。

<Note>
上下文构建流水线中的 `critic_model` 可以与[生成流水线的 `FiltrationConfig`](/docs/golden-synthesizer#filteration-quality) 中使用的不同。
</Note>

### Context Grouping

在最后的**上下文分组**步骤中，每个先前选中的节点会与 `max_context_length` 个余弦相似度高于 `context_similarity_threshold` 的其他节点分组。这确保每个上下文对后续生成来说足够连贯。

与上下文选择步骤类似，如果 `max_retries` 次重试后余弦相似度仍低于 `context_similarity_threshold`，将使用相似度分数最高的上下文。尽管这意味着你可能会看到未通过过滤的上下文被使用，但可以保证一定有上下文组可用于生成。

## FAQs

<AccordionGroup>
<Accordion title="What document types does generate_goldens_from_docs support?">
`.txt` 、`.docx` 、`.pdf` 、`.md` 、`.markdown` 和 `.mdx` 文件，以列表形式传入 `document_paths` 参数。
</Accordion>
<Accordion title="How are contexts constructed from my documents?">
`deepeval` 将文档解析为基于 token 的块（通过 `chunk_size` 和 `chunk_overlap` ），选择并做质量过滤，然后按余弦相似度把语义相似的块分组为上下文。用 `ContextConstructionConfig` 调整这一过程。
</Accordion>
<Accordion title="When should I use this instead of generate_goldens_from_contexts?">
当你有原始文档并希望 `deepeval` 替你提取上下文时，使用 `generate_goldens_from_docs`。如果你已经自己控制分块，请改用 [generate_goldens_from_contexts](/docs/synthesizer-generate-from-contexts)。
</Accordion>
<Accordion title="Can my team generate goldens from our documents without code?">
可以。在 [Confident AI](https://www.confident-ai.com) 上你可以连接知识库并无代码地运行生成流水线——调整过滤、演化和样式，试验不同变体，并与团队协作处理产生的数据集。
</Accordion>
</AccordionGroup>
