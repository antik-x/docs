title: Turn Faithfulness

**标签**：LLM-as-a-judge · 多轮 · RAG · 聊天机器人 · 多模态

轮次忠实度（turn faithfulness）指标是一个对话式指标，判断你的 LLM 聊天机器人**在整个对话过程中**生成的回复是否事实准确、并以检索上下文为依据。

## Required Arguments

要使用 `TurnFaithfulnessMetric`，你需要在创建 [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) 时提供以下参数：

- `turns`

你必须提供每个轮次的 `role`、`content` 与 `retrieval_context`，评估才能进行。更多信息见下方的 [How Is It Calculated](#how-is-it-calculated) 一节。

## Usage

`TurnFaithfulnessMetric()` 可用于[端到端](/docs/evaluation-end-to-end-llm-evals)多轮评估：

<Tabs>

<Tab title="Python">

```python
from deepeval.test_case import Turn, ConversationalTestCase
from deepeval.metrics import TurnFaithfulnessMetric
from deepeval import evaluate

convo_test_case = ConversationalTestCase(
    turns=[
        Turn(role="user", content="...", retrieval_context=["..."]),
        Turn(role="assistant", content="...", retrieval_context=["..."])
    ]
)
metric = TurnFaithfulnessMetric(threshold=0.5)

# To run metric as a standalone
# metric.measure(convo_test_case)
# print(metric.score, metric.reason)

evaluate(test_cases=[convo_test_case], metrics=[metric])
```

</Tab>

<Tab title="TypeScript">

```typescript
import { Turn, ConversationalTestCase } from "deepeval/test-case";

  ],

// To run metric as a standalone
// await metric.measure(convoTestCase);
// console.log(metric.score, metric.reason);

await evaluate([convoTestCase], [metric]);
```

- [Optional] `threshold`: a number representing the minimum passing threshold. Can also be set to `None`（TypeScript 中为 `null`） to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [可选] `model`：字符串，指定使用 OpenAI 的哪款 GPT 模型，**或**类型为 `DeepEvalBaseLLM` 的[任意自定义 LLM 模型](/docs/metrics-introduction#using-a-custom-llm)。默认为 `gpt-5.4`。
- [可选] `include_reason`：布尔值，设为 `True`（TypeScript 中为 `true`）时，会为评估分数附带理由。默认为 `True`（TypeScript 中为 `true`）。
- [可选] `strict_mode`：布尔值，设为 `True`（TypeScript 中为 `true`）时，把指标分数强制为二元：完美为 1，否则为 0。它还会覆盖当前阈值并将其设为 1。默认为 `False`（TypeScript 中为 `false`）。
- [可选] `async_mode`：布尔值，设为 `True` 时，启用[`measure()` 方法内的并发执行](/docs/metrics-introduction#measuring-metrics-in-async)。默认为 `True`。
  
- [可选] `verbose_mode`：布尔值，设为 `True`（TypeScript 中为 `true`）时，把计算该指标所用的中间步骤打印到控制台，具体见 [How Is It Calculated](#how-is-it-calculated) 一节。默认为 `False`（TypeScript 中为 `false`）。
- [Optional] `truths_extraction_limit`: an optional integer to limit the number of truths extracted from retrieval context per document. Defaulted to `None`（TypeScript 中为 `null`）.
- [Optional] `penalize_ambiguous_claims`: a boolean which when set to `True`（TypeScript 中为 `true`）, penalizes claims that cannot be verified as true or false. Defaulted to `False`（TypeScript 中为 `false`）.
- [可选] `window_size`：整数，定义评估期间使用的轮次滑动窗口大小。默认为 `10`。
- [可选] `flaky`：布尔值，设为 `True`（TypeScript 中为 `true`）时，[把指标标记为 flaky](/docs/metrics-introduction#flaky-metrics)。默认为 `False`（TypeScript 中为 `false`）。

## How Is It Calculated?

`TurnFaithfulnessMetric` 的分数按以下公式计算：

$$
\text{Turn Faithfulness} = \frac{\sum \text{Turn Faithfulness Scores}}{\text{Total Number of Assistant Turns}}
$$

`TurnFaithfulnessMetric` 首先构建轮次滑动窗口。对每个窗口，它会：

1. 从各轮次提供的检索上下文中**抽取真相**
2. 从该交互中助手的回复**生成声明**
3. **评估判定**，检查每条声明是否与真相矛盾
4. **计算该交互的分数**，即忠实声明占全部声明的比例

$$
\text{Faithfulness} = \frac{\text{Number of Truthful Claims}}{\text{Total Number of Claims}}
$$

最终分数是整段对话中所有交互忠实度分数的平均值。

## FAQs

<AccordionGroup>
<Accordion title="When should I use TurnFaithfulnessMetric instead of the single-turn FaithfulnessMetric?">
当 RAG 助手跨轮次作答、而你想让每条声明对照其所在窗口的 `retrieval_context` 检查时使用。单轮的 [FaithfulnessMetric](/docs/metrics-faithfulness) 只把一个输出对照一个上下文打分，无法定位是哪一轮产生了幻觉。
</Accordion>
<Accordion title="Does every turn need its own retrieval context?">
把 `retrieval_context` 挂到由检索生成的轮次上。指标会从该上下文抽取真相，并对照它们验证助手的声明——没有依据上下文的轮次正是忠实度问题浮现的地方。
</Accordion>
<Accordion title="My answers are factually correct but faithfulness is low — how do I debug it?">
忠实度奖励的是以 `retrieval_context` 为依据的声明，而不是碰巧为真的声明——正确但未出现在检索内容中的事实也算不忠实。用 `verbose_mode` 检查逐声明的判定，并尝试 `penalize_ambiguous_claims` 处理含糊声明。
</Accordion>
<Accordion title="How do window size and truths extraction limit affect long conversations?">
`window_size` (default `10` ) groups turns per evaluation; `truths_extraction_limit` caps truths pulled from each document. Tune them together when long conversations make scoring slow or noisy.
</Accordion>
</AccordionGroup>
