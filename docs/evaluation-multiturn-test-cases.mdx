## Quick Summary

**多轮测试用例**是 `deepeval` 提供的蓝图，用于对一系列 LLM 交互做单元测试。`deepeval` 中的多轮测试用例由 `ConversationalTestCase` 表示，有**五个**参数：

- `turns`
- [Optional] `scenario`
- [Optional] `expected_outcome`
- [Optional] `context`
- [Optional] `chatbot_role`

<Note>
`deepeval` 假设多轮使用场景主要是对话式聊天机器人。而智能体应当改用[组件级评估](/docs/evaluation-component-level-llm-evals)来评估，对你的智能体工作流中的每个组件单独评估。
</Note>

下面是一个 `ConversationalTestCase` 的示例实现：

<Tabs>

<Tab title="Python">

```python
from deepeval.test_case import ConversationalTestCase, Turn

test_case = ConversationalTestCase(
    scenario="User chit-chatting randomly with AI.",
    expected_outcome="AI should respond in friendly manner.",
    turns=[
        Turn(role="user", content="How are you doing?"),
        Turn(role="assistant", content="Why do you care?")
    ]
)
```

</Tab>

<Tab title="TypeScript">

```typescript
import { ConversationalTestCase, Turn } from "deepeval/test-case";

const testCase = new ConversationalTestCase({
  scenario: "User chit-chatting randomly with AI.",
  expectedOutcome: "AI should respond in friendly manner.",
  turns: [
    new Turn({ role: "user", content: "How are you doing?" }),
    new Turn({ role: "assistant", content: "Why do you care?" }),
  ],
});
```

</Tab>

</Tabs>

## 多轮 LLM 交互

与[单轮 LLM 交互](/docs/evaluation-test-cases#what-is-an-llm-interaction)不同，多轮 LLM 交互封装了用户与对话式智能体/聊天机器人之间的多次交换，在 `deepeval` 中由 `ConversationalTestCase` 表示。

![对话式测试用例](https://deepeval-docs.s3.amazonaws.com/docs:conversational-test-case.png)

对话式测试用例中的 `turns` 参数对指定对话的角色与内容（OpenAI API 格式）至关重要，并允许你提供可选的 `tools_called` 与 `retrieval_context`。其他可选参数如 `scenario` 与 `expected outcome` 最适合在评估时把 [`ConversationalGolden`](/docs/evaluation-datasets#goldens-data-model) 转换为测试用例的用户。

## Conversational Test Case

[单轮测试用例](/docs/evaluation-test-cases)表示单次 LLM 系统交互，而 `ConversationalTestCase` 封装了构成一次基于 LLM 的对话的一系列 `Turn`。当你想评估例如用户与基于 LLM 的聊天机器人之间的对话时，这特别有用。

`ConversationalTestCase` 只能用**对话式指标**来评估。

<Tabs>

<Tab title="Python">

```python title="main.py"
from deepeval.test_case import Turn, ConversationalTestCase

turns = [
    Turn(role="user", content="Why did the chicken cross the road?"),
    Turn(role="assistant", content="Are you trying to be funny?"),
]

test_case = ConversationalTestCase(turns=turns)
```

</Tab>

<Tab title="TypeScript">

```typescript title="main.ts"
import { Turn, ConversationalTestCase } from "deepeval/test-case";

const turns = [
  new Turn({ role: "user", content: "Why did the chicken cross the road?" }),
  new Turn({ role: "assistant", content: "Are you trying to be funny?" }),
];

const testCase = new ConversationalTestCase({ turns });
```

</Tab>

</Tabs>

<Note>
正如未明确说明时「测试用例」一词指 `LLMTestCase`，在 `deepeval` 全文中「指标」一词也指非对话式指标。
</Note>

### Turns

`turns` 参数是 `Turn` 的列表，基本上就是用户与 LLM 对话中的消息/交换列表。如果你使用 [`ConversationalGEval`](/docs/metrics-conversational-g-eval)，可能还想为 `Turn` 提供不同的参数。`Turn` 由以下参数组成：

```python
class Turn:
    role: Literal["user", "assistant"]
    content: str
    user_id: Optional[str] = None
    retrieval_context: Optional[List[Union[str, RetrievedContextData]]] = None
    tools_called: Optional[List[ToolCall]] = None
```

<Info>
只有当 `role` 为 `"assistant"` 时，你才应提供 `retrieval_context` 与 `tools_called` 参数。
</Info>

<Note>
`retrieval_context` 参数接受字符串列表或 `RetrievedContextData` 对象列表。
</Note>

```python
class RetrievedContextData(BaseModel):
    context: str
    source: str
```

`role` 参数指定某个轮次是 `"user"`（最终用户）还是 `"assistant"`（LLM）发出的。这与 OpenAI 的 API 类似。

对于**语音对话**，`Turn` 还携带额外字段，记录实际说了什么、何时说的、以及回复是否被打断：

```python
class Turn:
    ...
    audio: Optional[Audio] = None
    latency_ms: Optional[float] = None
    interrupted: Optional[bool] = None
```

- **`audio`** —— 该轮次的语音音频，为 [`Audio`](/docs/evaluation-voice#audio-data-model) 对象（片段时长为 `Audio.duration`）。
- **`latency_ms`** —— 用户说完后助手过了多久才开始说话（助手轮次）。
- **`interrupted`** —— 如果用户插话打断了这条助手回复则为 `True`；否则为 `None`。

轮次携带音频的 `ConversationalTestCase` 会自动把 `voice` 标志设为 `True`。这些字段在模拟中的含义见[语音](/docs/evaluation-voice)。

### Scenario

`scenario` 参数是一个**可选**参数，指定对话发生的情境。

### Chatbot Role

`chatbot_role` 参数是一个**可选**参数，指定聊天机器人应当扮演的角色。目前只有 `RoleAdherenceMetric` 需要它，在角色扮演评估场景中特别有用。

<Tabs>

<Tab title="Python">

```python

```

</Tab>

<Tab title="TypeScript">

```typescript
  chatbotRole: "A happy jolly wizard.",
  turns: [new Turn({ role: "user", content: "..." })],

```

</Tab>

### Context

`context` 是一个**可选**参数，表示你的 LLM 应用收到的、作为金标准真值补充来源的额外数据。你可以把它看作知识库中与特定输入相关的、作为支撑信息的理想片段。上下文是**静态的**，不应动态生成。

<Tabs>

<Tab title="Python">

```python
from deepeval.test_case import Turn, ConversationalTestCase

test_case = ConversationalTestCase(
    context=["Customers must be over 50 to be eligible for a refund."],
    turns=[Turn(...)]
)
```

</Tab>

<Tab title="TypeScript">

```typescript
import { Turn, ConversationalTestCase } from "deepeval/test-case";

const testCase = new ConversationalTestCase({
  context: ["Customers must be over 50 to be eligible for a refund."],
  turns: [new Turn({ role: "user", content: "..." })],
});
```

</Tab>

</Tabs>

<Info>
单轮 `LLMTestCase` 也包含 `context`。
</Info>

## Including Images

默认情况下，`deepeval` 支持通过 `MLLMImage` 对象在测试用例中同时传入文本与图片。`deepeval` 中的 `MLLMImage` 类用于在测试用例中引用多模态图片。它让你可以使用本地图片、远程 URL 和 `base64` 数据创建测试用例。

<Tabs>

<Tab title="Python">

```python
from deepeval.test_case import ConversationalTestCase, MLLMImage, Turn

shoes = MLLMImage(url='./shoes.png', local=True)

test_case = ConversationalTestCase(
    turns=[
        Turn(role="user", content=f"What's the color of the shoes in this image? {shoes}"),
        Turn(role="assistant", content=f"They are blue shoes!")
    ],
    scenario=f"A person trying to buy shoes online by looking at a customer's photo {shoes}",
    expected_outcome=f"The assistant must clarify that the shoes in the image {shoes} are blue color.",
    context=[f"..."]
)
```

</Tab>

<Tab title="TypeScript">

```typescript
import { ConversationalTestCase, Turn, MLLMImage } from "deepeval/test-case";

const shoes = new MLLMImage({ url: "./shoes.png", local: true });

const testCase = new ConversationalTestCase({
  turns: [
    new Turn({ role: "user", content: `What's the color of the shoes in this image? ${shoes}` }),
    new Turn({ role: "assistant", content: `They are blue shoes!` }),
  ],
  scenario: `A person trying to buy shoes online by looking at a customer's photo ${shoes}`,
  expectedOutcome: `The assistant must clarify that the shoes in the image ${shoes} are blue color.`,
  context: [`...`],
});
```

</Tab>

</Tabs>

<Info>
当你在输入或输出中包含 `MLLMImage` 对象时，多模态测试用例会被自动识别。你可以将它们与几乎所有 `deepeval` 指标一起使用。
</Info>

### `MLLMImage` 数据模型

以下是 `deepeval` 中 `MLLMImage` 的数据模型：

```python
class MLLMImage:
    dataBase64: Optional[str] = None
    mimeType: Optional[str] = None
    url: Optional[str] = None
    local: Optional[bool] = None
    filename: Optional[str] = None
```

初始化 `MLLMImage` 时，你**必须**提供 `url` 或同时提供 `dataBase64` 与 `mimeType` 参数。本地存储的图片 `local` 属性应设为 `True`，在线托管的图片设为 `False`（默认为 `False`）。

<Note>

所有 `MLLMImage` 实例都会被转换成一个特殊的 `deepeval` 占位符（例如 `[DEEPEVAL:IMAGE:uuid]`）。这就是把 `MLLMImage` 嵌入 f 字符串后它在测试用例中的样子：

<Tabs>

<Tab title="Python">

```python
from deepeval.test_case import ConversationalTestCase, Turn, MLLMImage

shoes = MLLMImage(url='./shoes.png', local=True)

test_case = ConversationalTestCase(
    turns=[
        Turn(role="user", content=f"What's the color of the shoes in this image? {shoes}"),
        Turn(role="assistant", content=f"They are blue shoes!")
    ]
)

print(test_case.turns[0].content)
```

</Tab>

<Tab title="TypeScript">

```typescript
import { ConversationalTestCase, Turn, MLLMImage } from "deepeval/test-case";

const shoes = new MLLMImage({ url: "./shoes.png", local: true });

const testCase = new ConversationalTestCase({
  turns: [
    new Turn({ role: "user", content: `What's the color of the shoes in this image? ${shoes}` }),
    new Turn({ role: "assistant", content: `They are blue shoes!` }),
  ],
});

console.log(testCase.turns[0].content);
```

</Tab>

</Tabs>

它输出如下内容：

```
What's the color of the shoes in this image? [DEEPEVAL:IMAGE:awefv234fvbnhg456]
```

想自行访问图片做任何 ETL 处理的用户，可以使用 `convert_to_multi_modal_array` 方法把你的测试用例按顺序转换为字符串与 `MLLMImage` 的列表。用法如下：

```python
from deepeval.test_case import ConversationalTestCase, Turn, MLLMImage
from deepeval.utils import convert_to_multi_modal_array

shoes = MLLMImage(url='./shoes.png', local=True)

test_case = ConversationalTestCase(
    turns=[
        Turn(role="user", content=f"What's the color of the shoes in this image? {shoes}"),
        Turn(role="assistant", content=f"They are blue shoes!")
    ]
)

print(convert_to_multi_modal_array(test_case.turns[0].content))
```

输出如下：

```
["What's the color of the shoes in this image? ",  [DEEPEVAL:IMAGE:awefv234fvbnhg456]]
```

这里的 `[DEEPEVAL:IMAGE:awefv234fvbnhg456]` 实际上就是你传入测试用例的那个 `MLLMImage` 实例。

</Note>

## 把测试用例标记为 Flaky

`flaky` 是一个**可选**的布尔参数（默认 `False`），用于把 `ConversationalTestCase` 标记为 flaky。flaky 测试用例的结果仍会正常计算、记录与报告，但它的失败不会阻塞你的 CI/CD 流水线——当 flaky 测试用例失败时，`assert_test()` 会打印警告而不是抛出 `AssertionError`。

```python
from deepeval.test_case import Turn, ConversationalTestCase

test_case = ConversationalTestCase(
    flaky=True,
    turns=[Turn(...)]
)
```

这最适合那些你明知有噪声的对话——例如分数处于临界、多次运行在通过与失败之间来回摆动的模拟对话，但你仍想继续评估与追踪、又不想让它们阻塞部署。`flaky` 状态也会记录在 Confident AI 上，方便你监控 flaky 测试用例实际的失败频率。

<Info>
单轮 `LLMTestCase` 也可以被标记为 `flaky`，指标也可以——flaky **指标**的失败永远不会决定其测试用例的通过/失败状态。
</Info>

## 为 Confident AI 标记测试用例

如果你在使用 Confident AI，以下是一些帮助你管理测试用例的额外参数。

### Name

可选的 `name` 参数允许你提供一个字符串标识来标记 `LLMTestCase` 与 `ConversationalTestCase`，方便你在 Confident AI 上搜索与过滤。当你从外部数据源导入测试用例时尤其有用。

<Tabs>

<Tab title="Python">

```python
from deepeval.test_case import ConversationalTestCase

test_case = ConversationalTestCase(name="my-external-unique-id", ...)
```

</Tab>

<Tab title="TypeScript">

```typescript
import { Turn, ConversationalTestCase } from "deepeval/test-case";

const testCase = new ConversationalTestCase({
  name: "my-external-unique-id",
  turns: [new Turn({ role: "user", content: "..." })],
});
```

</Tab>

</Tabs>

### Tags

你也可以为测试用例打标签，以便在 Confident AI 上过滤与搜索：

```python
from deepeval.test_case import ConversationalTestCase

test_case = ConversationalTestCase(tags=["Topic 1", "Topic 3"], ...)
```

## 用测试用例进行评估

你可以为两种类型的评估创建测试用例：

- [端到端](/docs/evaluation-end-to-end-llm-evals) - 把你的多轮 LLM 应用当作黑盒，综合考虑每个轮次的输入与输出来评估整体对话。
- 一次性独立评估 - 在单个测试用例上执行单个指标，用于调试或自定义评估流水线

与单轮测试用例不同，多轮场景不存在组件级评估的概念。

## FAQs

<AccordionGroup>
<Accordion title="ConversationalTestCase 与 LLMTestCase 有什么区别？">
`ConversationalTestCase` 通过一系列 `Turn` 表示完整的多轮对话，而 [`LLMTestCase`](/docs/evaluation-test-cases) 表示单次原子化的交互。当上下文跨越多个轮次（例如聊天机器人与助手）时，使用对话式的那个。
</Accordion>
<Accordion title="一个 Turn 包含什么？">
每个 `Turn` 有一个 `role`（ `user` 或 `assistant` ）与 `content`，并可选地携带检索上下文、工具调用与 MCP 原语，以便对逐轮行为进行评估。
</Accordion>
<Accordion title="scenario 和 expected_outcome 是做什么用的？">
它们从高层描述对话：`scenario` 设定用户所处的情境，`expected_outcome` 描述一次成功的对话应当达成什么。它们对模拟轮次以及基于结果的对话式指标尤其有用。
</Accordion>
<Accordion title="每一轮都必须手写吗？">
不需要。你可以手工编写轮次，也可以用[对话模拟器](/docs/conversation-simulator)基于 `ConversationalGolden` 的场景与用户人设自动生成它们。
</Accordion>
<Accordion title="多轮测试用例可以包含图片吗？">
可以。你可以在轮次的内容中嵌入 `MLLMImage` 对象，以评估多模态对话。
</Accordion>
<Accordion title="我的团队如何在云端共享多轮对话并在界面中可视化？">
对话完全在本地运行，但在终端里阅读冗长的多轮转写不太可扩展。登录 [Confident AI](https://www.confident-ai.com)（`deepeval` 团队的平台）会把同样的对话及其逐轮分数渲染到共享的云端界面中，团队可以审阅、标注并追踪其随时间的变化——无需改动你的测试用例代码。它完全是可选的。
</Accordion>
</AccordionGroup>
