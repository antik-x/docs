## TLS Errors

如果 `deepeval` 上传结果到 Confident AI 失败，报错类似：

<Tabs>

<Tab title="Python">

```text
SSLCertVerificationError: [SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed: unable to get local issuer certificate
```

</Tab>

<Tab title="TypeScript">

```text
Error: unable to verify the first certificate (UNABLE_TO_VERIFY_LEAF_SIGNATURE)
```

</Tab>

</Tabs>

这通常意味着本地环境（而非 `deepeval` 内部）的证书校验失败。

请在你运行 `deepeval` 的同一台机器和环境中执行以下检查。

1. 用 `curl` 检查

```bash
curl -v https://api.confident-ai.com/
```

如果 `curl` 报告 SSL/证书错误，请复制完整输出。

2. 在代码中检查

通过 `deepeval` 使用的同一套 HTTP 栈访问 API：

<Tabs>

<Tab title="Python">

```bash
unset REQUESTS_CA_BUNDLE SSL_CERT_FILE SSL_CERT_DIR
python -m pip install -U certifi
python - << 'PY'
import requests

r = requests.get("https://api.confident-ai.com")
print(r.status_code)
PY
```

</Tab>

<Tab title="TypeScript">

```bash
node -e "require('https').get('https://api.confident-ai.com', r => console.log(r.statusCode)).on('error', e => console.error(e))"
```

</Tab>

</Tabs>

如果这一步因证书错误失败，请复制完整输出。

<Info>
**TypeScript**

当你的组织用私有 CA 终结 TLS 时，让 Node 指向该 CA 证书包：

```bash
export NODE_EXTRA_CA_CERTS=/path/to/your-ca.pem
```
</Info>

3. 重新运行 `deepeval`

如果上面的代码片段成功了，请在同一个终端会话中重新运行你的 `deepeval` 评估，看上传是否仍然失败。如果仍出现 TLS 错误，请在报告问题时附上完整错误以及上述两项检查的输出。

### When to disable SSL verification

`CONFIDENT_DISABLE_SSL=1` 会关闭 `deepeval` 对 Confident AI API 请求的证书校验。

<Warning>
禁用 SSL 校验只应作为修复受信任证书链期间的临时手段。不要把它当作永久设置，尤其是在内部/自托管环境之外。
</Warning>

以下情况你可能需要开启它：

- 你在用 `CONFIDENT_BASE_URL` 把 `deepeval` 指向内部或自托管的 Confident AI API。
- 该端点使用自签名证书、私有 CA，或你的运行时证书存储不信任的证书链。
- 你已确认失败与证书校验有关。

优先修复受信任的证书链，而不是禁用校验。对于公共 Confident AI 端点（`https://api.confident-ai.com`、`https://eu.api.confident-ai.com` 或 `https://au.api.confident-ai.com`），请保持 SSL 校验开启；如错误持续，请附上完整的 TLS 诊断信息。

```bash
export CONFIDENT_BASE_URL=https://your-self-hosted-confident-api.example.com
export CONFIDENT_DISABLE_SSL=1
```

## Configure Logging

<Tabs>

<Tab title="Python">

`deepeval` 使用标准的 Python `logging` 模块。要看到日志，你的应用（或测试运行器）需要配置日志输出。

```python
import logging

logging.basicConfig(level=logging.DEBUG)
```

</Tab>

<Tab title="TypeScript">

`deepeval` 无需任何配置即可写入控制台，级别为 `WARNING` 及以上。调低 `LOG_LEVEL` 可以看到其余日志。

```bash
export LOG_LEVEL=DEBUG
```

</Tab>

</Tabs>

`deepeval` 还暴露了几个便于调试的环境开关：

- `LOG_LEVEL`：设置 `deepeval` 使用的全局日志级别（接受 `DEBUG`、`INFO` 等标准名称）。
- `DEEPEVAL_VERBOSE_MODE`：启用额外的警告与诊断。
- `DEEPEVAL_LOG_STACK_TRACES`：在重试日志中包含堆栈跟踪。
- `DEEPEVAL_RETRY_BEFORE_LOG_LEVEL`：重试"休眠前"消息的日志级别。
- `DEEPEVAL_RETRY_AFTER_LOG_LEVEL`：重试"尝试后"消息的日志级别。

注意重试日志级别是在调用时读取的。

## Timeout Tuning

如果评估频繁超时（或看起来卡住），最快的解决办法通常是增大单任务总时间预算并减少重试次数。

`deepeval` 对每个任务（指标/测试用例）使用外层时间预算。它还可以对单个提供商调用施加单次尝试超时。如果你没有设置单次尝试覆盖，`deepeval` 可能会根据外层预算和重试设置推导出一个。

关键设置：

- `DEEPEVAL_PER_TASK_TIMEOUT_SECONDS_OVERRIDE`：每个任务的总时间预算（秒），包括重试。
- `DEEPEVAL_PER_ATTEMPT_TIMEOUT_SECONDS_OVERRIDE`：提供商调用的单次尝试超时（秒）。
- `DEEPEVAL_TASK_GATHER_BUFFER_SECONDS_OVERRIDE`：为异步 gather/清理预留的额外缓冲。
- `DEEPEVAL_RETRY_MAX_ATTEMPTS`：总尝试次数（首次尝试 + 重试）。
- `DEEPEVAL_RETRY_INITIAL_SECONDS`、`DEEPEVAL_RETRY_EXP_BASE`、`DEEPEVAL_RETRY_JITTER`、`DEEPEVAL_RETRY_CAP_SECONDS`：重试退避调节。
- `DEEPEVAL_SDK_RETRY_PROVIDERS`：应改用 SDK 管理重试而非 `deepeval` 重试的提供商标识列表（`['*']` 表示全部）。

常见的调试做法是临时增大预算：

```bash
export LOG_LEVEL=DEBUG
export DEEPEVAL_VERBOSE_MODE=1
export DEEPEVAL_PER_TASK_TIMEOUT_SECONDS_OVERRIDE=600
export DEEPEVAL_RETRY_MAX_ATTEMPTS=2

```

<Tip>
在高延迟或重度限流的网络上，增大外层预算（`DEEPEVAL_PER_TASK_TIMEOUT_SECONDS_OVERRIDE`）通常是最稳妥的起点。
</Tip>

<Note>
如果只设置 `DEEPEVAL_PER_TASK_TIMEOUT_SECONDS_OVERRIDE`，`deepeval` 可能根据总预算和重试设置推导出单次尝试超时。
如果单次尝试超时未设置或解析为 `0`，`deepeval` 会跳过内层的 `asyncio.wait_for`，只依赖外层的单任务预算。
对于同步超时，`deepeval` 使用有界信号量。参见 `DEEPEVAL_TIMEOUT_THREAD_LIMIT` 和 `DEEPEVAL_TIMEOUT_SEMAPHORE_WARN_AFTER_SECONDS`。
</Note>

## Dotenv Loading

`deepeval` 在首次导入时加载 dotenv 文件，这可能会在你运行测试套件时带入并非有意加载的项目 `.env`。dotenv 永远不覆盖已有的进程环境变量。优先级从低到高：`.env`、`.env.{APP_ENV}`、`.env.local`。

控制项：`DEEPEVAL_DISABLE_DOTENV=1`（跳过加载）和 `ENV_DIR_PATH`（dotenv 目录，默认：当前工作目录）。

<Tip>
请在任何东西导入 `deepeval` **之前**设置 `DEEPEVAL_DISABLE_DOTENV=1`。
</Tip>

<Tabs>

<Tab title="Python">

```bash
DEEPEVAL_DISABLE_DOTENV=1 pytest -q
ENV_DIR_PATH=/path/to/project pytest -q
APP_ENV=production pytest -q
```

</Tab>

<Tab title="TypeScript">

```bash
DEEPEVAL_DISABLE_DOTENV=1 npx deepeval test run tests/evals
ENV_DIR_PATH=/path/to/project npx deepeval test run tests/evals
APP_ENV=production npx deepeval test run tests/evals
```

</Tab>

</Tabs>

## Save Config

`deepeval` 的设置会被缓存。如果你在运行时修改了环境变量但没有看到变化，请重启进程。

<Tabs>

<Tab title="Python">

你也可以原地重新加载：

```python
from deepeval.config.settings import reset_settings

reset_settings(reload_dotenv=True)
```

要从代码持久化设置变更，使用 `edit()`：

```python
from deepeval.config.settings import get_settings

settings = get_settings()
with settings.edit(save="dotenv"):
    settings.DEEPEVAL_VERBOSE_MODE = True
```

计算字段（如派生的超时设置）不会被持久化。

</Tab>

<Tab title="TypeScript">

要持久化某个设置而不是每次会话都导出，用 CLI 把它写入你的 dotenv 文件：

```bash
npx deepeval settings --set DEEPEVAL_VERBOSE_MODE=1 --save
```

</Tab>

</Tabs>

## Report issue

如果你要提 GitHub issue，请包含：

- `deepeval` 版本
- Your OS, plus the output of `python --version`（TypeScript 中为 `node --version`）
- 一个最小复现脚本
- 完整堆栈跟踪
- `LOG_LEVEL=DEBUG` 下的日志
- 你设置过的任何非默认 `deepeval` 环境变量

请对 API key 和其他任何密钥做脱敏处理。
