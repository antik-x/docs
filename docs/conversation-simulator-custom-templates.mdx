---
title: Custom Templates
---

通过传入 `template=` 来自定义用于模拟用户轮次的提示词。你可以覆盖默认的用户模拟和助手模拟模板。

## API

```python
from deepeval.simulator import default_simulation_node

default_simulation_node(template=MyTemplate)
```

| Argument | Description |
|---|---|
| `template` | A subclass of `SimulationTemplate` overriding `simulate_first_user_turn()` and/or `simulate_user_turn()`. Validated eagerly — invalid templates raise `TypeError` at construction time. When omitted, the built-in `SimulationTemplate` is used. |
| `terminal`, `max_visits`, `name` | Same as `SimulationNode` — see [Simulation Graph](/docs/conversation-simulator-simulation-graph#default_simulation_node) for full reference. |

自定义模板必须：

- 继承自 `SimulationTemplate`。
- 覆盖 `simulate_first_user_turn(golden, language)` 来改变**第一条**用户消息的生成方式。
- 覆盖 `simulate_user_turn(golden, turns, language)` 来改变**后续**用户消息的生成方式。

两个方法都必须返回一个提示字符串，该字符串引导出包含 `simulated_input` 键的 JSON 响应。

<Note>
过去接受顶层 `simulation_template=` 关键字参数。该参数已被移除，改用 `default_simulation_node(template=...)`，它将模板保持在实际使用它的节点上。
</Note>

## 示例

```python
from deepeval.simulator import (
    ConversationSimulator,
    SimulationTemplate,
    default_simulation_node,
)

class FormalUserTemplate(SimulationTemplate):
    @staticmethod
    def simulate_first_user_turn(golden, language):
        return f"""
        Pretend you are a formal enterprise buyer.
        Start a conversation in {language} for this scenario:
        {golden.scenario}

        Return JSON with one key: simulated_input.
        """

    @staticmethod
    def simulate_user_turn(golden, turns, language):
        return f"""
        Continue the conversation as a formal enterprise buyer.
        Keep the tone concise, professional, and procurement-oriented.

        Scenario: {golden.scenario}
        Conversation so far: {turns}

        Return JSON with one key: simulated_input.
        """

simulator = ConversationSimulator(
    model_callback=model_callback,
    simulation_graph=default_simulation_node(template=FormalUserTemplate),
)
```

## Common Use Cases

### 用户风格

当模拟用户需要以特定语气说话时使用自定义模板，例如正式的买家、沮丧的客户、临床医生、学生或非技术用户。

### 领域框架

当生成的用户轮次应反映默认模拟器提示未强调的领域特定行为、词汇或约束时，使用自定义模板。

### 对话压力

当你希望模拟用户比默认角色扮演行为更具对抗性、更困惑、更简洁或更执着时，使用自定义模板。

### 与模拟图混合使用

你还可以将 `default_simulation_node(template=...)` 作为节点嵌入更大的[模拟图](/docs/conversation-simulator-simulation-graph)中。

```python
from deepeval.simulator import SimulationNode, default_simulation_node

scripted_opener = SimulationNode(
    action=lambda: "Hi, I need help with a refund.",
    name="opener",
)
scripted_opener.add_node(
    default_simulation_node(template=FormalUserTemplate),
    when="The assistant asked a clarifying question",
)
```

## 常见问题

<AccordionGroup>
<Accordion title="When do I need a custom template versus the default simulator?">
当模拟用户需要以特定语气、领域框架或压力水平说话时使用它。如果默认的角色扮演听起来已经合适，就不需要模板。
</Accordion>
<Accordion title="How do I actually plug a custom template in?">
Pass it to `default_simulation_node(template=MyTemplate)` and feed the returned node into `simulation_graph` . The old top-level `simulation_template=` kwarg has been removed in favor of this, which keeps the template attached to the node that consumes it.
</Accordion>
<Accordion title="Which methods does my template have to override?">
Subclass `SimulationTemplate` and override `simulate_first_user_turn(golden, language)` and/or `simulate_user_turn(golden, turns, language)` . Each must return a prompt string that elicits JSON with one key, `simulated_input` . Templates are validated eagerly, so bad subclasses raise `TypeError` at construction time.
</Accordion>
<Accordion title="Can I keep a custom voice on some branches but script others?">
Yes — embed `default_simulation_node(template=...)` as one node inside a larger [simulation graph](/docs/conversation-simulator-simulation-graph) , using the template for free-form exploration on some branches and deterministic, scripted nodes on others.
</Accordion>
</AccordionGroup>
