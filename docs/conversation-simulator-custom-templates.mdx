---
title: Custom Templates
---

通过将 `template=` 传给 [`default_simulation_node`](/docs/conversation-simulator-simulation-graph#default_simulation_node) 并把返回的节点传入 `simulation_graph`，自定义用于模拟用户轮次的提示词。

## API

```python
from deepeval.simulator import default_simulation_node

default_simulation_node(template=MyTemplate)
```

| Argument | Description |
|---|---|
| `template` | `SimulationTemplate` 的子类，覆盖 `simulate_first_user_turn()` 和/或 `simulate_user_turn()`。会在构造时立即验证——无效模板会在构造时抛出 `TypeError`。省略时使用内置的 `SimulationTemplate`。 |
| `terminal`, `max_visits`, `name` | 与 `SimulationNode` 相同——完整参考见 [Simulation Graph](/docs/conversation-simulator-simulation-graph#default_simulation_node)。 |

自定义模板必须：

- 继承自 `SimulationTemplate`。
- 覆盖 `simulate_first_user_turn(golden, language)` 来改变**第一条**用户消息的生成方式。
- 覆盖 `simulate_user_turn(golden, turns, language)` 来改变**后续**用户消息的生成方式。

两个方法都必须返回一个提示字符串，该字符串引导出包含 `simulated_input` 键的 JSON 响应。

<Note>
`ConversationSimulator` 过去接受顶层 `simulation_template=` 关键字参数。该参数已被移除，改用 `default_simulation_node(template=...)`，它将模板保持在实际使用它的节点上。
</Note>

## Example

```python
from deepeval.simulator import (
    ConversationSimulator,
    SimulationTemplate,
    default_simulation_node,
)

class FormalUserTemplate(SimulationTemplate):
    @staticmethod
    def simulate_first_user_turn(golden, language):
        return f"""
        Pretend you are a formal enterprise buyer.
        Start a conversation in {language} for this scenario:
        {golden.scenario}

        Return JSON with one key: simulated_input.
        """

    @staticmethod
    def simulate_user_turn(golden, turns, language):
        return f"""
        Continue the conversation as a formal enterprise buyer.
        Keep the tone concise, professional, and procurement-oriented.

        Scenario: {golden.scenario}
        Conversation so far: {turns}

        Return JSON with one key: simulated_input.
        """

simulator = ConversationSimulator(
    model_callback=model_callback,
    simulation_graph=default_simulation_node(template=FormalUserTemplate),
)
```

## Common Use Cases

### User Style

当模拟用户需要以特定语气说话时使用自定义模板，例如正式的买家、沮丧的客户、临床医生、学生或非技术用户。

### Domain Framing

当生成的用户轮次应反映默认模拟器提示未强调的领域特定行为、词汇或约束时，使用自定义模板。

### Conversation Pressure

当你希望模拟用户比默认角色扮演行为更具对抗性、更困惑、更简洁或更执着时，使用自定义模板。

### Mixing with a Simulation Graph

你还可以将 `default_simulation_node(template=...)` 作为节点嵌入更大的[模拟图](/docs/conversation-simulator-simulation-graph)中。

```python
from deepeval.simulator import SimulationNode, default_simulation_node

scripted_opener = SimulationNode(
    action=lambda: "Hi, I need help with a refund.",
    name="opener",
)
scripted_opener.add_node(
    default_simulation_node(template=FormalUserTemplate),
    when="The assistant asked a clarifying question",
)
```

## FAQs

<AccordionGroup>
<Accordion title="When do I need a custom template versus the default simulator?">
当模拟用户需要以特定语气、领域框架或压力水平说话时使用它——正式的买家、沮丧的客户、临床医生、更具对抗性或更简洁的用户。如果默认的角色扮演听起来已经合适，就不需要模板。
</Accordion>
<Accordion title="如何实际接入自定义模板？">
把它传给 `default_simulation_node(template=MyTemplate)` 并将返回的节点传入 `simulation_graph`。旧的顶层 `simulation_template=` 参数已被移除，改为此方式，它将模板保持在实际使用它的节点上。
</Accordion>
<Accordion title="我的模板必须覆盖哪些方法？">
继承 `SimulationTemplate` 并覆盖 `simulate_first_user_turn(golden, language)` 和/或 `simulate_user_turn(golden, turns, language)`。每个方法都必须返回一个引导出包含 `simulated_input` 键的 JSON 响应的提示字符串。模板会立即验证，因此无效的子类会在构造时抛出 `TypeError`。
</Accordion>
<Accordion title="可以在某些分支上保留自定义语气但对其他分支使用脚本吗？">
可以——将 `default_simulation_node(template=...)` 作为一个节点嵌入更大的[模拟图](/docs/conversation-simulator-simulation-graph)中，在某些分支上使用自定义模板进行自由探索，在其他分支上使用确定性脚本节点。
</Accordion>
</AccordionGroup>
