**标签**：LLM-as-a-judge · 单轮 · 无参考 · 多模态

提示词对齐（prompt alignment）指标使用 LLM-as-a-judge，衡量你的 LLM 应用能否生成与提示词模板中指定的**指令**相一致的 `actual_output`。`deepeval` 的提示词对齐指标是会自我解释的 LLM-Eval，会输出指标分数的理由。

<Tip>
不确定这个指标是否适合你？运行以下命令一探究竟：

```bash
deepeval recommend metrics
```

</Tip>

## Required Arguments

要使用 `PromptAlignmentMetric`，你需要在创建 [`LLMTestCase`](/docs/evaluation-test-cases#llm-test-case) 时提供以下参数：

- `input`
- `actual_output`

请阅读下文 [How Is It Calculated](#how-is-it-calculated) 一节，了解测试用例参数如何用于指标计算。

## Usage

`PromptAlignmentMetric()` 可用于[端到端](/docs/evaluation-end-to-end-llm-evals)评估：

<Tabs>

<Tab title="Python">

```python
from deepeval.metrics import PromptAlignmentMetric
from deepeval.test_case import LLMTestCase
from deepeval import evaluate

metric = PromptAlignmentMetric(
    prompt_instructions=["Reply in all uppercase"],
    model="gpt-4",
    include_reason=True
)
test_case = LLMTestCase(
    input="What if these shoes don't fit?",
    # Replace this with the actual output from your LLM application
    actual_output="We offer a 30-day full refund at no extra cost."
)

# To run metric as a standalone
# metric.measure(test_case)
# print(metric.score, metric.reason)

evaluate(test_cases=[test_case], metrics=[metric])
```

</Tab>

<Tab title="TypeScript">

```typescript
import { PromptAlignmentMetric } from "deepeval/metrics";
import { LLMTestCase } from "deepeval/test-case";
import { evaluate } from "deepeval";

const metric = new PromptAlignmentMetric({
  promptInstructions: ["Reply in all uppercase"],
  model: "gpt-4",
  includeReason: true,
});
const testCase = new LLMTestCase({
  input: "What if these shoes don't fit?",
  // Replace this with the actual output from your LLM application
  actualOutput: "We offer a 30-day full refund at no extra cost.",
});

// To run metric as a standalone
// await metric.measure(testCase);
// console.log(metric.score, metric.reason);

await evaluate([testCase], [metric]);
```

- `prompt_instructions`：字符串列表，指定你希望在提示词模板中被遵循的指令。
- [Optional] `threshold`: a number representing the minimum passing threshold. Can also be set to `None`（TypeScript 中为 `null`） to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [可选] `model`：字符串，指定使用 OpenAI 的哪款 GPT 模型，**或**类型为 `DeepEvalBaseLLM` 的[任意自定义 LLM 模型](/docs/metrics-introduction#using-a-custom-llm)。默认为 `gpt-5.4`。
- [可选] `include_reason`：布尔值，设为 `True`（TypeScript 中为 `true`）时，会为评估分数附带理由。默认为 `True`（TypeScript 中为 `true`）。
- [可选] `strict_mode`：布尔值，设为 `True`（TypeScript 中为 `true`）时，把指标分数强制为二元：完美为 1，否则为 0。它还会覆盖当前阈值并将其设为 1。默认为 `False`（TypeScript 中为 `false`）。
- [可选] `async_mode`：布尔值，设为 `True` 时，启用[`measure()` 方法内的并发执行](/docs/metrics-introduction#measuring-a-metric-in-async)。默认为 `True`。
  
- [可选] `verbose_mode`：布尔值，设为 `True`（TypeScript 中为 `true`）时，把计算该指标所用的中间步骤打印到控制台，具体见 [How Is It Calculated](#how-is-it-calculated) 一节。默认为 `False`（TypeScript 中为 `false`）。
- [可选] `flaky`：布尔值，设为 `True`（TypeScript 中为 `true`）时，[把指标标记为 flaky](/docs/metrics-introduction#flaky-metrics)。默认为 `False`（TypeScript 中为 `false`）。

### 在组件内

你还可以在嵌套组件内运行 `PromptAlignmentMetric`，进行[组件级](/docs/evaluation-component-level-llm-evals)评估。

<Tabs>

<Tab title="Python">

```python
from deepeval.dataset import EvaluationDataset, Golden
from deepeval.tracing import observe, update_current_span
...

@observe(metrics=[metric])
def inner_component():
    # Set test case at runtime
    test_case = LLMTestCase(input="...", actual_output="...")
    update_current_span(test_case=test_case)
    return

@observe
def llm_app(input: str):
    # Component can be anything from an LLM call, retrieval, agent, tool use, etc.
    inner_component()
    return

dataset = EvaluationDataset(goldens=[Golden(input="Hi!")])
for golden in dataset.evals_iterator():
    llm_app(golden.input)
```

</Tab>

<Tab title="TypeScript">

```typescript
import { EvaluationDataset, Golden } from "deepeval/dataset";
import { observe, updateCurrentSpan } from "deepeval/tracing";
// ...

const innerComponent = observe({
  metrics: [metric],
  fn: async () => {
    // Set test case at runtime
    const testCase = new LLMTestCase({ input: "...", actualOutput: "..." });
    updateCurrentSpan({ testCase });
  },
});

const llmApp = observe({
  fn: async (input: string) => {
    // Component can be anything from an LLM call, retrieval, agent, tool use, etc.
    await innerComponent();
  },
});

const dataset = new EvaluationDataset({
  goldens: [new Golden({ input: "Hi!" })],
});
for await (const golden of dataset.evalsIterator()) {
  await llmApp((golden as Golden).input);
}
```

## How Is It Calculated?

`PromptAlignmentMetric` 的分数按以下公式计算：

$$
\text{Prompt Alignment} = \frac{\text{Number of Instructions Followed}}{\text{Total Number of Instructions}}
$$

`PromptAlignmentMetric` 使用 LLM，借助 `input` 中的额外上下文，判断每条提示词指令是否在 `actual_output` 中被遵循。

<Tip>

通过提供 `prompt_instructions` 的初始列表而不是整个提示词模板，`PromptAlignmentMetric` 能更准确地判断提示词模板中的核心指令是否被遵循。

</Tip>

## FAQs

<AccordionGroup>
<Accordion title="为什么要单独传提示词指令，而不是完整的提示词模板？">
完整的模板把指令与示例、格式混在一起，会让裁判的判断不够可靠。只列出你希望被遵循的 `prompt_instructions`，指标就能干净地为每条打分，并精确定位哪条被遵循、哪条被忽略。
</Accordion>
<Accordion title="How do I find out which specific instruction was violated?">
Keep `include_reason=True`（TypeScript 中为 `includeReason: true`） (default) for a `reason` naming the failed instructions, or set `verbose_mode=True`（TypeScript 中为 `verboseMode: true`） for the per-instruction classification. Splitting bundled instructions into separate entries isolates the offender.
</Accordion>
<Accordion title="每条提示词指令应该是单一规则，还是可以打包多条？">
每个条目一条原子规则。`prompt_instructions` 中的每一项都会被单独判定遵循与否，打包（例如「全大写且不超过 20 词」）会导致全有或全无的判定，掩盖失败的那一半。
</Accordion>
<Accordion title="1.0 分在这里具体意味着什么？">
`prompt_instructions` 中的每条指令都在 `actual_output` 中被遵循——但只有你列出的那些会被评估。`strict_mode` 会强制同样的二元 1 或 0 结果，并把阈值设为 1。
</Accordion>
</AccordionGroup>
