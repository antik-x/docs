`deepeval` 会按以下顺序自动从 dotenv 文件加载环境变量：`.env` → `.env.{APP_ENV}` → `.env.local`（最高优先级）。已有的进程环境变量永远不会被覆盖——进程环境变量总是优先。

## Boolean flags

用 `1` 启用布尔环境变量，用 `0` 禁用。这两个值对本页所有布尔变量都有效，因此每个示例都用它们。

规则：
- 取值匹配不区分大小写，两侧的引号或空白会被忽略。
- 如果值**未设置**（或不匹配任何可识别的取值），`deepeval` 回退到该设置的默认值。

其他拼写—— `true`/`false`、`yes`/`no`、`y`/`n`、`t`/`f`、`on`/`off`、`enable`/`disable`、`enabled`/`disabled` —— 也被接受，但建议使用 `1` 和 `0`。

<Tabs>

<Tab title="Python">

无效值会在启动时报错，拼写错误会大声失败而不是静默回退。

</Tab>

<Tab title="TypeScript">

无效值会记录日志 `Ignoring invalid value for <NAME>` 并回退到该设置的默认值。

</Tab>

</Tabs>

## General Settings

这些是控制 `deepeval` 行为、文件路径和运行标识符的核心设置。

| 变量                         | 取值                     | 作用                                                                                                                                                        |
| ---------------------------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CONFIDENT_API_KEY`          | `string` / 未设置           | 登录 Confident AI。启用追踪可观测性，并在评估完成时自动把测试结果上传到云端。                     |
| `CONFIDENT_REGION`           | <Tabs><Tab title="Python">`US` / `EU` / 未设置</Tab><Tab title="TypeScript">`US` / `EU` / `AU` / 未设置</Tab></Tabs> | Confident AI 数据区域。未设置时，区域会从你的 API key 前缀推断。                                                                        |
| `CONFIDENT_BASE_URL`         | `string` / 未设置           | Confident AI API 服务器的基础 URL（仅在使用自定义或自托管端点时设置）。优先级高于 `CONFIDENT_REGION`。                    |
| `CONFIDENT_DISABLE_SSL`      | `1` / `0` / 未设置          | 禁用对 Confident AI API 服务器请求的 TLS 证书校验。仅用于带自签名证书的自托管端点。     |
| `CONFIDENT_OPEN_BROWSER`     | `1` / `0` / 未设置          | 为 Confident AI 链接和流程自动打开浏览器。默认开启；在 CI 和无头机器上设为 `0`。                                           |
| `DEEPEVAL_DISABLE_DOTENV`    | `1` / `0` / 未设置          | 禁用导入时的 dotenv 自动加载。在 CI 中避免加载本地 `.env*` 文件时很有用。                                                                         |
| `ENV_DIR_PATH`               | `path` / 未设置             | 包含 `.env` 文件的目录（默认为当前工作目录）。                                                                                |
| `APP_ENV`                    | `string` / 未设置           | 设置后会在 `.env` 和 `.env.local` 之间加载 `.env.{APP_ENV}`。                                                                                             |
| `DEEPEVAL_DEFAULT_SAVE`      | `dotenv[:path]` / 未设置    | 省略 `--save` 时 `deepeval set-* --save` 的默认持久化目标。                                     |
| `DEEPEVAL_FILE_SYSTEM`       | `READ_ONLY` / 未设置        | 阻止 `deepeval` 写自己的文件：keystore、dotenv 持久化、指标缓存、最新测试运行以及结果导出。                       |
| `DEEPEVAL_RESULTS_FOLDER`    | `path` / 未设置             | 把最新测试运行的时间戳 JSON 导出到该目录（按需创建）。                                                                     |
| `DEEPEVAL_VOICE_FOLDER`      | `path` / 未设置             | 语音模拟写入对话音频的目录（按需创建）。默认为 `.deepeval-voice-simulations`。                                |
| `DEEPEVAL_IDENTIFIER`        | `string` / 未设置           | 运行的默认标识符（与 `deepeval test run -id ...` 同一概念）。                                          |
| `IGNORE_DEEPEVAL_ERRORS`     | `1` / `0` / 未设置          | 指标出错时继续运行，而不是让测试用例失败。                                                                                        |
| `SKIP_DEEPEVAL_MISSING_PARAMS` | `1` / `0` / 未设置        | 当测试用例缺少指标所需参数时跳过该指标。                                                                                          |
| `ENABLE_DEEPEVAL_CACHE`      | `1` / `0` / 未设置          | 对未变化的测试用例和配置复用缓存的指标结果。                                                                                      |

`DEEPEVAL_FILE_SYSTEM` 也接受 `READ-ONLY`、`READONLY` 和 `RO`。其他任何值都会被拒绝。

## Retries

<Tabs>

<Tab title="Python">

这些设置控制 LLM 提供商调用的重试与退避。

| 变量                        | 类型           | 默认值 | 说明                                                                                        |
| ------------------------------- | -------------- | ------- | ---------------------------------------------------------------------------------------------- |
| `DEEPEVAL_RETRY_MAX_ATTEMPTS`   | `int`          | `2`     | 总尝试次数，即默认重试一次。                                                 |
| `DEEPEVAL_RETRY_INITIAL_SECONDS` | `float`       | `1.0`   | 初始退避。                                                                             |
| `DEEPEVAL_RETRY_EXP_BASE`       | `float`        | `2.0`   | 指数底数（≥ 1）。                                                                      |
| `DEEPEVAL_RETRY_JITTER`         | `float`        | `2.0`   | 每次重试附加的随机抖动（秒）。                                                   |
| `DEEPEVAL_RETRY_CAP_SECONDS`    | `float`        | `5.0`   | 重试之间的最长休眠。`0` 完全禁用退避休眠。                             |
| `DEEPEVAL_SDK_RETRY_PROVIDERS`  | `list` / 未设置 | 未设置   | 其重试改为委托给提供商 SDK 管理的提供商标识。支持 `["*"]`。    |

</Tab>

<Tab title="TypeScript">

`deepeval` 不会在 LLM 调用外再包一层自己的重试。重试由各提供商的 SDK 处理，因此请在你传入的客户端上配置——`openai` 和 `@anthropic-ai/sdk` 客户端默认带各自退避策略重试两次。

```typescript
import OpenAI from "openai";

const client = new OpenAI({ maxRetries: 5 });
```

对 Confident AI API 的请求会在瞬时网络错误时自动重试。该行为不可配置。

</Tab>

</Tabs>

## Timeouts / Concurrency

这些选项让你为并行执行和提供商调用调整超时上限与并发。

| 变量                                        | 取值             | 作用                                                                                      |
| ----------------------------------------------- | ------------------ | ------------------------------------------------------------------------------------------- |
| `DEEPEVAL_DISABLE_TIMEOUTS`                     | `1` / `0` / 未设置  | 禁用 `deepeval` 强制超时（单次尝试、单任务、gather）。                       |
| `DEEPEVAL_PER_ATTEMPT_TIMEOUT_SECONDS_OVERRIDE` | `float` / 未设置    | 提供商调用的单次尝试超时覆盖（首选覆盖键）。                   |
| `DEEPEVAL_PER_TASK_TIMEOUT_SECONDS_OVERRIDE`    | `float` / 未设置    | 指标/测试用例的外层超时预算覆盖（首选覆盖键）。              |
| `DEEPEVAL_TASK_GATHER_BUFFER_SECONDS_OVERRIDE`  | `float` / 未设置    | 任务完成后为 gather/清空追加的缓冲时间覆盖。                      |
| `DEEPEVAL_MAX_CONCURRENT_DOC_PROCESSING`        | `int`              | 并发文档处理任务上限（默认：2）。                                      |
| `DEEPEVAL_TIMEOUT_THREAD_LIMIT`                 | `int`              | 超时机制使用的最大线程数（默认：128）。                                       |
| `DEEPEVAL_TIMEOUT_SEMAPHORE_WARN_AFTER_SECONDS` | `float`            | 获取超时信号量耗时过长时告警（默认：5.0）。                          |
| `DEEPEVAL_PER_ATTEMPT_TIMEOUT_SECONDS`          | `float`（计算值） | 只读计算值。要覆盖请设置 `DEEPEVAL_PER_ATTEMPT_TIMEOUT_SECONDS_OVERRIDE`。 |
| `DEEPEVAL_PER_TASK_TIMEOUT_SECONDS`             | `float`（计算值） | 只读计算值。要覆盖请设置 `DEEPEVAL_PER_TASK_TIMEOUT_SECONDS_OVERRIDE`。    |
| `DEEPEVAL_TASK_GATHER_BUFFER_SECONDS`           | `float`（计算值） | 只读计算值。要覆盖请设置 `DEEPEVAL_TASK_GATHER_BUFFER_SECONDS_OVERRIDE`。  |

## Model Settings

你可以通过设置一组环境变量（API key、模型名称、提供商开关等）来配置模型提供商。不过我们推荐改用 [CLI 命令](/docs/command-line-interface#model-provider-configs)，它们会替你设置这些变量。

<Info>

例如，运行：

<Tabs>

<Tab title="Python">

```bash
deepeval set-openai --model=gpt-4o
```

</Tab>

<Tab title="TypeScript">

```bash
npx deepeval set-openai --model=gpt-4o
```

</Tab>

</Tabs>

会自动设置 `OPENAI_API_KEY`、`OPENAI_MODEL_NAME` 和 `USE_OPENAI_MODEL=1`。

</Info>

Explicit constructor arguments (e.g. `OpenAIModel(api_key=...)`（TypeScript 中为 `new OpenAIModel({ apiKey: ... })`）) always take precedence over environment variables. Token costs resolve in the same order: the constructor argument first, then the provider's `*_COST_PER_*_TOKEN` variable, then `deepeval`'s built-in price for that model.

你还可以设置 `TEMPERATURE`，为所有模型实例提供默认温度。

| 变量                  | 取值            | 作用                                                                                                                                                          |
| ------------------------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DEEPEVAL_MODEL_THINKING` | `1` / `0` / 未设置 | 让支持 thinking 参数的模型在回答前先思考。思考**默认禁用**，这样评审模型会把整个 token 预算花在结论上。 |

除非设置 `DEEPEVAL_MODEL_THINKING=1`，否则思考是关闭的，没有 thinking 参数的模型会忽略它。启用后默认输出预算会调大，为推理腾出空间，因为提供商把思考 token 与响应计入同一个 `max_tokens` 上限——显式设置的值仍然优先，如果小到装不下两者会报错而不是返回被截断的结论。

始终思考的模型（例如 `claude-fable-5`）无法关闭，无论开关如何都会推理。

### Variable Options

设为 `1` 时，`USE_{PROVIDER}_MODEL`（例如 `USE_OPENAI_MODEL`）告诉 `deepeval` 在没有显式传入模型时，LLM-as-a-judge 指标使用哪个提供商。

每个提供商还有自己的一组变量，用于 API key、模型名称和其他专属选项。展开下面各节查看每个提供商的完整列表。

<Warning>
**请记住**，不要手动摆弄这些变量，它们只应用于调试目的。请改用 CLI，`deepeval` 会替你管理这些变量。
</Warning>

<summary>Speech models (TTS/STT)</summary>

| 变量               | 取值            | 作用                                                                                     |

| `USE_OPENAI_STT`       | `1` / `0` / 未设置 | 语音转文本优先使用 OpenAI。                                                          |
| `USE_ELEVENLABS_STT`   | `1` / `0` / 未设置 | 语音转文本优先使用 ElevenLabs。                                                      |
| `USE_CARTESIA_STT`     | `1` / `0` / 未设置 | 语音转文本优先使用 Cartesia。                                                        |
| `USE_DEEPGRAM_STT`     | `1` / `0` / 未设置 | 语音转文本优先使用 Deepgram。                                                        |

| `DEEPEVAL_STT_MODEL`   | `string` / 未设置  | 所选 STT 提供商的模型名称（默认为该提供商自己的默认模型）。  |
