主题遵循（topic adherence）指标是一个多轮智能体指标，评估你的**智能体是否只回答符合相关主题的问题**。它是会自我解释的评估，会输出指标分数的理由。

## Required Arguments

要使用 `TopicAdherenceMetric`，你需要在创建 [`ConversationalTestCase`](https://www.deepeval.com/docs/evaluation-multiturn-test-cases) 时提供以下参数：

- `turns`

其计算方式的更多信息见[这里](#how-is-it-calculated)。

## Usage

`TopicAdherenceMetric()` 可用于智能体的[端到端](/docs/evaluation-end-to-end-llm-evals)多轮评估：

<Tabs>

<Tab title="Python">

```python
from deepeval.test_case import Turn, ConversationalTestCase, ToolCall
from deepeval.metrics import TopicAdherenceMetric
from deepeval import evaluate

convo_test_case = ConversationalTestCase(
    turns=[
        Turn(role="...", content="..."), 
        Turn(role="...", content="...", tools_called=[...])
    ],
)
metric = TopicAdherenceMetric(threshold=0.5)

# To run metric as a standalone
# metric.measure(convo_test_case)
# print(metric.score, metric.reason)

evaluate(test_cases=[convo_test_case], metrics=[metric])
```

</Tab>

<Tab title="TypeScript">

```typescript
import { Turn, ConversationalTestCase, ToolCall } from "deepeval/test-case";
import { TopicAdherenceMetric } from "deepeval/metrics";
import { evaluate } from "deepeval";

const convoTestCase = new ConversationalTestCase({
  turns: [
    new Turn({ role: "user", content: "..." }),
    new Turn({ role: "assistant", content: "...", toolsCalled: [new ToolCall({ name: "..." })] }),
  ],
});
const metric = new TopicAdherenceMetric({ relevantTopics: ["..."], threshold: 0.5 });

// To run metric as a standalone
// await metric.measure(convoTestCase);
// console.log(metric.score, metric.reason);

await evaluate([convoTestCase], [metric]);
```

- `relevant_topics`：字符串列表，定义你的 LLM 智能体可以回答哪些主题。任何偏离这些主题的回答都会惩罚该指标的分数。
- [Optional] `threshold`: a number representing the minimum passing threshold. Can also be set to `None`（TypeScript 中为 `null`） to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [可选] `model`：字符串，指定使用 OpenAI 的哪款 GPT 模型，**或**类型为 `DeepEvalBaseLLM` 的[任意自定义 LLM 模型](/docs/metrics-introduction#using-a-custom-llm)。默认为 `gpt-5.4`。
- [可选] `include_reason`：布尔值，设为 `True`（TypeScript 中为 `true`）时，会为评估分数附带理由。默认为 `True`（TypeScript 中为 `true`）。
- [可选] `strict_mode`：布尔值，设为 `True`（TypeScript 中为 `true`）时，把指标分数强制为二元：完美为 1，否则为 0。它还会覆盖当前阈值并将其设为 1。默认为 `False`（TypeScript 中为 `false`）。
- [可选] `async_mode`：布尔值，设为 `True` 时，启用[`measure()` 方法内的并发执行](/docs/metrics-introduction#measuring-a-metric-in-async)。默认为 `True`。
  
- [可选] `verbose_mode`：布尔值，设为 `True`（TypeScript 中为 `true`）时，把计算该指标所用的中间步骤打印到控制台，具体见 [How Is It Calculated](#how-is-it-calculated) 一节。默认为 `False`（TypeScript 中为 `false`）。
- [可选] `flaky`：布尔值，设为 `True`（TypeScript 中为 `true`）时，[把指标标记为 flaky](/docs/metrics-introduction#flaky-metrics)。默认为 `False`（TypeScript 中为 `false`）。

## How Is It Calculated

`TopicAdherenceMetric` 的分数通过以下流程计算：

- 从整段对话中找出问答对：问题来自用户，回答来自 LLM 智能体。
- 为所有问答对求出真值表取值。
- **真阳性**：问题相关且回答正确。
- **真阴性**：问题不相关，助手正确拒绝回答。
- **假阳性**：问题不相关，但助手仍然作答。
- **假阴性**：问题相关，但助手拒绝回答或给出了无关的回复。

随后，指标使用以下公式计算最终分数：

$$
\text{Topic Adherence Score} = \frac{\text{Number of True Positives and True Negatives}}{\text{Total Number of QA Pairs}}
$$

`TopicAdherenceMetric` 把轮次转成独立的单元交互，并逐个交互分别找出问答对，同时分别评估每对以获得更准确的结果。

## FAQs

<AccordionGroup>
<Accordion title="How do I stop my support bot from drifting off-topic?">
在 `relevant_topics` 中定义允许的主题并运行 `TopicAdherenceMetric`。任何回答主题之外问题的轮次都会被惩罚，精确定位机器人跑偏的位置。
</Accordion>
<Accordion title="How are off-topic turns actually scored?">
每个用户问题与智能体的回答配对：回答离题问题是*假阳性*（坏），拒绝回答是*真阴性*（好）。分数是真阳性与真阴性占全部问答对的比例。
</Accordion>
<Accordion title="Will my agent be penalized for refusing irrelevant questions?">
不会——拒绝 `relevant_topics` 之外的问题是真阴性，反而*有助*分数。只有回答离题问题、或拒绝相关问题时才会被惩罚。
</Accordion>
<Accordion title="What should I put in relevant topics?">
一组字符串，描述你的智能体覆盖的主题领域（例如 `"billing"` 或 `"shipping"`）。保持具体，但别窄到把合理的问题也标记出来。
</Accordion>
</AccordionGroup>
