## 创建你的第一次测试运行

创建一个测试文件，来运行你的第一次**端到端评估**。

<Tabs>
<Tab title="单轮">

`deepeval` 中的 [LLM 测试用例](/docs/evaluation-test-cases#llm-test-case)表示**单次 LLM 应用交互单元**，包含 `input` 和 `actual_output`（LLM 生成的输出）等必填字段，以及 `expected_output` 等可选字段。

![LLM 测试用例](https://deepeval-docs.s3.amazonaws.com/docs:llm-test-case.png)

在终端运行 `touch test_example.py`（TypeScript 中为 `touch example.test.ts`），并粘贴以下代码：

<Tabs>

<Tab title="Python">

```python title="test_example.py"
from deepeval import assert_test
from deepeval.test_case import LLMTestCase, SingleTurnParams
from deepeval.metrics import GEval

def test_correctness():
    correctness_metric = GEval(
        name="Correctness",
        criteria="Determine if the 'actual output' is correct based on the 'expected output'.",
        evaluation_params=[SingleTurnParams.ACTUAL_OUTPUT, SingleTurnParams.EXPECTED_OUTPUT],
        threshold=0.5
    )
    test_case = LLMTestCase(
        input="I have a persistent cough and fever. Should I be worried?",
        # Replace this with the actual output from your LLM application
        actual_output="A persistent cough and fever could be a viral infection or something more serious. See a doctor if symptoms worsen or don't improve in a few days.",
        expected_output="A persistent cough and fever could indicate a range of illnesses, from a mild viral infection to more serious conditions like pneumonia or COVID-19. You should seek medical attention if your symptoms worsen, persist for more than a few days, or are accompanied by difficulty breathing, chest pain, or other concerning signs."
    )
    assert_test(test_case, [correctness_metric])
```

</Tab>

<Tab title="TypeScript">

```typescript title="example.test.ts"
import { it, expect } from "vitest";
import { LLMTestCase, SingleTurnParams } from "deepeval/test-case";
import { GEval } from "deepeval/metrics";
import "deepeval/vitest";

it("gives medically sound advice", async () => {
  const correctnessMetric = new GEval({
    name: "Correctness",
    criteria:
      "Determine if the 'actual output' is correct based on the 'expected output'.",
    evaluationParams: [
      SingleTurnParams.ACTUAL_OUTPUT,
      SingleTurnParams.EXPECTED_OUTPUT,
    ],
    threshold: 0.5,
  });
  const testCase = new LLMTestCase({
    input: "I have a persistent cough and fever. Should I be worried?",
    // Replace this with the actual output from your LLM application
    actualOutput:
      "A persistent cough and fever could be a viral infection or something more serious. See a doctor if symptoms worsen or don't improve in a few days.",
    expectedOutput:
      "A persistent cough and fever could indicate a range of illnesses, from a mild viral infection to more serious conditions like pneumonia or COVID-19. You should seek medical attention if your symptoms worsen, persist for more than a few days, or are accompanied by difficulty breathing, chest pain, or other concerning signs.",
  });
  await expect(testCase).toPass([correctnessMetric]);
});
```

导入 `deepeval/vitest` 会注册 `toPass()` 匹配器。`npx deepeval test run` 会自动注入它，因此只有当你直接用 `vitest` 运行同一文件时这个导入才有意义。

</Tabs>

<Tabs>

<Tab title="Python">


</Tab>

<Tab title="TypeScript">


</Tab>

</Tabs>

恭喜！你的测试用例应该已经通过 ✅ 我们来分解一下发生了什么。

- 变量 `input` 模拟用户输入，`actual_output` 是你的应用基于该输入应当输出的内容的占位。
- 变量 `expected_output` 表示给定 `input` 的理想答案；[`GEval`](/docs/metrics-llm-evals) 是 `deepeval` 提供的、有研究支撑的指标，让你以类人准确度按任意自定义标准评估 LLM 输出。
- 在本例中，指标 `criteria` 是基于给定 `expected_output` 的 `actual_output` 正确性，但并非所有指标都需要 `expected_output`。
- 所有指标分数范围都是 0 - 1，`threshold=0.5`（TypeScript 中为 `threshold: 0.5`）阈值最终决定你的测试是否通过。

如果你运行了不止一次测试运行，就能通过并排比较测试用例来**发现回归**。如果把 `deepeval` 与 Confident AI 搭配使用会更容易（[见下文](/docs/getting-started#save-results)视频演示）。

</Tab>
<Tab title="多轮">

`deepeval` 中的[对话式测试用例](/docs/evaluation-multiturn-test-cases#conversational-test-case)表示**与 LLM 应用的一次多轮交互**，包含以 `turn` 形式组织的实际对话内容，以及可选的对话场景。

![对话式测试用例](https://deepeval-docs.s3.amazonaws.com/docs:conversational-test-case.png)

在终端运行 `touch test_example.py`（TypeScript 中为 `touch example.test.ts`），并粘贴以下代码：

<Tabs>

<Tab title="Python">

```python title="test_example.py"
from deepeval import assert_test
from deepeval.test_case import Turn, ConversationalTestCase
from deepeval.metrics import ConversationalGEval

def test_professionalism():
    professionalism_metric = ConversationalGEval(
        name="Professionalism",
        criteria="Determine whether the assistant has acted professionally based on the content.",
        threshold=0.5
    )
    test_case = ConversationalTestCase(
        turns=[
            Turn(role="user", content="What is DeepEval?"),
            Turn(role="assistant", content="DeepEval is an open-source LLM eval package.")
        ]
    )
    assert_test(test_case, [professionalism_metric])
```

</Tab>

<Tab title="TypeScript">

```typescript title="example.test.ts"
import { it, expect } from "vitest";
import {
  ConversationalTestCase,
  MultiTurnParams,
  Turn,
} from "deepeval/test-case";
import { ConversationalGEval } from "deepeval/metrics";
import "deepeval/vitest";

it("stays professional across the conversation", async () => {
  const professionalismMetric = new ConversationalGEval({
    name: "Professionalism",
    criteria:
      "Determine whether the assistant has acted professionally based on the content.",
    evaluationParams: [MultiTurnParams.CONTENT],
    threshold: 0.5,
  });
  const testCase = new ConversationalTestCase({
    turns: [
      new Turn({ role: "user", content: "What is DeepEval?" }),
      new Turn({
        role: "assistant",
        content: "DeepEval is an open-source LLM eval package.",
      }),
    ],
  });
  await expect(testCase).toPass([professionalismMetric]);
});
```

<details>

<summary>评估"卡住"了？</summary>

最可能是你的评估 LLM 出了问题，原因可能是速率限制或配额不足。

<Tabs>

<Tab title="Python">

默认情况下，`deepeval` 会对**瞬时** LLM 错误重试一次（共尝试 2 次）：

- **会重试：**网络/超时错误与 **5xx** 服务器错误。
- **速率限制（429）：**会重试，除非提供商标记为不可重试
  （对 OpenAI 而言，`insufficient_quota` 被视为不可重试）。
- **退避：**带抖动的指数退避（初始 **1s**，基数 **2**，抖动 **2s**，上限 **5s**）。

你可以通过环境开关调整这些行为（无需改代码）。详见[环境变量](/docs/environment-variables)。

</Tab>

<Tab title="TypeScript">

`deepeval` 不会在 LLM 调用外再包一层重试——重试由各提供商的 SDK 处理，因此请在你传入的客户端上配置：

```typescript
import OpenAI from "openai";

const client = new OpenAI({ maxRetries: 5 });
```

其余可调项见[环境变量](/docs/environment-variables)。

</Tab>

</Tabs>

</details>

## 评估 AI 智能体

AI 智能体在产出结果之前往往要经历许多步骤。要评估智能体是否完成了任务以及它是如何完成的，先用 [LLM 追踪](/docs/evaluation-llm-tracing)对它做埋点，再对它的完整轨迹打分。

<Steps>
<Step>

### 构建数据集

为你的智能体创建一个由代表性任务组成的小数据集：

<Tabs>

<Tab title="Python">

```python

```

</Tab>

<Tab title="TypeScript">

```typescript

  goldens: [new Golden({ input: "Plan a three-day trip to Paris" })],
```

</Tabs>

</Step>

### 埋点并评估轨迹

每个示例都会对智能体做埋点，为每个金标（golden）捕获一条完整追踪，并把 `TaskCompletionMetric` 应用到整条轨迹。

</Tab>

<Tab title="TypeScript">

<Tab title="手动埋点">

用 `@observe` 包装顶层函数，并调用 `update_current_trace(...)` 设置追踪级测试用例字段：

<Tabs>
<Tab title="Async">

```python title="main.py" showLineNumbers
import asyncio
from deepeval.tracing import observe, update_current_trace
from deepeval.metrics import TaskCompletionMetric
...

@observe()
async def my_ai_agent(query: str) -> str:
    answer = "..."  # await your LLM call here
    update_current_trace(input=query, output=answer)
    return answer

for golden in dataset.evals_iterator(metrics=[TaskCompletionMetric()]):
    task = asyncio.create_task(my_ai_agent(golden.input))
    dataset.evaluate(task)
```

</Tab>
<Tab title="Sync">

```python title="main.py" showLineNumbers

@observe()
```

用 `create_agent` 构建你的智能体，然后在循环中把 `deepeval` 的 `CallbackHandler` 传给它的 `invoke` / `ainvoke` 方法：

<Tabs>
<Tab title="Async">

```python title="langchain_app.py" showLineNumbers
import asyncio
from langchain.agents import create_agent
from deepeval.integrations.langchain import CallbackHandler
from deepeval.metrics import TaskCompletionMetric
...

def multiply(a: int, b: int) -> int:
    """Multiply two numbers."""
    return a * b

agent = create_agent(
    model="openai:gpt-4o-mini",
    tools=[multiply],
    system_prompt="Be concise.",
)

async def run_agent(prompt: str):
    return await agent.ainvoke(
        {"messages": [{"role": "user", "content": prompt}]},
        config={"callbacks": [CallbackHandler()]},
    )

for golden in dataset.evals_iterator(metrics=[TaskCompletionMetric()]):
    task = asyncio.create_task(run_agent(golden.input))
    dataset.evaluate(task)
```

<Tab title="LangGraph">

接好你的 `StateGraph`，然后在循环中把 `deepeval` 的 `CallbackHandler` 传给它的 `invoke` / `ainvoke` 方法：

<Tabs>
<Tab title="Async">

```python title="langgraph_app.py" showLineNumbers
import asyncio
from langchain.chat_models import init_chat_model
from langgraph.graph import StateGraph, MessagesState, START, END
from deepeval.integrations.langchain import CallbackHandler
from deepeval.metrics import TaskCompletionMetric
...

llm = init_chat_model("openai:gpt-4o-mini")

async def chatbot(state: MessagesState):
    return {"messages": [await llm.ainvoke(state["messages"])]}

graph = (
    StateGraph(MessagesState)
    .add_node(chatbot)
    .add_edge(START, "chatbot")
    .add_edge("chatbot", END)
    .compile()
)

async def run_graph(prompt: str):
    return await graph.ainvoke(
        {"messages": [{"role": "user", "content": prompt}]},
        config={"callbacks": [CallbackHandler()]},
    )

for golden in dataset.evals_iterator(metrics=[TaskCompletionMetric()]):
    task = asyncio.create_task(run_graph(golden.input))
    dataset.evaluate(task)
```

</Tab>
<Tab title="Sync">

```python title="langgraph_app.py" showLineNumbers

```

### 评估单个组件

基于轨迹的评估告诉你完整路径是否有效。[组件级评估](/docs/evaluation-component-level-llm-evals)用同一条追踪逐个对 span 打分，帮你定位是哪个规划器、检索器、工具调用、LLM 生成或子智能体造成了失败。

![智能体追踪中挂在单个 span 上的组件级指标](https://deepeval-docs.s3.us-east-1.amazonaws.com/component-level-evals.png)

智能体被追踪后，只把组件指标挂到你需要诊断的 span 上。轨迹分数与组件分数可以在同一次测试运行中一起产出。针对具体技术栈的示例、子智能体评估、检索器打分与 span 自定义，见[组件级指南](/docs/evaluation-component-level-llm-evals)。

</Step>
</Steps>

要在测试套件中运行轨迹评估，在断言中调用被追踪的智能体并传入轨迹指标。挂在其 span 上的组件指标会在同一次测试中运行：

<Tabs>

<Tab title="Python">

```python title="test_agent.py"
from deepeval.metrics import TaskCompletionMetric
from deepeval.dataset import Golden
from deepeval import assert_test
from agent import my_agent
import pytest

goldens = [Golden(input="Plan a three-day trip to Paris")]

@pytest.mark.parametrize("golden", goldens)
def test_agent(golden: Golden):
    my_agent(golden.input)
    assert_test(golden=golden, metrics=[TaskCompletionMetric()])
```

</Tab>

<Tab title="TypeScript">

```typescript title="agent.test.ts"
import { TaskCompletionMetric } from "deepeval/metrics";
import { Golden } from "deepeval/dataset";
import { myAgent } from "./agent";
import { expect, it } from "vitest";
import "deepeval/vitest";

const goldens = [new Golden({ input: "Plan a three-day trip to Paris" })];

it.each(goldens)("completes the agent trajectory #%$", async (golden) => {
  await expect(golden).toPass([new TaskCompletionMetric()], {
    task: (g) => myAgent(g.input),
  });
});
```

</Tab>

</Tabs>

无论哪种方式，都用 `deepeval test run` 像运行其他测试文件一样运行它。

<Tip>
每次 `evals_iterator()` 运行都会快照到磁盘，因此运行 `deepeval inspect` 即可在追踪树 TUI 中查看它——包含轨迹分数、每个 span 的分数与指标原因。完整细节见 [`deepeval inspect` 参考](/docs/command-line-interface#inspect)。

![deepeval inspect TUI 显示带每个 Span 分数与指标原因的追踪树](https://deepeval-docs.s3.us-east-1.amazonaws.com/docs:tui-trace-inspect.png)

</Tip>

## DeepEval 在线评估

使用 `deepeval` 做 LLM 追踪时，你可以自动运行在线评估，监控**生产环境中的追踪、Span 与线程（对话）**。

你需要使用 Confident AI 来提供所需的后端基础设施与仪表盘。

只需从 Confident AI 获取一个 [API key](https://app.confident-ai.com)，并在 CLI 中设置：

```bash
CONFIDENT_API_KEY="confident_us..."
```

然后向你的追踪添加一个「指标集合」（metric collection）：

<Tabs>

<Tab title="Python">

```python
from deepeval.tracing import observe, update_current_trace

@observe()
def ai_agent(input: str) -> str:
    output = "Your AI agent output"
    update_current_trace(metric_collection="My Online Evals",)
    return output
```

</Tab>

<Tab title="TypeScript">

```typescript
import { observe, updateCurrentTrace } from "deepeval/tracing";

const aiAgent = observe({
  type: "agent",
  fn: async (input: string): Promise<string> => {
    const output = "Your AI agent output";
    updateCurrentTrace({ metricCollection: "My Online Evals" });
    return output;
  },
});
```

</Tab>

</Tabs>

✅ 完成。你的 AI 智能体的所有调用现在都会运行在线评估。

<Tip>
想进一步了解什么是「指标集合」，以及如何把可观测性与在线评估配对，请查看 [Confident AI 文档](https://www.confident-ai.com/docs/llm-tracing/quickstart)。
</Tip>

`deepeval` 的 LLM 追踪实现是**非侵入的**，不会影响你代码的任何部分。

## FAQs

<AccordionGroup>
<Accordion title="为什么我的评估卡住了？">
大多数 LLM-as-a-judge 指标会调用一个评估模型。如果提供商被限速、配额不足或响应缓慢，评估可能看起来卡住了。请检查你的模型提供商密钥、配额与网络访问。
</Accordion>
<Accordion title="这个快速上手需要 Confident AI 吗？">
不需要。DeepEval 在本地运行。Confident AI 是可选的，当你想要共享报告、回归追踪、可观测性或生产监控时才有用。
</Accordion>
<Accordion title="这个测试文件应该放在哪里？">
放在你的测试运行器能发现的地方即可，通常与你的应用放在一起，或放在 `tests/` 文件夹里。然后运行 `deepeval test run path/to/test_file.py`（TypeScript 中为 `npx deepeval test run path/to/file.test.ts`）。
</Accordion>
<Accordion title="可以用 OpenAI 以外的模型吗？">
可以。DeepEval 支持多种模型提供商以及自定义/本地模型做评估。OpenAI 只是许多示例中最快的默认路径。
</Accordion>
<Accordion title="读完之后该看什么？">
如果你在评估智能体，从追踪开始。如果想要构建可复现的评估套件，从数据集与指标开始。
</Accordion>
</AccordionGroup>
