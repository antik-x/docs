title: Introduction to Synthetic Data Generation

当你还没有足够有代表性的示例时，合成数据生成可以帮你启动评估数据集，但它应该是对真实数据的补充——而不是替代。

<Warning>
合成数据很容易被滥用，因为它唾手可得。重要的是克制使用，而不是生成一堆你永远不会再看第二眼的 golden。
</Warning>

## Recommended Priority

最好的评估数据集扎根于真实的产品行为。我们建议按以下顺序选择数据来源：

1. **使用经过认真整理的数据集。** 如果有人工审核过的示例，从这里开始，尤其是反映重要用户旅程、失败和边界情况的示例。
2. **使用生产流量。** 如果没有整理好的数据集，就从生产环境中采样真实对话或请求，评估前先审阅和清理。
3. **使用合成数据。** 如果整理好的数据和生产数据都不够，就生成合成示例来建立初始覆盖并暴露明显的回归。

<Tip>
[Confident AI](https://www.confident-ai.com) 把"追踪 → 标注 → 数据集"的循环自动化，让你的团队可以把真实生产行为变成经过整理的评估数据。你只需用 `deepeval` 摄入追踪数据，然后审阅并把合适的样本提升进数据集。
</Tip>

合成数据最大的价值是让你更快获得起点。对于高风险的工作流，在把生成的示例当作真值之前，仍然应当审阅、编辑和充实它们。

## Best Practices On Synthetic Data Quality

并非所有合成数据都同样可靠。在完全开放式的生成之前，优先使用扎根且经过审阅的来源：

1. **从文档生成。** 这是最强的默认选择，因为生成的 golden 扎根于你的知识库。
2. **从既有 golden 生成。** 当种子 golden 已经经过认真整理和人工审核时，这种方式效果很好。
3. **从零生成。** 这是扎根程度最低的选项，除非用例简单或你只需要粗略的初始覆盖，否则不推荐。

## What You Can Synthesize

`deepeval` 支持两个相关的合成数据工作流：

- **生成 golden：** 使用 [Golden Synthesizer](/docs/golden-synthesizer) 为你的评估数据集创建单轮或会话式 golden。
- **模拟轮次：** 使用 [Conversation Simulator](/docs/conversation-simulator) 在模拟用户与你的聊天机器人之间生成真实的多轮往复对话。

### Generate Goldens

Golden 定义你要测试什么。它们可以是常规 LLM 交互的单轮示例，也可以是定义多轮场景和期望结果的会话式 golden。

```python
from deepeval.synthesizer import Synthesizer

synthesizer = Synthesizer()
goldens = synthesizer.generate_goldens_from_docs(
    document_paths=["support_docs.md"],
    include_expected_output=True,
)
```

对于多轮用例，改为生成会话式 golden：

```python
from deepeval.synthesizer import Synthesizer

synthesizer = Synthesizer()
conversational_goldens = synthesizer.generate_conversational_goldens_from_docs(
    document_paths=["support_docs.md"],
    include_expected_outcome=True,
)
```

更多信息见 [Golden Synthesizer](/docs/golden-synthesizer) 文档。

### Simulate Turns

轮次模拟只适用于多轮用例。它紧随 golden 生成之后：先创建带场景和期望结果的会话式 golden，再用 Conversation Simulator 产出实际的多轮往复对话。

```python
from deepeval.simulator import ConversationSimulator

simulator = ConversationSimulator(model_callback=model_callback)
test_cases = simulator.simulate(
    conversational_goldens=conversational_goldens,
    max_user_simulations=10,
)
```

更多信息见 [Conversation Simulator](/docs/conversation-simulator) 文档。

对于单轮用例，生成的 golden 通常就够用了。对于多轮用例，通常两者都需要：先用 Golden Synthesizer 定义场景和期望结果，再用 Conversation Simulator 生成实际的对话轮次用于评估。

## FAQs

<AccordionGroup>
<Accordion title="When should I use synthetic data?">
克制使用，作为缺少真实示例时的起点——它应该补充而非替代真实数据。优先用整理好的数据集，其次生产流量，最后才是合成生成。
</Accordion>
<Accordion title="What's the best source to generate goldens from?">
[从文档生成](/docs/synthesizer-generate-from-docs)是最强的默认选择，因为 golden 扎根于你的知识库；其次是[既有 golden](/docs/synthesizer-generate-from-goldens) 。[从零生成](/docs/synthesizer-generate-from-scratch)扎根程度最低——只用于简单场景或粗略覆盖。
</Accordion>
<Accordion title="How do I generate data for multi-turn chatbots?">
先生成会话式 golden（例如 `generate_conversational_goldens_from_docs` ）来定义场景和期望结果，再把它们交给 [Conversation Simulator](/docs/conversation-simulator) 产出实际的对话轮次。
</Accordion>
<Accordion title="Do I need to review generated goldens?">
需要。对任何高风险的内容，在把生成的 golden 当作真值之前都要审阅、编辑和充实——不要生成一堆你永远不会再看一眼的 golden。
</Accordion>
<Accordion title="Can I use any model to generate synthetic data?">
可以。`model` 参数按名称接受 OpenAI 的任意 GPT 模型，或 `DeepEvalBaseLLM` 类型的[任意自定义 LLM](/docs/metrics-introduction#using-a-custom-llm)（Anthropic、Gemini、Ollama、本地模型等）。若未显式设置，它还会被复用为过滤阶段的 `critic_model`。
</Accordion>
<Accordion title="How do I turn production traffic into evaluation datasets?">
用 `deepeval` 摄入追踪数据，然后在 [Confident AI](https://www.confident-ai.com)（集评估、可观测性和红队测试于一体的企业平台，自动完成追踪 → 标注 → 数据集的循环）上审阅并把最佳样本提升进数据集。
</Accordion>
<Accordion title="Can my team generate synthetic data without code?">
可以。在 [Confident AI](https://www.confident-ai.com) 上你可以无代码生成 golden——连接知识库，定制生成流水线，试验不同变体，并与团队协作处理产生的数据集。
</Accordion>
</AccordionGroup>
