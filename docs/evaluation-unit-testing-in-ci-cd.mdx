sidebarTitle: "CI/CD 中的单元测试"
---

Integrate LLM evaluations into your CI/CD pipeline with `deepeval` to catch regressions before they ship. `deepeval` plugs into `pytest`（TypeScript 中为 `vitest`） via `assert_test()`（TypeScript 中为 `expect(testCase).toPass()`） and the `deepeval test run` command, so every push (or every PR) runs the same evals you'd run locally — single-turn or multi-turn, end-to-end or component-level.

## 工作原理

无论你运行哪种风格的评估，CI/CD 中的单元测试都是同样的三步：

1. **加载数据集** —— 从 Confident AI、CSV 或 JSON 文件拉取金标。这一步对所有风格完全一致。
2. **Construct test cases & write your test** — this is where the flavor matters. End-to-end vs component-level, single-turn vs multi-turn, and (for single-turn) instrumented vs un-instrumented all change what you put inside the `pytest`（TypeScript 中为 `vitest`） test.
3. **运行你的测试文件** —— 对所有风格都是同一条命令。可原样放进 `.yml` 文件。

`deepeval`'s `pytest`（TypeScript 中为 `vitest`） integration allows you to leverage all of its flags and functionalities, as well as capabilities offered by `deepeval`, which you can learn more about below.

<Tip>
If you haven't already, we recommend reading the end-to-end and component-level guides first to understand what we're doing — `deepeval`'s `pytest`（TypeScript 中为 `vitest`） integration mirrors those workflows, just inside a test file:

- [单轮端到端评估](/docs/evaluation-end-to-end-single-turn)
- [多轮端到端评估](/docs/evaluation-end-to-end-multi-turn)
- [组件级评估](/docs/evaluation-component-level-llm-evals)（仅单轮）
</Tip>

### 构建测试用例

选择与你的应用匹配的风格——[单轮](/docs/evaluation-end-to-end-single-turn)（一个输入 → 一个输出）或[多轮](/docs/evaluation-end-to-end-multi-turn)（整段对话）。

<Tabs>

<Tab title="单轮">

在单轮之内，我们强烈建议**为你的应用做追踪埋点**，这样 `deepeval` 就能从每次运行自动构建 `LLMTestCase`，并且你可以在 Confident AI 上免费获得每个测试用例的完整追踪。

同样的设置还解锁[组件级评估](/docs/evaluation-component-level-llm-evals)——指标挂到单个 span（检索器、工具调用、子智能体）上，而不是整条追踪上。

**带评估的埋点/追踪**

下面每个示例都是完整的、带埋点的 `deepeval test run` 文件：

<Tab title="手动埋点">

```python title="test_llm_app.py" showLineNumbers
import pytest
from deepeval import assert_test
from deepeval.dataset import EvaluationDataset, Golden
from deepeval.metrics import TaskCompletionMetric
from deepeval.tracing import observe, update_current_trace

# 1. Load your dataset of goldens
dataset = EvaluationDataset(goldens=[Golden(input="What is pi rounded to 2 decimal places?")])

# 2. Instrument your agent
@observe()
def my_ai_agent(query: str) -> str:
    answer = "Pi rounded to 2 decimal places is 3.14."
    update_current_trace(input=query, output=answer)
    return answer

# 3. Evaluate end-to-end on each golden
@pytest.mark.parametrize("golden", dataset.goldens)
def test_llm_app(golden: Golden):
    my_ai_agent(golden.input)
    assert_test(golden=golden, metrics=[TaskCompletionMetric()])
```

用 `@observe` 包装智能体的顶层函数，并用 `update_current_trace(...)` 设置追踪级测试用例字段。完整用法见 [LLM 追踪](/docs/evaluation-llm-tracing)。

```python title="test_langgraph_app.py" showLineNumbers
import pytest
from langchain.chat_models import init_chat_model
from langgraph.graph import StateGraph, MessagesState, START, END
from deepeval import assert_test
from deepeval.integrations.langchain import CallbackHandler
from deepeval.dataset import EvaluationDataset, Golden
from deepeval.metrics import TaskCompletionMetric

# 1. Load your dataset of goldens
dataset = EvaluationDataset(goldens=[Golden(input="What is pi rounded to 2 decimal places?")])

# 2. Instrument your agent
llm = init_chat_model("openai:gpt-4o-mini")

def chatbot(state: MessagesState):
    return {"messages": [llm.invoke(state["messages"])]}

graph = (
    StateGraph(MessagesState)
    .add_node(chatbot)
    .add_edge(START, "chatbot")
    .add_edge("chatbot", END)
    .compile()
)

# 3. Evaluate end-to-end on each golden
@pytest.mark.parametrize("golden", dataset.goldens)
def test_langgraph_app(golden: Golden):
    graph.invoke(
        {"messages": [{"role": "user", "content": golden.input}]},
        config={"callbacks": [CallbackHandler()]},
    )
    assert_test(golden=golden, metrics=[TaskCompletionMetric()])
```

把 `deepeval` 的 `CallbackHandler` 传给你的 `StateGraph` 的 `invoke` 方法。完整用法见 [LangGraph 集成](/integrations/frameworks/langgraph)。

```python title="test_google_adk_app.py" showLineNumbers
import asyncio
import pytest
from google.adk.agents import LlmAgent
from google.adk.runners import InMemoryRunner
from google.genai import types
from deepeval import assert_test
from deepeval.integrations.google_adk import instrument_google_adk
from deepeval.dataset import EvaluationDataset, Golden
from deepeval.metrics import TaskCompletionMetric

# 1. Load your dataset of goldens
dataset = EvaluationDataset(goldens=[Golden(input="What is pi rounded to 2 decimal places?")])

# 2. Instrument your agent
instrument_google_adk()

agent = LlmAgent(model="gemini-2.0-flash", name="assistant", instruction="Answer math questions concisely.")
runner = InMemoryRunner(agent=agent, app_name="deepeval-google-adk")

async def run_agent(prompt: str) -> str:
    session = await runner.session_service.create_session(app_name="deepeval-google-adk", user_id="demo-user")
    message = types.Content(role="user", parts=[types.Part(text=prompt)])
    async for event in runner.run_async(user_id="demo-user", session_id=session.id, new_message=message):
        if event.is_final_response() and event.content:
            return "".join(part.text for part in event.content.parts if getattr(part, "text", None))
    return ""

# 3. Evaluate end-to-end on each golden
@pytest.mark.parametrize("golden", dataset.goldens)
def test_google_adk_app(golden: Golden):
    asyncio.run(run_agent(golden.input))
    assert_test(golden=golden, metrics=[TaskCompletionMetric()])
```

<Tab title="手动埋点">

```typescript title="llm-app.test.ts" showLineNumbers
import { it, expect } from "vitest";
import { EvaluationDataset, Golden } from "deepeval/dataset";
import { TaskCompletionMetric } from "deepeval/metrics";
import { observe, updateCurrentTrace } from "deepeval/tracing";
import "deepeval/vitest";

// 1. Load your dataset of goldens
const dataset = new EvaluationDataset({
  goldens: [new Golden({ input: "What is pi rounded to 2 decimal places?" })],
});

// 2. Instrument your agent
const myAiAgent = observe({
  type: "agent",
  fn: async (query: string): Promise<string> => {
    const answer = "Pi rounded to 2 decimal places is 3.14.";
    updateCurrentTrace({ input: query, output: answer });
    return answer;
  },
});

// 3. Evaluate end-to-end on each golden
it.each(dataset.goldens as Golden[])(
  "completes the task #%$",
  async (golden) => {
    await expect(golden).toPass([new TaskCompletionMetric()], {
      task: (g) => myAiAgent(g.input),
    });
  },
);
```

用 `observe` 包装智能体的顶层函数，并用 `updateCurrentTrace(...)` 设置追踪级测试用例字段。完整用法见 [LLM 追踪](/docs/evaluation-llm-tracing)。

<Tip>

**走向组件级**

Once your app is instrumented, you can attach metrics directly to individual `@observe`（TypeScript 中为 `observe()`）'d (or framework-emitted) spans to grade internal components — retrievers, tool calls, sub-agents — alongside the end-to-end trace.

每个集成的指标挂载方式见[组件级评估](/docs/evaluation-component-level-llm-evals)；追踪级与 span 级指标可以共存于同一次测试运行。
</Tip>

**无追踪**

Use this when you can't (or don't want to) instrument your app — e.g. a QA engineer evaluating a deployed black-box system. You build the `LLMTestCase` yourself inside the test and hand it to `assert_test()`（TypeScript 中为 `expect(testCase).toPass()`） directly. No tracing is involved, so you don't get per-test-case traces in CI.

```python title="test_llm_app.py" showLineNumbers
import pytest
from deepeval import assert_test
from deepeval.dataset import EvaluationDataset, Golden
from deepeval.test_case import LLMTestCase
from deepeval.metrics import AnswerRelevancyMetric

def your_llm_app(query: str) -> str:
    return "Pi rounded to 2 decimal places is 3.14."

@pytest.mark.parametrize("golden", dataset.goldens)
def test_llm_app(golden: Golden):

        input=golden.input,
        actual_output=answer,
    )
```

## 处理 Flaky 测试用例

LLM 评估是非确定性的，有些测试用例会恰好落在某个指标的阈值上，在多次运行之间于通过与失败之间来回摆动。与其把它们从套件中删除，不如把它们标记为 flaky：

<Tabs>

<Tab title="Python">

```python
from deepeval.test_case import LLMTestCase

test_case = LLMTestCase(flaky=True, ...)
```

</Tab>

<Tab title="TypeScript">

```typescript
import { LLMTestCase } from "deepeval/test-case";

const testCase = new LLMTestCase({ flaky: true, ... });
```

</Tab>

</Tabs>

当 flaky 测试用例失败时，<Tabs><Tab title="Python">`assert_test()` 会打印警告而不是抛出 `AssertionError`</Tab><Tab title="TypeScript">`expect(testCase).toPass()` 会打印警告而不是让测试失败</Tab></Tabs>，因此你的 CI 流水线继续运行，同时失败仍被记录在测试运行结果中。`LLMTestCase` 与 `ConversationalTestCase` 都支持 `flaky` 参数。

You can also mark individual **metrics** as flaky (`AnswerRelevancyMetric(flaky=True)`（TypeScript 中为 `new AnswerRelevancyMetric({ flaky: true })`）) — a flaky metric's score and verdict are still reported, but its failure never fails the test case it ran on.

## 用于 CI/CD 评估的 YAML 文件

把 `deepeval test run` 放进 `.yml`，即可在每次推送或 PR 时运行你的单元测试。本例使用 `OPENAI_API_KEY` 作为 LLM 裁判在本地运行评估。添加 `CONFIDENT_API_KEY` 可把结果发送到 Confident AI。

<Tabs>

<Tab title="Python">

```yaml {32-33}
name: LLM App `deepeval` Tests

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Code
        uses: actions/checkout@v2

      - name: Set up Python
        uses: actions/setup-python@v4
        with:
          python-version: "3.10"

      - name: Install Poetry
        run: |
          curl -sSL https://install.python-poetry.org | python3 -
          echo "$HOME/.local/bin" >> $GITHUB_PATH

      - name: Install Dependencies
        run: poetry install --no-root

      - name: Run `deepeval` Unit Tests
        env:
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
          CONFIDENT_API_KEY: ${{ secrets.CONFIDENT_API_KEY }}
        run: poetry run deepeval test run test_llm_app.py
```

</Tab>

<Tab title="TypeScript">

```yaml {24-25}

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

    steps:

      - name: Set up Node

          node-version: "20"
```

## 标记正式运行

你可以把某次测试运行指定为 Confident AI 上的**正式**测试运行——即被标记的优质运行，后续运行会与之比较以发现回归。添加 `--official` 开关（或 `-o`）在运行完成后进行标记：

<Tabs>

<Tab title="Python">

```bash
deepeval test run test_llm_app.py --official
```

</Tab>

<Tab title="TypeScript">

```bash
npx deepeval test run llm_app.test.ts --official
```

</Tab>

</Tabs>

If you evaluate with `evaluate()` rather than `deepeval test run`, pass `official=True`（TypeScript 中为 `official: true`） instead:

<Tabs>

<Tab title="Python">

```python
from deepeval import evaluate

evaluate(test_cases=[...], metrics=[...], official=True)
```

</Tab>

<Tab title="TypeScript">

```typescript
import { evaluate } from "deepeval";

await evaluate([...], [...], { official: true });
```

</Tab>

</Tabs>

这通常在主分支上进行，这样每个基线都反映已合并、可上生产的代码。

<Note>
把运行标记为正式运行需要 `CONFIDENT_API_KEY`，因为正式运行保存在 Confident AI 上。
</Note>

## FAQs

<AccordionGroup>
<Accordion title="How does deepeval fit into CI/CD?">
你把评估写成你所使用测试运行器中的测试，并用 `deepeval test run` 命令作为流水线中的一个步骤来运行它们。失败的指标会让构建失败，回归在上线前就会被发现。
</Accordion>
<Accordion title="What's the difference between unit testing and evaluate()?">
单元测试是为 CI/CD 设计的：当指标低于阈值时断言失败，构建变红。而 `evaluate()` 面向脚本与笔记本，只收集结果而不让任何东西失败。把关请用单元测试。
</Accordion>
<Accordion title="Do I need a Confident AI account to run evals in CI/CD?">
不需要。提供一个 LLM 裁判密钥（如 `OPENAI_API_KEY`），你的测试就完全在本地运行。添加 `CONFIDENT_API_KEY` 是可选的，只是把结果发送到云端。
</Accordion>
<Accordion title="Which CI providers does this work with?">
任何能执行 shell 步骤的提供商都可以。文档展示的是 GitHub Actions 的 `.yml`，但同一条 `deepeval test run` 命令在 GitLab CI、CircleCI、Jenkins 等环境中同样可用。
</Accordion>
<Accordion title="How do I speed up or control test runs in CI?">
使用 `deepeval test run` 的并行化、缓存、忽略错误等开关。完整列表见[开关与配置](/docs/evaluation-flags-and-configs#flags-for-deepeval-test-run)。
</Accordion>
<Accordion title="Can my team see professional test reports on the cloud and track results over time?">
可以——而且是可选的。把 `CONFIDENT_API_KEY` 加入你的 CI 密钥，同一条 `deepeval test run` 就会把结果发送到 [Confident AI](https://app.confident-ai.com)（`deepeval` 团队的平台），为你的团队提供可分享的测试报告、检查失败用例的界面，以及跨提交的性能趋势线。没有该密钥，完全相同的测试依然在本地运行。
</Accordion>
</AccordionGroup>
