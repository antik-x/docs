title: Step Efficiency

**标签**：LLM-as-a-judge · 单轮 · 轨迹 · 无参考 · 智能体 · 多模态

步骤效率（step efficiency）指标是一个智能体指标，它从智能体的追踪中抽取任务，并评估智能体为完成该任务所走**执行步骤的效率**。它是会自我解释的评估，会输出指标分数的理由。

<Info>
步骤效率会分析你**智能体的完整追踪**来判断任务与执行效率，因此需要[设置追踪](/docs/evaluation-llm-tracing)。
</Info>

## Usage

To begin, [set up tracing](/docs/evaluation-llm-tracing) and simply supply the `StepEfficiencyMetric()` to your agent's `@observe` tag or in the `evals_iterator` method.

<Tabs>

<Tab title="Python">

```python
from somewhere import llm
from deepeval.tracing import observe, update_current_trace
from deepeval.dataset import Golden, EvaluationDataset
from deepeval.metrics import StepEfficiencyMetric
from deepeval.test_case import ToolCall


@observe
def tool_call(input):
    ...
    return [ToolCall(name="CheckWeather")]

@observe
def agent(input):
    tools = tool_call(input)
    output = llm(input, tools)
    update_current_trace(
        input=input,
        output=output,
        tools_called=tools
    )
    return output


# Create dataset
dataset = EvaluationDataset(goldens=[Golden(input="What's the weather like in SF?")])

# Initialize metric
metric = StepEfficiencyMetric(threshold=0.7, model="gpt-4o")

# Loop through dataset
for golden in dataset.evals_iterator(metrics=[metric]):
    agent(golden.input)
```

</Tab>

<Tab title="TypeScript">

```typescript
import { observe, updateCurrentTrace } from "deepeval/tracing";
import { Golden, EvaluationDataset } from "deepeval/dataset";
import { StepEfficiencyMetric } from "deepeval/metrics";
import { ToolCall } from "deepeval/test-case";
import { llm } from "./somewhere";

const toolCall = observe({
  type: "tool",
  fn: async (input: string) => {
    // ...
    return [new ToolCall({ name: "CheckWeather" })];
  },
});

const agent = observe({
  type: "agent",
  fn: async (input: string) => {
    const tools = await toolCall(input);
    const output = await llm(input, tools);
    updateCurrentTrace({
      input,
      output,
      toolsCalled: tools,
    });
    return output;
  },
});

// Create dataset
const dataset = new EvaluationDataset({
  goldens: [new Golden({ input: "What's the weather like in SF?" })],
});

// Initialize metric
const metric = new StepEfficiencyMetric({ threshold: 0.7, model: "gpt-4o" });

// Loop through dataset
for await (const golden of dataset.evalsIterator({ metrics: [metric] })) {
  await agent((golden as Golden).input);
}
```

- [Optional] `threshold`: a number representing the minimum passing threshold. Can also be set to `None`（TypeScript 中为 `null`） to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [可选] `model`：字符串，指定使用 OpenAI 的哪款 GPT 模型，**或**类型为 `DeepEvalBaseLLM` 的[任意自定义 LLM 模型](/docs/metrics-introduction#using-a-custom-llm)。默认为 `gpt-5.4`。
- [可选] `include_reason`：布尔值，设为 `True`（TypeScript 中为 `true`）时，会为评估分数附带理由。默认为 `True`（TypeScript 中为 `true`）。
- [可选] `strict_mode`：布尔值，设为 `True`（TypeScript 中为 `true`）时，把指标分数强制为二元：完美为 1，否则为 0。它还会覆盖当前阈值并将其设为 1。默认为 `False`（TypeScript 中为 `false`）。
- [可选] `async_mode`：布尔值，设为 `True` 时，启用[`measure()` 方法内的并发执行](/docs/metrics-introduction#measuring-a-metric-in-async)。默认为 `True`。
  
- [可选] `verbose_mode`：布尔值，设为 `True`（TypeScript 中为 `true`）时，把计算该指标所用的中间步骤打印到控制台，具体见 [How Is It Calculated](#how-is-it-calculated) 一节。默认为 `False`（TypeScript 中为 `false`）。
- [可选] `flaky`：布尔值，设为 `True`（TypeScript 中为 `true`）时，[把指标标记为 flaky](/docs/metrics-introduction#flaky-metrics)。默认为 `False`（TypeScript 中为 `false`）。

关于 `evals_iterator` 工作方式的更多内容，[点击这里](/docs/evaluation-end-to-end-llm-evals#e2e-evals-for-tracing)。

<Info>
`StepEfficiencyMetric` 是只能用于追踪的智能体指标，因此与其他 `deepeval` 指标不同，它不能独立使用，**必须**在 `evals_iterator` 或 `observe` 装饰器中使用。
</Info>

## How Is It Calculated?

`StepEfficiencyMetric` 的分数按以下步骤计算：

- 从追踪中抽取**任务**，它定义了用户对智能体的目标或意图，并且是可执行的。
- 评估追踪中的**智能体执行步骤**，看智能体完成任务的效率如何。

$$
\text{Step Efficiency Score} = \text{AlignmentScore}(\text{Task}, \text{Execution Steps})
$$

- **对齐分数**由 LLM 结合计划、执行步骤等所有预处理与抽取的信息生成最终分数。它会惩罚 LLM 智能体为完成任务而采取的并非严格必要的行动。

## FAQs

<AccordionGroup>
<Accordion title="How do I detect my agent taking unnecessary or redundant steps?">
这正是步骤效率的用途。它为抽取出的**任务**与**执行步骤**之间的 `AlignmentScore` 打分，惩罚一切并非严格必要的行动——重复、重试、绕路。设置 `include_reason` 可查看被标记的步骤。
</Accordion>
<Accordion title="Why can't I run Step Efficiency on a single test case?">
效率只有对整次运行才有意义，因此它只能用于追踪。你**必须**把 `StepEfficiencyMetric()` 挂到一条追踪上——通过[设置追踪](/docs/evaluation-llm-tracing)或通过 LangChain、OpenAI 等[框架集成](/integrations)。
</Accordion>
<Accordion title="Step Efficiency vs Task Completion — doesn't an efficient agent always finish the task?">
Not necessarily. [Task Completion](/docs/metrics-task-completion) asks if the **outcome** was achieved; Step Efficiency asks if the **path** was lean. An agent can finish via a bloated route or take a tight path that misses the goal — run both.
</Accordion>
<Accordion title="Do I define the task for Step Efficiency?">
不需要——**任务**会自动从追踪中抽取，然后针对它为执行步骤打分。它是无参考的，没有需要标注的预期路径。
</Accordion>
<Accordion title="Can I use Step Efficiency with LangChain, OpenAI, or another framework?">
可以。`deepeval` 会自动追踪用 [LangChain](/integrations/frameworks/langchain)、[OpenAI](/integrations/frameworks/openai)、LlamaIndex、CrewAI 等构建的智能体——全部[框架集成](/integrations)见相应页面。
</Accordion>
</AccordionGroup>
