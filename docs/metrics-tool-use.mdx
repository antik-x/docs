**标签**：LLM-as-a-judge · 多轮 · 无参考 · 智能体 · 多模态

工具使用（tool use）指标是一个多轮智能体指标，评估你的 LLM 智能体的**工具选择与参数生成**能力。它是会自我解释的评估，会输出指标分数的理由。

## Required Arguments

要使用 `ToolUseMetric`，你需要在创建 [`ConversationalTestCase`](https://www.deepeval.com/docs/evaluation-multiturn-test-cases) 时提供以下参数：

- `turns`

其计算方式的更多信息见[这里](#how-is-it-calculated)。

## Usage

`ToolUseMetric()` 可用于智能体的[端到端](/docs/evaluation-end-to-end-llm-evals)多轮评估：

<Tabs>

<Tab title="Python">

```python
from deepeval.test_case import Turn, ConversationalTestCase, ToolCall
from deepeval.metrics import ToolUseMetric
from deepeval import evaluate

convo_test_case = ConversationalTestCase(
    turns=[
        Turn(role="...", content="..."), 
        Turn(role="...", content="...", tools_called=[...])
    ],
)
metric = ToolUseMetric(threshold=0.5)

# To run metric as a standalone
# metric.measure(convo_test_case)
# print(metric.score, metric.reason)

evaluate(test_cases=[convo_test_case], metrics=[metric])
```

</Tab>

<Tab title="TypeScript">

```typescript
import { Turn, ConversationalTestCase, ToolCall } from "deepeval/test-case";
import { ToolUseMetric } from "deepeval/metrics";
import { evaluate } from "deepeval";

const convoTestCase = new ConversationalTestCase({
  turns: [
    new Turn({ role: "user", content: "..." }),
    new Turn({ role: "assistant", content: "...", toolsCalled: [new ToolCall({ name: "..." })] }),
  ],
});
const metric = new ToolUseMetric({
  availableTools: [new ToolCall({ name: "...", description: "..." })],
  threshold: 0.5,
});

// To run metric as a standalone
// await metric.measure(convoTestCase);
// console.log(metric.score, metric.reason);

await evaluate([convoTestCase], [metric]);
```

</Tab>

</Tabs>

- `available_tools`：`ToolCall` 列表，提供你的 LLM 智能体可用的全部工具的上下文。该列表用于评估智能体的工具选择能力。
- [Optional] `threshold`: a number representing the minimum passing threshold. Can also be set to `None`（TypeScript 中为 `null`） to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [可选] `model`：字符串，指定使用 OpenAI 的哪款 GPT 模型，**或**类型为 `DeepEvalBaseLLM` 的[任意自定义 LLM 模型](/docs/metrics-introduction#using-a-custom-llm)。默认为 `gpt-5.4`。
- [Optional] `include_reason`: a boolean which when set to `True`（TypeScript 中为 `true`）, will include a reason for its evaluation score. Defaulted to `True`（TypeScript 中为 `true`）.
- [Optional] `strict_mode`: a boolean which when set to `True`（TypeScript 中为 `true`）, enforces a binary metric score: 1 for perfection, 0 otherwise. It also overrides the current threshold and sets it to 1. Defaulted to `False`（TypeScript 中为 `false`）.
[可选] `async_mode`：布尔值，设为 `True` 时，启用[`measure()` 方法内的并发执行](/docs/metrics-introduction#measuring-a-metric-in-async)。默认为 `True`。
  
- [Optional] `verbose_mode`: a boolean which when set to `True`（TypeScript 中为 `true`）, prints the intermediate steps used to calculate said metric to the console, as outlined in the [How Is It Calculated](#how-is-it-calculated) section. Defaulted to `False`（TypeScript 中为 `false`）.
- [Optional] `flaky`: a boolean which when set to `True`（TypeScript 中为 `true`）, [marks the metric as flaky](/docs/metrics-introduction#flaky-metrics). Defaulted to `False`（TypeScript 中为 `false`）.

## How Is It Calculated

`ToolUseMetric` 的分数通过以下流程确定：

1. 为每个单元交互计算**工具选择分数**。
2. 为所有包含工具调用的单元交互计算**参数正确性分数**。

$$
\text{Tool Use Score} = \min(\text{ToolSelectionScore}, \text{ArgumentCorrectnessScore})
$$

- **工具选择分数**评估智能体是否在所有可用工具中为任务选择了最合适的工具。
- **参数正确性分数**评估工具调用中提供的参数是否准确、是否适合该任务。只有发生工具调用时才计入该分数。

## FAQs

<AccordionGroup>
<Accordion title="How do I check whether my agent called the right tools across a conversation?">
`ToolUseMetric` 会评估每次交互的工具选择与传入的参数，同时标出「选错工具」和「工具对但参数错」的轮次。
</Accordion>
<Accordion title="Why do I have to pass available tools if the agent already called tools?">
`available_tools` is the full menu of `ToolCall` s the agent could have used. Without the alternatives, the metric can't tell whether a better tool existed or whether a tool should have been called at all.
</Accordion>
<Accordion title="My agent picked the right tool but with wrong arguments — does that fail?">
会。最终分数是 `min(ToolSelectionScore, ArgumentCorrectnessScore)`，因此完美的工具选择配上糟糕的参数依然会拉低分数。参数分数只适用于发生工具调用的轮次。
</Accordion>
<Accordion title="Does it catch unnecessary or missing tool calls?">
两者都会损害**工具选择分数**：调用不需要的工具或漏掉需要的工具，都会被记为对照 `available_tools` 的糟糕选择。用 `verbose_mode` 可查看逐交互的推理。
</Accordion>
</AccordionGroup>
