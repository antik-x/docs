title: DeepEval 简介
---

**DeepEval** 是一个面向 LLM 应用的开源 LLM 评估框架。DeepEval 让 LLM（应用）的构建与迭代变得极其简单，其设计遵循以下原则：

- 用 Pytest 风格的断言对 LLM 输出做单元测试。
- 提供 50+ 开箱即用的指标，涵盖 LLM-as-a-judge、智能体、工具调用、对话、安全、RAG 与多模态等。
- 评估 AI 智能体、对话式智能体（聊天机器人）、RAG 流水线、MCP 系统及其他自定义工作流。
- 支持端到端评估、基于轨迹的评估与组件级评估。
- 为难以手工收集的边界场景合成数据集。
- 在内置行为不够用时，可自定义指标、提示词、模型与评估模板。

DeepEval 是本地优先的：评估在你自己的环境中运行。当团队需要共享仪表盘、回归追踪、可观测性或生产监控时，DeepEval 与 [Confident AI](https://www.confident-ai.com) 原生集成。

<Tip>

## DeepEval 适合谁？

DeepEval 为技术受众设计，以下是我们服务良好的主要人群：

- **AI 工程师**：需要评估智能体、RAG 流水线、工具调用与生产 LLM 工作流，为 AI 行为编写单元测试，并在 Claude Code、Codex 等智能体编码工具中使用评估。
- **数据科学家**：想要可复现的实验，用来比较提示词、模型、数据集与指标分数。
- **QA**：需要在变更触达用户之前，为 AI 行为建立可靠的回归测试。
- **懂技术的 PM**：想要定义质量标准、检查失败案例，并追踪产品变更是否改善了 AI 输出。

### 三种评估模式

DeepEval 支持三种互补的评估方式。选择与你要度量内容匹配的范围：

  <Card

  >
    <div className="pt-2">
      把 LLM 应用当作黑盒。提供输入、输出、预期行为与指标，然后用 DeepEval 检测质量回归。

  </Card>
  <Card
    icon="git-merge"

    href="/docs/evaluation-component-level-llm-evals"
  >
    <div className="pt-2">
      对应用做追踪，评估单个 Span、工具、规划器、检索器、生成器或其他内部组件。
    </div>
  </Card>
  <Card
    className="md:col-span-2"
    icon="workflow"
    title="基于轨迹的评估"
    description="最适合执行路径影响质量的 AI 智能体与长程智能体。"
    href="/docs/evaluation-trajectory-based-llm-evals"

三种模式可独立使用，也可组合使用：给黑盒结果打分、评估完整的智能体轨迹，再检查单个 Span 定位失败点。

## 常见问题

<AccordionGroup>
<Accordion title="DeepEval 是什么？">
DeepEval 是一个开源 LLM 评估框架。它让你可以对 LLM 输出做单元测试、运行端到端与组件级评估、生成合成数据集，并从 Python 把评估带进 CI/CD。
</Accordion>
<Accordion title="使用 DeepEval 需要注册账号吗？">
不需要。DeepEval 在本地运行。只有当指标使用 LLM 裁判时，你才需要 LLM 提供商的密钥（如 `OPENAI_API_KEY`）。只有想把结果发送到 Confident AI 时才需要账号。
</Accordion>
<Accordion title="DeepEval 能评估什么？">
AI 智能体、MCP 系统、聊天机器人、使用工具的工作流、LLM 竞技场、RAG 流水线、摘要器、结构化输出、多模态应用以及自定义 LLM 工作流。
</Accordion>
<Accordion title="DeepEval 与可观测性工具有何不同？">
可观测性工具帮你检查发生了什么；DeepEval 关注的是行为是否足够好——它对测试用例、追踪、Span 与数据集运行指标。两者可以搭配使用。
</Accordion>
<Accordion title="DeepEval 能在 CI/CD 中使用吗？">
可以。DeepEval 就是为配合 `pytest` 与 CI 提供商而构建的，你可以用 LLM 回归测试为变更把关。
</Accordion>
</AccordionGroup>
