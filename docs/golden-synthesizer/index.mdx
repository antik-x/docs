---
title: Golden Synthesizer
---

`deepeval` 的 `Synthesizer` 提供了一种快速简单的方法，只需几行代码即可为你的评估数据集生成高质量的**单轮和多轮 golden**。这在以下情况特别有帮助：

- 你还没有可用的评估数据集
- 你有一个小数据集，希望用更多示例来扩充它
- 你有一个知识库，想用它创建数据集

<Note>
对于单轮生成，请注意 `deepeval` 的 `Synthesizer` **不会**为每个 golden 生成 `actual_output`。这是因为 `actual_output` 应由你的 LLM（应用）生成，而不是 `deepeval` 的合成器。

对于多轮生成，`deepeval` 的 `Synthesizer` 也不生成 `turns`。你应该改用 [`ConversationSimulator`](/docs/conversation-simulator) 来模拟 `turns`。
</Note>

<details>
<summary>Should you generate synthetic datasets?</summary>

当你没有准备好的评估数据集时，合成评估数据尤其有帮助，因为它能**帮你生成启动评估所需的初始测试数据**。

不过，你应尽可能人工检查并编辑合成数据。

</details>

## Quick Summary

`Synthesizer` 使用 LLM 先生成一系列输入/场景，然后将其演化得更复杂、更真实。这些演化后的输入/场景随后被用来创建一组合成 golden，可以是单轮或多轮，构成你的合成 `EvaluationDataset`。

要开始生成 golden，粘贴以下代码：

<Tabs>
<Tab title="单轮">

```python title="main.py"
from deepeval.synthesizer import Synthesizer

synthesizer = Synthesizer()
goldens = synthesizer.generate_goldens_from_docs(
    document_paths=['example.txt'], # Replace with your file
    include_expected_output=True
)
print(goldens)
```

</Tab>
<Tab title="多轮">

```python title="main.py"
from deepeval.synthesizer import Synthesizer

synthesizer = Synthesizer()
conversational_goldens = synthesizer.generate_conversational_goldens_from_docs(
    document_paths=['example.txt'], # Replace with your file
    include_expected_outcome=True
)
print(conversational_goldens)
```

</Tab>
</Tabs>

```bash
python main.py
```

恭喜 🎉🥳！你刚刚生成了第一批合成 golden。

<Info>
`deepeval` 的 `Synthesizer` 使用数据演化方法跨多个复杂度级别生成大量数据，使合成数据更真实。该方法最初由 [Evol-Instruct 和 WizardML 的开发者](https://arxiv.org/abs/2304.12244)提出。

感兴趣的话，这里有一篇[关于 `deepeval` 合成器如何构建的好文章。](https://www.confident-ai.com/blog/the-definitive-guide-to-synthetic-data-generation-using-llms)
</Info>

## Create Your First Synthesizer

要开始为你的 `EvaluationDataset` 生成 golden，先创建一个 `Synthesizer` 对象：

```python
from deepeval.synthesizer import Synthesizer

synthesizer = Synthesizer()
```

创建 `Synthesizer` 时有**八个**可选参数：

- [可选] `async_mode`：布尔值，设为 `True` 时启用**并发生成 golden**。默认为 `True`。
- [可选] `model`：字符串，指定用于生成的 OpenAI GPT 模型，**或者** `DeepEvalBaseLLM` 类型的[任意自定义 LLM 模型](/docs/metrics-introduction#using-a-custom-llm)。默认为 `gpt-5.4`。
- [可选] `max_concurrent`：整数，决定任一时刻可并行生成的最大 golden 数。遇到限流错误时可以调低该值。默认为 `100`。
- [可选] `filtration_config`：`FiltrationConfig` 类型的实例，允许你[自定义生成期间 golden 被过滤的程度](#filtration-quality)。默认为默认的 `FiltrationConfig` 值。
- [可选] `evolution_config`：`EvolutionConfig` 类型的实例，允许你[自定义生成期间应用的演化复杂度](#evolution-complexity)。默认为默认的 `EvolutionConfig` 值。
- [可选] `styling_config`：`StylingConfig` 类型的实例，允许你[自定义**单轮**生成的样式和格式](#styling-options)。默认为默认的 `StylingConfig` 值。
- [可选] `conversational_styling_config`：`ConversationalStylingConfig` 类型的实例，允许你[自定义**多轮**生成的样式和格式](#styling-options)。默认为默认的 `ConversationalStylingConfig` 值。
- [可选] `cost_tracking`：布尔值，设为 `True` 时会打印 golden 合成期间你的 LLM 产生的成本。

<Note>
`filtration_config`、`evolution_config`、`styling_config` 和 `conversational_styling_config` 参数让你可以定制 `Synthesizer` 生成的 golden。

此外，**如果没有提供相应的自定义配置实例**，`Synthesizer` 的 `model` 会自动用作 [`FiltrationConfig`](#filtration-quality) 和 [`ContextConstructionConfig`](/docs/synthesizer-generate-from-docs#customize-context-construction) 的 `critic_model`。
</Note>

## Generate Your First Golden

创建好带有所需过滤参数和模型的 `Synthesizer` 对象后，就可以开始生成 golden 了。

<Tabs>
<Tab title="单轮">

```python
from deepeval.synthesizer import Synthesizer

synthesizer = Synthesizer()
goldens = synthesizer.generate_goldens_from_docs(
    document_paths=['example.txt', 'example.docx', 'example.pdf', 'example.md', 'example.markdown', 'example.mdx'],
    include_expected_output=True
)
print(goldens)
```

在这个示例中，我们使用了 `generate_goldens_from_docs` 和 `generate_conversational_goldens_from_docs` 方法，它们是 `deepeval` 的 `Synthesizer` 提供的四种生成方法中的两种。四种方法包括：

- [`generate_goldens_from_docs()`](/docs/synthesizer-generate-from-docs)：适合基于从知识库中以文档形式提取的上下文，生成评估你的 LLM 应用的金标。
- [`generate_goldens_from_contexts()`](/docs/synthesizer-generate-from-contexts)：适合基于一组准备好的上下文，生成评估你的 LLM 应用的金标。
- [`generate_goldens_from_scratch()`](/docs/synthesizer-generate-from-scratch)：适合不依赖知识库上下文，生成评估你的 LLM 应用的金标。
- [`generate_goldens_from_goldens()`](/docs/synthesizer-generate-from-goldens)：适合通过扩增一组已知金标来生成金标。

<Tip>
你可能注意到 `generate_goldens_from_docs()` 是 `generate_goldens_from_contexts()` 的超集，而 `generate_goldens_from_contexts()` 是 `generate_goldens_from_scratch()` 的超集。

这意味着如果你想对上下文提取有更多控制，应使用 `generate_goldens_from_contexts()`；如果你想让 `deepeval` 连上下文提取也一并处理，则使用 `generate_goldens_from_docs()`。
</Tip>

</Tab>
<Tab title="多轮">

```python
from deepeval.synthesizer import Synthesizer

synthesizer = Synthesizer()
conversational_goldens = synthesizer.generate_conversational_goldens_from_docs(
    document_paths=['example.txt', 'example.docx', 'example.pdf', 'example.md', 'example.markdown', 'example.mdx'],
    include_expected_outcome=True
)
print(conversational_goldens)
```

在这个示例中，我们使用了 `generate_goldens_from_docs` 和 `generate_conversational_goldens_from_docs` 方法，它们是 `deepeval` 的 `Synthesizer` 提供的四种生成方法中的两种。四种方法包括：

- [`generate_conversational_goldens_from_docs()`](/docs/synthesizer-generate-from-docs)：适合基于从知识库文档中提取的上下文生成 golden，用于评估你的 LLM 应用。
- [`generate_conversational_goldens_from_contexts()`](/docs/synthesizer-generate-from-contexts)：适合基于一组已准备好的上下文生成 golden，用于评估你的 LLM 应用。
- [`generate_conversational_goldens_from_scratch()`](/docs/synthesizer-generate-from-scratch)：适合不依赖知识库上下文生成 golden，用于评估你的 LLM 应用。
- [`generate_conversational_goldens_from_goldens()`](/docs/synthesizer-generate-from-goldens)：适合通过扩充一组已知 golden 来生成 golden。

<Tip>
你可能注意到 `generate_conversational_goldens_from_docs()` 是 `generate_conversational_goldens_from_contexts()` 的超集，而 `generate_conversational_goldens_from_contexts()` 是 `generate_conversational_goldens_from_scratch()` 的超集。

这意味着如果你想对上下文提取有更多控制，应使用 `generate_conversational_goldens_from_contexts()`；如果你想让 `deepeval` 连上下文提取也一并处理，则使用 `generate_conversational_goldens_from_docs()`。
</Tip>

## Save Your Synthetic Dataset

<Tabs>
<Tab title="Confident AI">

为避免丢失任何已生成的合成 `Golden`，你可以把包含这些 golden 的数据集推送到 Confident AI：

```python
from deepeval.dataset import EvaluationDataset
...

dataset = EvaluationDataset(goldens=synthesizer.synthetic_goldens)
dataset.push(alias="My Generated Dataset")
```

这样你的数据集就保存在云端，你可以在一处编辑它并做版本管理。当你准备好使用这些 golden 评估你的 LLM 应用时，只需像拉取 GitHub 仓库一样从云端拉取数据集：

```python
from deepeval import evaluate
from deepeval.dataset import EvaluationDataset
from deepeval.metrics import AnswerRelevancyMetric
...

dataset = EvaluationDataset()
# Same alias as before
dataset.pull(alias="My Generated Dataset")
evaluate(dataset, metrics=[AnswerRelevancyMetric()])
```

</Tab>
<Tab title="Locally">

你也可以使用 `save_as()` 方法把合成 golden 保存到本地：

```python
synthesizer.save_as(
    # Type of file to save ('json' or 'csv')
    file_type='json',
    # Directory where the file will be saved
    directory="./synthetic_data"
)
```

`save_as()` 方法支持以下参数：

- `file_type`：指定保存数据的格式（'json' 或 'csv'）
- `directory`：文件保存到的文件夹路径
- `file_name`：可选的自定义文件名（不含扩展名）——提供时文件将保存为 `{file_name}.{file_type}`
- `quiet`：可选布尔值，用于抑制关于保存位置的输出消息

默认情况下，该方法生成基于时间戳的文件名（例如 "20240523_152045.json"）。当你通过 `file_name` 参数提供自定义文件名时，该名称将作为基础文件名，扩展名按 `file_type` 参数添加。

例如，如果你指定 `file_type='json'` 和 `file_name='my_dataset'`，文件将保存为 "my_dataset.json"。

```python
# Save as JSON with a custom filename my_dataset.json
synthesizer.save_as(
    file_type='json',
    directory="./synthetic_data",
    file_name="my_dataset"
)

# Save as CSV with a custom filename my_dataset.csv
synthesizer.save_as(
    file_type='csv',
    directory="./synthetic_data",
    file_name="my_dataset"
)
```

<Warning>
注意 `file_name` 不应包含句点或文件扩展名，因为它们会根据 `file_type` 参数自动添加。
</Warning>

</Tab>
</Tabs>

## Customize Your Generations

`deepeval` 的 `Synthesizer` 生成流水线由多个组件组成，你可以轻松定制它们来决定最终生成的 golden 的质量和风格。

<Tip>
你可能想先[了解构成 `Synthesizer` 生成流水线的所有组件和步骤](#how-does-it-work)。
</Tip>

### Filtration Quality

你可以通过在实例化 `Synthesizer` 时传入 `FiltrationConfig` 实例，自定义生成 golden 被过滤掉的程度，以确保合成输入的质量。

```python
from deepeval.synthesizer import Synthesizer
from deepeval.synthesizer.config import FiltrationConfig

filtration_config = FiltrationConfig(
  critic_model="gpt-4.1",
  synthetic_input_quality_threshold=0.5
)

synthesizer = Synthesizer(filtration_config=filtration_config)
```

创建 `FiltrationConfig` 时有**三个**可选参数：

- [可选] `critic_model`：字符串，指定用于判定上下文 `quality_score` 的 OpenAI GPT 模型，**或者** `DeepEvalBaseLLM` 类型的[任意自定义 LLM 模型](/docs/metrics-introduction#using-a-custom-llm)。默认为 **`Synthesizer` 中使用的模型**；作为独立实例初始化时为 `gpt-5.4`。
- [可选] `synthetic_input_quality_threshold`：浮点数，表示合成输入生成的最低质量阈值。`quality_score` 低于 `synthetic_input_quality_threshold` 的输入将被拒绝。默认为 `0.5`。
- [可选] `max_quality_retries`：整数，指定合成输入未达到要求质量时的重试次数。默认为 `3`。

如果 `max_quality_retries` 次重试后 `quality_score` 仍低于 `synthetic_input_quality_threshold`，将使用 `quality_score` 最高的那个 golden。

### Evolution Complexity

你可以通过在实例化 `Synthesizer` 时传入 `EvolutionConfig` 实例来自定义应用的演化类型与深度。应通过定制 `EvolutionConfig` 来改变生成 golden 的复杂度。

```python
from deepeval.synthesizer import synthesizer
from deepeval.synthesizer.config import EvolutionConfig

evolution_config = EvolutionConfig(
    evolutions={
        Evolution.REASONING: 1/4,
        Evolution.MULTICONTEXT: 1/4,
        Evolution.CONCRETIZING: 1/4,
        Evolution.CONSTRAINED: 1/4
    },
    num_evolutions=4
)

synthesizer = Synthesizer(evolution_config=evolution_config)
```

创建 `EvolutionConfig` 时有**两个**可选参数：

- [可选] `evolutions`：以 `Evolution` 为键、采样概率为值的字典，指定要使用的数据演化分布。默认为所有 `Evolution` 等概率。
- [可选] `num_evolutions`：对每个生成的输入应用的演化步数。该参数通过迭代细化与演化初始输入，控制生成数据集的复杂度和多样性。默认为 1。

<Info>

`Evolution` 是一个 `ENUM`，指定你希望用来让合成 `Golden` 更真实的各种数据演化技术。`deepeval` 的 `Synthesizer` 支持 7 种演化，按定义的分布随机采样。你可以对每个 `Golden` 应用多次演化，稍后可通过 `Golden` 的附加元数据字段访问演化序列。

如果用于 RAG 评估：注意某些演化技术并不要求演化后的输入能从上下文中得到回答。目前只有这 4 种演化紧扣上下文：`Evolution.MULTICONTEXT`、`Evolution.CONCRETIZING`、`Evolution.CONSTRAINED` 和 `Evolution.COMPARATIVE`。

```python
from deepeval.synthesizer import Evolution

available_evolutions = {
    Evolution.REASONING: 1/7,
    Evolution.MULTICONTEXT: 1/7, # sticks to the context
    Evolution.CONCRETIZING: 1/7, # sticks to the context
    Evolution.CONSTRAINED: 1/7, # sticks to the context
    Evolution.COMPARATIVE: 1/7, # sticks to the context
    Evolution.HYPOTHETICAL: 1/7,
    Evolution.IN_BREADTH: 1/7,
}
```

</Info>

### Styling Options

你可以通过在实例化 `Synthesizer` 时传入 `StylingConfig` 实例（单轮生成）和/或 `ConversationalStylingConfig` 实例（多轮生成），自定义所生成 `input` 和/或 `expected_output` 的输出风格与格式。

<Tabs>
<Tab title="单轮">

```python
from deepeval.synthesizer import Synthesizer
from deepeval.synthesizer.config import StylingConfig

styling_config = StylingConfig(
  input_format="Questions in English that asks for data in database.",
  expected_output_format="SQL query based on the given input",
  task="Answering text-to-SQL-related queries by querying a database and returning the results to users",
  scenario="Non-technical users trying to query a database using plain English.",
)

synthesizer = Synthesizer(styling_config=styling_config)
```

创建 `StylingConfig` 时有**四个**可选参数：

- [可选] `input_format`：字符串，指定合成 golden 中所生成 `input` 的期望格式。默认为 `None`。
- [可选] `expected_output_format`：字符串，指定合成 golden 中所生成 `expected_output` 的期望格式。默认为 `None`。
- [可选] `task`：字符串，表示你要评估的 LLM 应用承担的用途。默认为 `None`。
- [可选] `scenario`：字符串，表示你要评估的 LLM 应用所处的场景。默认为 `None`。

`scenario`、`task`、`input_format` 和/或 `expected_output_format` 参数（如果提供）用于强制所有生成 golden 的样式和格式。

</Tab>
<Tab title="多轮">

```python
from deepeval.synthesizer import Synthesizer
from deepeval.synthesizer.config import ConversationalStylingConfig

conversational_styling_config = ConversationalStylingConfig(
  scenario_format="Questions in English that asks for data in database.",
  expected_outcome_format="SQL query based on the given input",
  conversational_task="Answering text-to-SQL-related queries by querying a database and returning the results to users",
  scenario_context="Non-technical users trying to query a database using plain English.",
  participant_roles="A customer support agent and a non-technical end user.",
)

synthesizer = Synthesizer(conversational_styling_config=conversational_styling_config)
```

创建 `ConversationalStylingConfig` 时有**五个**可选参数：

- [可选] `scenario_context`：字符串，表示你要评估的 LLM 应用所处的场景。默认为 `None`。
- [可选] `conversational_task`：字符串，表示你要评估的 LLM 应用承担的用途。默认为 `None`。
- [可选] `participant_roles`：字符串，描述对话中参与者的角色。默认为 `None`。
- [可选] `scenario_format`：字符串，指定所生成对话场景的期望格式。默认为 `None`。
- [可选] `expected_outcome_format`：字符串，指定合成 `ConversationalGolden` 中所生成 `expected_outcome` 的期望格式。默认为 `None`。

`scenario_context`、`conversational_task`、`participant_roles`、`scenario_format` 和/或 `expected_outcome_format` 参数（如果提供）用于强制所有生成会话 golden 的样式和格式。

</Tab>
</Tabs>

## How Does it Work?

`deepeval` 的 `Synthesizer` 生成流水线由四个主要步骤组成：

1. **输入生成**：在有无提供上下文的情况下生成合成 golden 的 `input`。
2. **过滤**：滤掉任何不符合指定生成标准的初始合成 golden。
3. **演化**：演化过滤后的合成 golden，提高复杂度并使其更真实。
4. **样式化**：为演化后的合成 golden 的 `input` 和 `expected_output` 设置输出格式样式。

该生成流水线对 `generate_goldens_from_docs()`、`generate_goldens_from_contexts()` 和 `generate_goldens_from_scratch()` 都相同。

<Tip>
还有两个步骤未提及——上下文构建步骤和期望输出生成步骤。

**上下文构建步骤**（[其工作原理见这里](synthesizer-generate-from-docs#how-does-context-construction-work)）发生在初始生成步骤之前；之所以没有提到它，是因为只有使用 `generate_goldens_from_docs()` 方法时才需要它。

至于**期望输出生成步骤**，它被省略是因为这只是紧挨最终样式化步骤之前发生的一个简单的一步过程。
</Tip>

### Input Generation

在初始的**输入生成**步骤中，使用 LLM 在有无提供上下文的情况下生成 golden 的 `input`。提供的上下文可以是字符串列表或文档列表的形式，使生成的 golden 扎根于你知识库中呈现的信息。

### Filtration

<Note>
这一步的位置可能让许多人意外，但过滤步骤之所以在流水线中这么早就发生，是因为 `deepeval` 假定通过初始过滤的 golden 在后续演化和样式化中不会劣化。
</Note>

在**过滤**步骤中，生成的 golden 的 `input` 要接受质量过滤。这些合成 `input` 由 LLM 依据以下标准评估并赋予质量分数（0-1）：

- **自包含性**：`input` 无需额外的外部上下文或引用即可被理解且完整。
- **清晰度**：`input` 清楚地传达其意图，无歧义地指明所请求的信息或操作。

质量分数低于 `synthetic_input_quality_threshold` 的 golden 都会重新生成。如果允许的 `max_quality_retries` 次重试后质量分数仍达不到要求的 `synthetic_input_quality_threshold`，则使用得分最高的那次生成。因此，最终评估数据集中某些生成的 `Golden` 可能达不到最低输入质量分数，但无论如何你都会保证至少得到一个 golden。

[点击这里](#filtration-quality)了解如何自定义 `synthetic_input_quality_threshold` 和 `max_quality_retries` 参数。

### Evolution

在**演化**步骤中，过滤后的 golden 的 `input` 会被重写得更复杂、更真实，常常与人工精心编写的 golden 难以区分。每个 `input` 被重写 `num_evolutions` 次，每次演化从 `evolution` 分布中采样，为重写后的 `input` 增加一层额外的复杂度。

[点击这里](#evolution-types-and-depth)了解如何自定义 `evolution` 和 `num_evolutions` 参数。

### Styling

<Tip>
例如，如果你想用另一种语言生成 golden，或希望 `expected_output` 是 SQL 格式（文本转 SQL 用例），这一步会很有用。

在最后的**样式化**步骤中，每个 golden 的 `input` 和 `expected_output` 会按需重写为期望的格式与风格。可以通过设置 `scenario`、`task`、`input_format` 和 `expected_output_format` 参数来配置，`deepeval` 会在生成流水线的末尾使用你提供的内容为 golden 定制样式，确保所有合成数据对你而言是合理的。

## FAQs

<AccordionGroup>
<Accordion title="Does the Synthesizer generate actual_outputs for my goldens?">
不会。`Synthesizer` 生成 `input` （以及可选的 `expected_output` ），而 `actual_output` 由你的 LLM 应用在评估时产出，而不是 `deepeval` 。
</Accordion>
<Accordion title="Can the Synthesizer generate multi-turn turns?">
不。多轮生成产出的 `ConversationalGolden` 不带 `turns` ——请使用 [ConversationSimulator](/docs/conversation-simulator) 来模拟实际的 `turns` 。
</Accordion>
<Accordion title="Which generate_goldens_from_* method should I use?">
`generate_goldens_from_docs` 是 [generate_goldens_from_contexts](/docs/synthesizer-generate-from-contexts) 的超集，后者又是 [generate_goldens_from_scratch](/docs/synthesizer-generate-from-scratch) 的超集。想让 `deepeval` 处理上下文提取就用 [generate_goldens_from_docs](/docs/synthesizer-generate-from-docs)，想要更多控制就用更低层的方法。
</Accordion>
<Accordion title="How do I control the quality, complexity, and style of goldens?">
实例化 `Synthesizer` 时传入 `FiltrationConfig`（输入质量阈值）、`EvolutionConfig`（通过演化控制复杂度）和 `StylingConfig`（任务、场景和输出格式）。
</Accordion>
<Accordion title="Can my team generate goldens without code?">
可以。在 [Confident AI](https://www.confident-ai.com) 上你可以连接知识库并无代码地运行生成流水线——调整过滤、演化和样式，试验不同变体，并与团队协作处理产生的数据集。
</Accordion>
</AccordionGroup>
