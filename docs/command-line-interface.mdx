## Quick Summary

`deepeval` 提供了一套 CLI，让你直接在终端管理常见任务。你可以用它：

- 登录/登出并查看测试运行
- 从测试文件运行评估
- 按治理策略检查项目（`deepeval gate`）
- 诊断你的环境（`deepeval diagnose`）：默认模型、生效设置以及每个值的来源
- 启用/禁用调试
- 选择 LLM 提供商（OpenAI、Azure OpenAI、Gemini、Grok、DeepSeek、OpenRouter、本地/Ollama）
- 设置/取消提供商专属选项（模型、端点、部署等）
- 列出并更新任意 deepeval 设置（`deepeval settings -l`、`deepeval settings --set KEY=VALUE`）
- 把设置和密钥持久化保存到 `.env` 文件
- 在终端 TUI 中检查已保存的测试运行（`deepeval inspect`）

- 从文档、上下文、零起点或既有 golden 生成合成 golden
- 选择嵌入提供商（Azure OpenAI、本地、Ollama）

<Tip>
要获取任何命令完整且最新的参数列表，请在命令后追加 `--help`。
</Tip>

## Read & Write Settings

deepeval 从当前工作目录的 dotenv 文件读取设置，不覆盖已有的进程环境变量。dotenv 优先级（从低到高）为：`.env` → `.env.<APP_ENV>` → `.env.local`。

deepeval 还在 `.deepeval/.deepeval` 使用一个旧版 JSON keystore 存放**非密钥**。该 keystore 仅作为兜底（dotenv/进程环境变量优先）。密钥永远不会写入 JSON keystore。

<Tip>
用 `ENV_DIR_PATH=/path/to/project` 让 deepeval 指向别的目录，或用 `DEEPEVAL_DISABLE_DOTENV=1` 完全禁用 dotenv 自动加载（在 CI 中避免导入时加载本地 `.env*` 文件很有用）。
</Tip>

## Core Commands

### `generate`

使用 `deepeval generate` 在终端用 Golden Synthesizer 生成合成 golden。该命令需要两个选择器：

- `--method`：golden 的来源：`docs`、`contexts`、`scratch` 或 `goldens`
- `--variation`：生成什么：`single-turn` 或 `multi-turn`

从文档生成单轮 golden：

```bash
deepeval generate \
  --method docs \
  --variation single-turn \
  --documents example.txt \
  --documents another.pdf \
  --output-dir ./synthetic_data
```

从零生成多轮 golden：

```bash
deepeval generate \
  --method scratch \
  --variation multi-turn \
  --num-goldens 25 \
  --scenario-context "Users asking support questions" \
  --conversational-task "Help users solve product issues" \
  --participant-roles "User and assistant"
```

通用选项：

| 选项                                       | 说明                                                                  |
| -------------------------------------------- | ---------------------------------------------------------------------------- |
| `--method docs\|contexts\|scratch\|goldens`  | 选择生成方法。                                                |
| `--variation single-turn\|multi-turn`        | 选择生成 `Golden` 还是 `ConversationalGolden`。             |
| `--output-dir`                               | 生成 golden 的保存目录。默认为 `./synthetic_data`。 |
| `--file-type json\|csv\|jsonl`               | 输出文件类型。默认为 `json`。                                        |
| `--file-name`                                | 可选的输出文件名（不含扩展名）。                                  |
| `--model`                                    | 用于生成的模型。                                                 |
| `--async-mode / --sync-mode`                 | 启用或禁用并发生成。                                     |
| `--max-concurrent`                           | 并发生成任务的最大数量。                               |
| `--include-expected / --no-include-expected` | 生成或跳过期望输出/结果。                                  |
| `--cost-tracking`                            | 模型支持时打印生成成本。                           |

方法专属选项：

| 方法     | 必需选项                     | 常用可选选项                                                                                                                                                                                               |
| ---------- | ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `docs`     | `--documents`                        | `--max-goldens-per-context`、`--max-contexts-per-document`、`--min-contexts-per-document`、`--chunk-size`、`--chunk-overlap`、`--context-quality-threshold`、`--context-similarity-threshold`、`--max-retries`        |
| `contexts` | `--contexts-file`                    | `--max-goldens-per-context`                                                                                                                                                                                           |
| `scratch`  | `--num-goldens` 加样式选项 | 单轮：`--scenario`、`--task`、`--input-format`、`--expected-output-format`。多轮：`--scenario-context`、`--conversational-task`、`--participant-roles`、`--scenario-format`、`--expected-outcome-format` |
| `goldens`  | `--goldens-file`                     | `--max-goldens-per-golden`                                                                                                                                                                                            |

更深入的讲解见 [Golden Synthesizer](/docs/golden-synthesizer#generate-goldens-from-the-cli) 文档。

### `diagnose`

使用 `deepeval diagnose` 打印你的环境实际解析出的配置——以及每个值来自哪里。当评估用错了模型、凭证或数据区域，或不确定哪个 `.env` 文件生效时，就用它。

<Tabs>

<Tab title="Python">

```bash
deepeval diagnose
```

</Tab>

<Tab title="TypeScript">

```bash
npx deepeval diagnose
```

</Tab>

</Tabs>

报告会显示：

- **版本**：deepeval 及其运行时的版本。
- **评估模型**：当指标（或合成器、模拟器等）在构造时未显式指定模型时 deepeval 将使用的模型，以及它胜出的原因。旁边列出默认嵌入模型，其下是选定的文本转语音和语音转文本模型，并说明各自的用途。
- **配置来源**：每个变量被独立解析时依据的优先级顺序（进程环境 → `.env.local` → `.env.<APP_ENV>` → `.env` → JSON keystore → 内置默认值）、加载了哪些 dotenv 文件，以及 keystore 的位置。
- **已配置的设置**：每个显式设置的 deepeval 设置，密钥打码（只显示最后 6 个字符），并标出每个设置的**生效来源**——报告使用的解析器与运行时相同，所以你看到的就是评估得到的。
- **Confident AI**：登录状态、打码的 API key、数据区域和 API 端点。同时显示 OTEL 端点，若任一端点看起来与你的 API key 不属于同一区域会给出警告。

选项：

| 选项   | 说明                                                             |
| -------- | ----------------------------------------------------------------------- |
| `--json` | 以 JSON 输出完整报告（机器可读，密钥保持打码）。 |

<Tip>
在 CI 或缺陷报告里加上 `--json` 很方便——所有密钥都已打码，可以安全分享。
</Tip>

## Confident AI Commands

使用这些命令把 `deepeval` 连接到 **Confident AI**（`deepeval` 云），这样你的本地评估就能上传到云端，组织并在云端查看为丰富的测试运行报告。如果你还没有账号，请[在这里注册](https://app.confident-ai.com?utm_source=deepeval&utm_medium=docs&utm_content=cli_confident_commands_signup&ref_page=/docs/command-line-interface)。

### `login` & `logout`

- `deepeval login [--api-key ...] [--save=dotenv[:path]]`
  : 登录 Confident AI。交互式流程会打开浏览器完成认证，然后回到终端创建组织和首个项目，或选择已有项目。DeepEval 会创建专属的项目 API key 并保存为 `CONFIDENT_API_KEY`。CI、无头自动化或手动兜底场景请使用 `--api-key`。
- `deepeval logout [--save=dotenv[:path]]`：从本地持久化中移除你的 Confident AI 凭证——包括 JSON keystore 以及 deepeval 自动加载的每个 dotenv 文件（`.env`、`.env.<APP_ENV>`、`.env.local`）。如果 `CONFIDENT_API_KEY` 是你的 shell 自己导出的，deepeval 无法取消它，并会提示你运行 `unset CONFIDENT_API_KEY`。

### `view`

`deepeval view` 在浏览器中打开 Confident
AI 上的最新测试运行。如有需要，它会先上传缓存的运行工件。它不接受
任何参数。

| 选项          | 说明                                                          |
| --------------- | -------------------------------------------------------------------- |
| `REGION`        | 位置参数。<Tabs><Tab title="Python">`US` 或 `EU` 之一。</Tab><Tab title="TypeScript">`US`、`EU` 或 `AU` 之一。</Tab></Tabs> |

## Persistence & Secrets

所有 `set-*` / `unset-*` 命令遵循相同的规则：

- 非密钥（模型名称、端点、部署等）可以镜像写入 `.deepeval/.deepeval`。
- 密钥（API key）永远不会写入 `.deepeval/.deepeval`。
- 传入 `--save=dotenv[:path]` 把设置（包括密钥）写入 dotenv 文件（默认：`.env.local`）。
- 省略 `--save` 时，deepeval 会使用 `DEEPEVAL_DEFAULT_SAVE`（如果设置）；否则不会写 dotenv 文件（某些命令如 `login` 仍默认写 `.env.local`）。
- 取消某个提供商只会移除该提供商的键。其他提供商遗留的凭证（例如 `OPENAI_API_KEY`）本身不会选中任何东西——由 `USE_*` 开关决定哪个提供商生效。

<Tip>
你可以通过 `DEEPEVAL_DEFAULT_SAVE=dotenv:.env.local` 设置默认保存目标，这样就不必每次传 `--save`。
</Tip>

<Info>
token 成本以**每 token 美元**表示。如果你使用的是以 **$/MTok**（百万 token）计的公开定价，请除以 **1,000,000**。
例如，**&#36;3 / MTok = 0.000003**。
</Info>

## Model Provider Configs

所有提供商命令都是成对出现的：

<Tabs>

<Tab title="Python">

- `deepeval set-<provider> [provider-specific flags] [--save=dotenv[:path]] [--quiet]`
- `deepeval unset-<provider> [--save=dotenv[:path]] [--quiet]`

</Tab>

<Tab title="TypeScript">

- `npx deepeval set-<provider> [provider-specific flags] [--save=dotenv[:path]] [--quiet]`
- `npx deepeval unset-<provider> [--save=dotenv[:path]] [--quiet]`

</Tab>

</Tabs>

这会在**同一家族内**切换活跃提供商：

- 设置该提供商的 `USE_*` 开关，例如 `USE_ANTHROPIC_MODEL`，并且
- 关闭同一家族中其他 `USE_*` 开关，因此每个家族同一时间只启用一个提供商。

四个家族分别是 LLM 评审、嵌入、文本转语音和语音转文本。它们相互独立，因此 `deepeval set-openai` 不会影响已配置的嵌入或语音提供商，且任一家族在没有任何开关设置时回退到 OpenAI。

（TypeScript：这里的每个 `USE_*` 开关都属于 LLM 家族，设置一个提供商会关闭其他所有提供商。全都不设置时，`deepeval` 回退到 OpenAI。）

**取消**一个提供商时，只会禁用该提供商的 `USE_*` 开关，其他一概不动。如果你手动设置环境变量（或编辑 dotenv 文件），可能出现同一家族内多个 `USE_*` 开关同时启用的情况。

<Warning>
由于 `deepeval` 以特定方式管理你的模型相关环境变量，**使用 CLI 是在 `deepeval` 中配置评估模型 100% 推荐的方式。**它会替你处理所有必需的环境变量，确保不同提供商之间配置一致且正确。

如果你想了解 `deepeval` 底层管理哪些环境变量，参见 [模型设置](/docs/environment-variables#model-settings)文档。
</Warning>

## Common Issues

- **没有输出？** 对 `set-*` / `unset-*` / `set-debug` 来说，干净退出且无输出通常意味着你传了 `--quiet` / `-q` 参数。
- **取消设置后提供商仍然生效？** 取消设置只关闭该提供商的 `USE_*` 开关；如果同一家族中另一个提供商的开关仍开启，它就成为该家族的活跃提供商。家族内没有任何开关启用时，deepeval 对该家族回退到 OpenAI。要强制某个提供商，请运行对应的 `set-<provider>` 命令。
- **dotenv 修改未生效？** deepeval 默认从当前工作目录加载 dotenv 文件，或使用 `ENV_DIR_PATH`（如果设置）。请确保你的进程在该上下文中运行。

如果仍然卡住，专门的 [Troubleshooting](/docs/troubleshooting) 页面涵盖更深入的调试（TLS 错误、日志、超时、dotenv 加载和配置缓存）。
