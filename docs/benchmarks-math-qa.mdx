**MathQA** 基准包含 37,000 道多选数学题，评估 LLM 的数学推理能力。更多信息见 [MathQA 数据集](https://arxiv.org/pdf/1905.13319.pdf)。

<Info>
`MathQA` 由 AQuA 数据集构建，其中包含超过 10 万道 **GRE 和 GMAT 水平**的数学应用题。
</Info>

## 参数

使用 `MathQA` 基准时有**两个**可选参数：

- [可选] `tasks`：任务列表（`MathQATask` 枚举），指定模型评估的主题领域。默认为所有任务。`MathQATask` 枚举列表见[这里](#mathqa-tasks)。
- [可选] `n_shots`：用于少样本学习的示例数量。**默认设为 5**，**不能超过 5**。

## 用法

下面的代码评估自定义 `mistral_7b` 模型（[点击这里](/guides/guides-using-custom-llms)了解如何使用任意自定义 LLM）使用 3-shot 提示评估其在 `MathQA` 几何与概率上的表现。

```python
from deepeval.benchmarks import MathQA
from deepeval.benchmarks.tasks import MathQATask

# Define benchmark with specific tasks and shots
benchmark = MathQA(
    tasks=[MathQATask.PROBABILITY, MathQATask.GEOMETRY],
    n_shots=3
)

# Replace 'mistral_7b' with your own custom model
benchmark.evaluate(model=mistral_7b)
print(benchmark.overall_score)
```

该基准的 `overall_score` 范围为 0 到 1，1 表示完美表现，0 表示全部答错。模型分数基于**精确匹配**，通过确定模型给出精确正确选项的多选题占总题数的比例来计算。

<Tip>
因此，使用更多少样本提示（`n_shots`）可以大幅提升模型以精确正确格式生成答案的稳健性，并提高总分。
</Tip>

## MathQA Tasks

`MathQATask` 枚举分类了 MathQA 基准涵盖的多样化类别。

```python
from deepeval.benchmarks.tasks import MathQATask

math_qa_tasks = [MathQATask.PROBABILITY]
```

以下是所有可用任务的完整列表：

- `PROBABILITY`
- `GEOMETRY`
- `PHYSICS`
- `GAIN`
- `GENERAL`
- `OTHER`

## 常见问题

<AccordionGroup>
<Accordion title="What does the MathQA benchmark measure?">
MathQA 通过 3.7 万道英文多选数学应用题评估 LLM 的多步数学推理能力，覆盖概率和几何等多个领域。各基准的评分方式见[基准介绍](/docs/benchmarks-introduction)。
</Accordion>
<Accordion title="How is MathQA scored?">
评分基于**精确匹配**：`overall_score` 是模型给出精确正确多选答案（如 'A' 或 'C'）的问题占总题数的比例。范围为 0 到 1，1 表示完美表现。
</Accordion>
<Accordion title="What is the default n_shots for MathQA?">
默认为 `5` 且不能超过。用 `n_shots` 参数调低以进行少样本提示。
</Accordion>
<Accordion title="Which tasks can I evaluate with MathQA?">
向 `tasks` 参数传入一组 `MathQATask` 枚举以针对特定主题领域。可用任务为 `PROBABILITY` 、`GEOMETRY` 、`PHYSICS` 、`GAIN` 、`GENERAL` 和 `OTHER` 。默认评估所有任务。
</Accordion>
<Accordion title="Can using more few-shot prompts improve the MathQA score?">
可以。通过 `n_shots` 使用更多少样本提示可以大幅提升模型以精确正确格式生成答案的稳健性，并提高 `overall_score` 。
</Accordion>
<Accordion title="How do I run MathQA on a custom LLM?">
定义基准，然后用你的模型调用 `evaluate()` 并读取 `overall_score` 。使用任意自定义 LLM 见[评估你的 LLM](/docs/benchmarks-introduction#benchmarking-your-llm)。
</Accordion>
</AccordionGroup>
