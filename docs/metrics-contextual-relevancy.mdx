**标签**：LLM-as-a-judge · 单轮 · 无参考 · RAG · 多模态

上下文相关性（contextual relevancy）指标使用 LLM-as-a-judge，通过评估 `retrieval_context` 中呈现的信息对给定 `input` 的整体相关性，来衡量你的 RAG 流水线检索器的质量。`deepeval` 的上下文相关性指标是会自我解释的 LLM-Eval，会输出指标分数的理由。

<Info>
不确定 `ContextualRelevancyMetric` 是否适合你的用例？运行以下命令一探究竟：

```bash
deepeval recommend metrics
```

</Info>

## Required Arguments

要使用 `ContextualRelevancyMetric`，你需要在创建 [`LLMTestCase`](/docs/evaluation-test-cases#llm-test-case) 时提供以下参数：

- `input`
- `actual_output`
- `retrieval_context`

<Note>
与 `ContextualPrecisionMetric` 类似，`ContextualRelevancyMetric` 使用你的 RAG 流水线的 `retrieval_context` 进行评估。
</Note>

请阅读下文 [How Is It Calculated](#how-is-it-calculated) 一节，了解测试用例参数如何用于指标计算。

## Usage

`ContextualRelevancyMetric()` 可用于文本与多模态测试用例的[端到端](/docs/evaluation-end-to-end-llm-evals)评估：

```python
from deepeval.metrics import ContextualRelevancyMetric
from deepeval.test_case import LLMTestCase
from deepeval import evaluate

# Replace this with the actual output from your LLM application
actual_output = "We offer a 30-day full refund at no extra cost."

# Replace this with the actual retrieved context from your RAG pipeline
retrieval_context = ["All customers are eligible for a 30 day full refund at no extra cost."]

metric = ContextualRelevancyMetric(
    threshold=0.7,
    model="gpt-4.1",
    include_reason=True
)
test_case = LLMTestCase(
    input="What if these shoes don't fit?",
    actual_output=actual_output,
    retrieval_context=retrieval_context
)

# To run metric as a standalone
# metric.measure(test_case)
# print(metric.score, metric.reason)

evaluate(test_cases=[test_case], metrics=[metric])
```

- [Optional] `threshold`: a number representing the minimum passing threshold. Can also be set to `None`（TypeScript 中为 `null`） to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [可选] `model`：字符串，指定使用 OpenAI 的哪款 GPT 模型，**或**类型为 `DeepEvalBaseLLM` 的[任意自定义 LLM 模型](/docs/metrics-introduction#using-a-custom-llm)。默认为 `gpt-5.4`。
- [可选] `include_reason`：布尔值，设为 `True`（TypeScript 中为 `true`）时，会为评估分数附带理由。默认为 `True`（TypeScript 中为 `true`）。
- [可选] `strict_mode`：布尔值，设为 `True`（TypeScript 中为 `true`）时，把指标分数强制为二元：完美为 1，否则为 0。它还会覆盖当前阈值并将其设为 1。默认为 `False`（TypeScript 中为 `false`）。
- [可选] `async_mode`：布尔值，设为 `True` 时，启用[`measure()` 方法内的并发执行](/docs/metrics-introduction#measuring-metrics-in-async)。默认为 `True`。
  
- [可选] `verbose_mode`：布尔值，设为 `True`（TypeScript 中为 `true`）时，把计算该指标所用的中间步骤打印到控制台，具体见 [How Is It Calculated](#how-is-it-calculated) 一节。默认为 `False`（TypeScript 中为 `false`）。
- [可选] `evaluation_template`：类型为 `ContextualRelevancyTemplate` 的类，允许你覆盖用于计算 `ContextualRelevancyMetric` 分数的默认提示词模板。默认提示词的样子可以在[这里](https://github.com/confident-ai/deepeval/blob/main/deepeval/metrics/contextual_relevancy/template.py)查看，并请阅读下方的 [How Is It Calculated](#how-is-it-calculated) 一节了解如何按需裁剪。默认为 `deepeval` 的 `ContextualRelevancyTemplate`。
- [可选] `flaky`：布尔值，设为 `True`（TypeScript 中为 `true`）时，[把指标标记为 flaky](/docs/metrics-introduction#flaky-metrics)。默认为 `False`（TypeScript 中为 `false`）。

### 在组件内

你还可以在嵌套组件内运行 `ContextualRelevancyMetric`，进行[组件级](/docs/evaluation-component-level-llm-evals)评估。

<Tabs>

<Tab title="Python">

```python
from deepeval.dataset import EvaluationDataset, Golden
from deepeval.tracing import observe, update_current_span
...

@observe(metrics=[metric])
def inner_component():
    # Set test case at runtime
    test_case = LLMTestCase(input="...", actual_output="...")
    update_current_span(test_case=test_case)
    return

@observe
def llm_app(input: str):
    # Component can be anything from an LLM call, retrieval, agent, tool use, etc.
    inner_component()
    return

dataset = EvaluationDataset(goldens=[Golden(input="Hi!")])
for golden in dataset.evals_iterator():
    llm_app(golden.input)
```

</Tab>

<Tab title="TypeScript">

```typescript
import { EvaluationDataset, Golden } from "deepeval/dataset";
import { observe, updateCurrentSpan } from "deepeval/tracing";
// ...

const innerComponent = observe({
  metrics: [metric],
  fn: async () => {
    // Set test case at runtime
    const testCase = new LLMTestCase({ input: "...", actualOutput: "..." });
    updateCurrentSpan({ testCase });
  },
});

const llmApp = observe({
  fn: async (input: string) => {
    // Component can be anything from an LLM call, retrieval, agent, tool use, etc.
    await innerComponent();
  },
});

const dataset = new EvaluationDataset({ goldens: [new Golden({ input: "Hi!" })] });
for await (const golden of dataset.evalsIterator()) {
  await llmApp((golden as Golden).input);
}
```

## How Is It Calculated?

`ContextualRelevancyMetric` 的分数按以下公式计算：

$$
\text{Contextual Relevancy} = \frac{\text{Number of Relevant Statements}}{\text{Total Number of Statements}}
$$

虽然计算方式与 `AnswerRelevancyMetric` 相似，但 `ContextualRelevancyMetric` 首先用 LLM 抽取的是 `retrieval_context` 中做出的所有陈述，再用同一个 LLM 判断每条陈述是否与 `input` 相关。

## Customize Your Template

由于 `deepeval` 的 `ContextualRelevancyMetric` 由 LLM-as-a-judge 评估，你可以通过[覆盖 `deepeval` 的默认提示词模板](/docs/metrics-introduction#customizing-metric-prompts)来提升指标准确性。这在以下情况特别有帮助：

- 你在使用[自定义评估 LLM](/guides/guides-using-custom-llms)，尤其是指令遵循能力较弱的更小模型。
- 你想自定义默认 `ContextualRelevancyTemplate` 中使用的示例，使其更符合你的预期。

<Tip>
默认 `ContextualRelevancyTemplate` 的样子可以在 [GitHub 这里](https://github.com/confident-ai/deepeval/blob/main/deepeval/metrics/contextual_relevancy/template.py)查看，并请阅读上方的 [How Is It Calculated](#how-is-it-calculated) 一节，了解如何按需裁剪。
</Tip>

下面是一个快速示例，展示如何覆盖 `ContextualRelevancyMetric` 算法中相关性分类的步骤：

<Tabs>

<Tab title="Python">

```python
from deepeval.metrics.contextual_relevancy import ContextualRelevancyTemplate
from deepeval.metrics import ContextualRelevancyMetric

# Define custom template
class CustomTemplate(ContextualRelevancyTemplate):
    @staticmethod
    def generate_verdicts(input: str, context: str):
        return f"""Based on the input and context, please generate a JSON object to indicate whether each statement found in the context is relevant to the provided input.

Example JSON:
{{
    "verdicts": [
        {{
            "verdict": "yes",
            "statement": "...",
        }}
    ]
}}
**

Input:
{input}

Context:
{context}

JSON:
"""

# Inject custom template to metric
metric = ContextualRelevancyMetric(evaluation_template=CustomTemplate)
metric.measure(...)
```

</Tab>

<Tab title="TypeScript">

```typescript
import { ContextualRelevancyMetric } from "deepeval/metrics";

// Inject custom template to metric
const metric = new ContextualRelevancyMetric({
  evaluationTemplate: {
    generateVerdicts: ({ input, context }) =>
      `Based on the input and context, please generate a JSON object to indicate whether each statement found in the context is relevant to the provided input.

Example JSON:
{
    "verdicts": [
        {
            "verdict": "yes",
            "statement": "...",
        }
    ]
}
**

Input:
${input}

Context:
${context}

JSON:
`,
  },
});
await metric.measure(testCase);
```

每个覆盖函数都会收到模板变量作为第一个参数、默认渲染器作为第二个参数，因此你可以在替换之外扩展提示词：

```typescript
const metric = new ContextualRelevancyMetric({
  evaluationTemplate: {
    generateVerdicts: (vars, renderDefault) =>
      `${renderDefault(vars)}\n\nTreat a heading as its own statement.`,
  },
});
```

## FAQs

<AccordionGroup>
<Accordion title="Why is my contextual relevancy low even though the right answer was retrieved?">
它度量的是信噪比，而不只是「有没有」。它为 `retrieval_context` 中与 `input` 相关的陈述占比打分，因此正确的段落被埋在不相关文本里依然得低分。解决办法通常是减少上下文噪声。
</Accordion>
<Accordion title="What does a low contextual relevancy score tell me to change?">
`retrieval_context` 里混入了太多无关内容。调低 top-K 以返回更少的边缘文本块、缩小文本块大小以获得更聚焦的节点——这是提高相关占比最直接的方式。
</Accordion>
<Accordion title="How is Contextual Relevancy different from Answer Relevancy?">
流水线的两端。上下文相关性通过 `retrieval_context` 评判你的检索器，而[答案相关性](/docs/metrics-answer-relevancy)通过 `actual_output` 评判你的生成器。上下文干净但答案跑题指向生成器；上下文嘈杂指向检索器。
</Accordion>
<Accordion title="Do I need a ground-truth answer to run it?">
不会。它是无参考的——纯粹基于 `input` 评判 `retrieval_context` ，不需要 `expected_output` ，这与基于参考的 [Contextual Recall](/docs/metrics-contextual-recall) 不同。因此可以在没有标注数据的线上流量上使用。
</Accordion>
</AccordionGroup>
