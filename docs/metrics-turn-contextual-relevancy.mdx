轮次上下文相关性（turn contextual relevancy）指标是一个对话式指标，评估**在整个对话过程中**检索上下文是否包含解决用户输入的相关信息。

## Required Arguments

要使用 `TurnContextualRelevancyMetric`，你需要在创建 [`ConversationalTestCase`](/docs/evaluation-multiturn-test-cases) 时提供以下参数：

- `turns`

你必须提供每个轮次的 `role`、`content` 与 `retrieval_context`，评估才能进行。更多信息见下方的 [How Is It Calculated](#how-is-it-calculated) 一节。

## Usage

`TurnContextualRelevancyMetric()` 可用于[端到端](/docs/evaluation-end-to-end-llm-evals)多轮评估：

<Tabs>

<Tab title="Python">

```python
from deepeval.test_case import Turn, ConversationalTestCase
from deepeval.metrics import TurnContextualRelevancyMetric
from deepeval import evaluate

content = "We offer a 30-day full refund at no extra cost."
retrieval_context = [
    "All customers are eligible for a 30 day full refund at no extra cost."
]

convo_test_case = ConversationalTestCase(
    turns=[
        Turn(role="user", content="What if these shoes don't fit?"),
        Turn(role="assistant", content=content, retrieval_context=retrieval_context)
    ],
    expected_outcome="The chatbot must explain the store policies like refunds, discounts, ..etc.",
)

metric = TurnContextualRelevancyMetric(threshold=0.5)

# To run metric as a standalone
# metric.measure(convo_test_case)
# print(metric.score, metric.reason)

evaluate(test_cases=[convo_test_case], metrics=[metric])
```

</Tab>

// To run metric as a standalone
// await metric.measure(convoTestCase);

- [Optional] `threshold`: a number representing the minimum passing threshold. Can also be set to `None`（TypeScript 中为 `null`） to run the metric in [score-only mode](/docs/metrics-introduction#metric-thresholds). Defaulted to `0.5`.
- [可选] `model`：字符串，指定使用 OpenAI 的哪款 GPT 模型，**或**类型为 `DeepEvalBaseLLM` 的[任意自定义 LLM 模型](/docs/metrics-introduction#using-a-custom-llm)。默认为 `gpt-5.4`。
- [可选] `include_reason`：布尔值，设为 `True`（TypeScript 中为 `true`）时，会为评估分数附带理由。默认为 `True`（TypeScript 中为 `true`）。
- [可选] `strict_mode`：布尔值，设为 `True`（TypeScript 中为 `true`）时，把指标分数强制为二元：完美为 1，否则为 0。它还会覆盖当前阈值并将其设为 1。默认为 `False`（TypeScript 中为 `false`）。
- [可选] `async_mode`：布尔值，设为 `True` 时，启用[`measure()` 方法内的并发执行](/docs/metrics-introduction#measuring-metrics-in-async)。默认为 `True`。
  
- [可选] `verbose_mode`：布尔值，设为 `True`（TypeScript 中为 `true`）时，把计算该指标所用的中间步骤打印到控制台，具体见 [How Is It Calculated](#how-is-it-calculated) 一节。默认为 `False`（TypeScript 中为 `false`）。
- [可选] `window_size`：整数，定义评估期间使用的轮次滑动窗口大小。默认为 `10`。
- [可选] `flaky`：布尔值，设为 `True`（TypeScript 中为 `true`）时，[把指标标记为 flaky](/docs/metrics-introduction#flaky-metrics)。默认为 `False`（TypeScript 中为 `false`）。

## How Is It Calculated?

`TurnContextualRelevancyMetric` 的分数按以下公式计算：

$$
\text{Turn Contextual Relevancy} = \frac{\sum \text{Turn Contextual Relevancy Scores}}{\text{Total Number of Assistant Turns}}
$$

`TurnContextualRelevancyMetric` 首先构建轮次滑动窗口。对每个窗口，它会：

1. 从每个检索上下文节点**抽取陈述**
2. **评估每条陈述**，判断它是否与用户的输入相关
3. **计算该交互的分数**，即相关陈述占全部陈述的比例

$$
\text{Contextual Relevancy} = \frac{\text{Number of Relevant Statements}}{\text{Total Number of Statements}}
$$

最终分数是整段对话中所有相关性分数的平均值。它衡量你的检索系统是否在为每个轮次返回上下文相关的信息。

## FAQs

<AccordionGroup>
<Accordion title="When should I use TurnContextualRelevancyMetric instead of the single-turn version?">
当 `ConversationalTestCase` 中逐轮进行检索、而你想在上下文中衡量每轮 `retrieval_context` 的信噪比时使用。单轮的 [ContextualRelevancyMetric](/docs/metrics-contextual-relevancy) 一次只检查一次检索对一个查询。
</Accordion>
<Accordion title="Is this a retriever metric or a generator metric?">
它是**检索器**指标。它只衡量每轮 `retrieval_context` 中有多少内容与用户输入相关，从不读答案——低分数指向嘈杂的检索器，而不是糟糕的生成器。
</Accordion>
<Accordion title="How is relevancy different from Turn Contextual Recall and Precision?">
相关性衡量信噪比，[召回率](/docs/metrics-turn-contextual-recall)衡量完整性，[精确率](/docs/metrics-turn-contextual-precision)衡量排序。
</Accordion>
<Accordion title="My chatbot answered correctly but this score is low — is that a bug?">
不是 bug。它评的是检索到的上下文而不是回复，因此无关节点会拉低分数，即使回答是好的。收紧检索（更少、更聚焦的文本块）即可提高分数。
</Accordion>
</AccordionGroup>
